# Step 1-7. 주석·들여쓰기·자기소개 실습

이번 Step에서는 Part 1에서 배운 프로그램 구조와 출력을 읽기 쉬운 자기소개 프로그램으로 묶는다. 기준은 C17 호스트 환경이며, 명령 관찰은 GCC가 있는 GNU/Linux 환경을 기준으로 한다.

## 1. 학습 목표

- `//`와 `/* ... */` 주석의 범위와 제한을 구별한다.
- 들여쓰기가 C 문법이 아니라 코드 읽기 규칙임을 설명한다.
- 중괄호, 세미콜론, 토큰처럼 실제 문법인 요소를 들여쓰기와 혼동하지 않는다.
- `printf`와 이스케이프 시퀀스를 이용해 읽기 쉬운 자기소개 프로그램을 작성한다.

## 2. 선수 지식

Step 1-1~1-6의 `int main(void)`, `#include <stdio.h>`, statement·중괄호·세미콜론, `printf`, `\n`·`\t`·`\"`·`\\`, `return 0;`을 알고 있어야 한다.

아직 변수, 입력, 조건문, 반복문은 사용하지 않는다. 자기소개 내용은 문자열 리터럴에 직접 작성한다.

이식성 비교가 목적이면 C의 기본 소스 문자 집합에 속하는 ASCII 문구를 사용한다. 한글을 소스와 출력에 직접 쓰는 실습은 해당 구현의 입력·실행 문자 집합, 인코딩, 터미널 표시 지원에 의존한다.

**[GCC 구현]** 아래 실습은 `gcc -std=c17 -Wall -Wextra -pedantic profile.c -o profile`처럼 빌드할 수 있다.

**[GNU/Linux 구현]** 빌드에 성공한 경우 `./profile`로 실행한다.

## 3. 핵심 개념

**주석(comment)**은 사람에게 코드의 의도나 이유를 설명하기 위한 소스 텍스트다. 주석 자체는 실행되지 않고 `printf` 출력에도 나타나지 않는다.

**[C 표준]** N1570 5.1.1.2의 번역 단계 3에서 소스는 전처리 토큰과 공백 시퀀스로 나뉘며, **각 주석은 공백 하나로 대체된다.** 따라서 주석은 프로그램의 출력 문장이 아니고, 인접한 토큰이 의도하지 않게 붙는 일을 막을 수 있다.

| 형태 | 범위 | 용도 | 주의점 |
|---|---|---|---|
| `//` | 번역 단계 2의 줄 이어붙이기 후, 다음 new-line character 전까지 | 짧은 논리적 한 줄 설명 | C99부터 제공된다. |
| `/* ... */` | `/*`부터 첫 `*/`까지 | 여러 줄 설명 | 중첩되지 않는다. |

**[C 표준]** `//` 주석은 C99부터 언어에 포함되었다. `/* ... */` 블록 주석은 중첩되지 않는다. 즉, 다음 코드는 바깥 주석 안에 안쪽 주석이 생기는 것이 아니다.

```c
/* 바깥 /* 안 */ 뒤 */
```

첫 `*/`에서 주석이 끝나므로 뒤의 텍스트는 C 코드로 해석될 수 있다.

문자열 리터럴 안의 `//`, `/*`, `*/`는 주석 구분자가 아니라 문자다.

```c
printf("// 이것은 출력 문자열입니다.\n");
printf("/* 이것도 출력 문자열입니다. */\n");
```

**들여쓰기(indentation)**는 줄 앞의 공백 또는 탭으로 블록 구조를 사람이 읽기 쉽게 만드는 스타일이다. 들여쓰기 폭은 C 문법이 아니다. 반면 `{`, `}`, `;`, `(`, `)`와 식별자·키워드 등의 토큰은 문법이다.

```c
int main(void)
{
    return 0;
}
```

위 코드에서 네 칸 들여쓰기는 스타일이고, 함수 본문을 실제로 정하는 것은 중괄호다.

## 4. 문법

```c
// 한 줄 주석

/* 여러 줄
   블록 주석 */

int main(void)
{
    printf("Hello.\n");
    return 0;
}
```

- `// 설명`: 역슬래시-new-line 이어붙이기를 먼저 처리한 뒤, 다음 new-line character 전까지의 주석이다.
- `/* 설명 */`: 시작과 끝이 반드시 짝이어야 한다.
- `printf(...);`: 호출 식 뒤의 세미콜론까지 하나의 문장이다.
- `{`와 `}`: 함수 본문의 시작과 끝을 정하는 문법 기호다.
- 들여쓰기: 본문 구조를 보이게 하는 스타일이다.

`printf`의 선언은 `<stdio.h>`가 제공한다. 문자열 안에서 `\n`은 줄 바꿈, `\t`는 수평 탭, `\"`는 큰따옴표, `\\`는 역슬래시를 나타낸다.

## 5. 최소 코드 예제

아래 코드는 주석과 들여쓰기를 보여 주는 최소 조각이다. 필수 실습의 완성 자기소개 답안은 아니다.

```c
#include <stdio.h>

int main(void)
{
    // 이름 한 항목을 출력한다.
    printf("Name: Mina\n");
    return 0;
}
```

**[C 표준]** 초기 `main`에서 `return 0;`은 성공 종료 상태를 나타낸다. 일반적인 터미널에서는 `Name: Mina`가 한 줄로 보인다.

## 6. 코드 해석

| 부분 | 해석 |
|---|---|
| `#include <stdio.h>` | `printf` 선언 등을 제공하는 표준 헤더를 포함한다. |
| `int main(void)` | 호스트 환경 프로그램의 시작 함수 정의다. |
| `{`와 `}` | 함수 본문의 실제 범위를 정한다. |
| `// ...` | 번역 단계 3에서 공백 하나로 대체되어 출력되지 않는다. |
| 네 칸 들여쓰기 | `printf`와 `return`이 함수 본문에 있음을 사람이 읽기 쉽게 보인다. |
| `printf("Name: Mina\n");` | 문자열과 new-line character를 표준 출력에 보낸다. |
| `return 0;` | 성공 종료 상태를 반환한다. |

주석을 지우거나 들여쓰기를 없애도 남은 토큰 순서가 같으면 C 의미는 같다. 그러나 세미콜론이나 중괄호를 지우면 문법이 바뀌므로 번역 진단이 발생할 수 있다.

## 7. 내부 동작

**[C 표준] 번역:** N1570 5.1.1.2의 단계 3에서 주석은 공백 하나로 대체된다. 그 뒤 전처리 지시문이 처리되고 번역 단위가 만들어진다. 이 단계는 컴파일러가 반드시 별도 프로그램을 실행한다는 뜻은 아니다.

**[C 표준] 주석 규칙:** 번역 단계 2에서 역슬래시 바로 뒤의 new-line character를 제거해 물리적 소스 줄을 이어 붙인 뒤, N1570 6.4.9에 따라 `//`는 다음 new-line character 전까지다. `/*`는 가장 가까운 뒤의 `*/`까지다. 블록 주석에는 중첩 깊이가 없다. 문자열 리터럴 안의 `//`, `/*`, `*/`는 문자열 문자이므로 주석이 아니다.

**[GCC 구현] 번역:** GCC는 주석을 처리한 뒤 문법과 타입을 검사하고 대상 코드로 번역한다. `-E -C`처럼 전처리 결과에 주석을 보이게 하는 옵션은 GCC의 관찰 기능이며 C 언어의 실행 의미가 아니다.

**[GNU/Linux 구현] 실행:** 일반적인 터미널에서는 표준 출력에 보낸 `\n`이 새 줄로 보이고 `\t`가 다음 탭 위치로 보일 수 있다. 탭 폭과 한글 표시 폭은 터미널 환경에 따라 다를 수 있다.

## 8. 자주 하는 실수

- `//`가 항상 원본 파일의 물리적 한 줄에서 끝난다고 생각한다. 줄 끝의 역슬래시-new-line은 주석 인식 전에 제거될 수 있다.
- `/* 바깥 /* 안 */ 바깥 */`처럼 블록 주석을 중첩한다.
- 문자열 안의 `//` 또는 `/*`를 주석 시작으로 오해한다.
- 주석이나 들여쓰기가 세미콜론과 중괄호를 대신한다고 생각한다.
- 들여쓰기만 보고 블록 범위를 판단하고 실제 중괄호를 확인하지 않는다.
- 탭과 공백을 섞어 편집기마다 다른 모양이 되게 한다.
- 탭으로 표를 맞추고 모든 터미널에서 같은 열 폭을 기대한다.
- 오래된 코드를 블록 주석으로 계속 숨겨 둔다.

## 9. 필수 실습

### 읽기 쉬운 자기소개 프로그램 작성하기

- **목적:** Part 1의 프로그램 구조와 출력을 한 파일에 직접 결합하고, 주석과 들여쓰기로 의도를 전달한다.
- **해야 할 일:** `profile.c`를 직접 작성한다. `<stdio.h>`, `int main(void)`, 중괄호, `printf`, `return 0;`을 사용한다. 이름, 좋아하는 것 또는 관심 분야, C를 배우는 이유를 각각 한 줄로 출력한다. 실제 내용에 맞게 `\t`, `\"`, `\\` 중 하나 이상을 사용한다. `//` 주석과 `/* ... */` 주석을 각각 하나 이상 쓰고, 함수 본문을 한 가지 들여쓰기 규칙으로 정렬한다.
- **사용할 개념:** 표준 헤더, `main`, statement·중괄호·세미콜론, `printf`, 문자열 리터럴, `\n`·`\t`·`\"`·`\\`, 주석, 들여쓰기, `return 0;`.
- **예상 관찰 결과:** 작성한 자기소개 항목이 줄 단위로 출력되고 주석은 출력되지 않는다. 정상 실행에서는 성공 종료한다. 탭의 폭은 **[GNU/Linux 구현]** 관찰이다.
- **확인 포인트:** 모든 `printf` 뒤에 세미콜론이 있는가? 블록 주석의 시작과 끝이 짝인가? 들여쓰기와 실제 중괄호를 모두 확인했는가? 출력 내용과 종료 상태를 따로 확인했는가?

빌드 명령과 점검표는 [실습 README](../../exercises/01-program-structure/1-7/README.md)에 있다.

## 11. 확인 문제

1. 주석은 어느 번역 단계에서 무엇으로 대체되는가?
2. 줄 끝에 역슬래시-new-line이 없다면 `//` 주석은 어디에서 끝나는가? 줄 이어붙이기가 있으면 무엇이 달라지는가?
3. `/* 바깥 /* 안 */ 뒤 */`가 중첩 주석이 아닌 이유는 무엇인가?
4. `printf("/* text */\n");`의 `/*`는 왜 주석 시작이 아닌가?
5. 들여쓰기를 모두 지워도 중괄호와 토큰이 같으면 블록은 바뀌는가?
6. 들여쓰기를 유지한 채 `}`를 삭제하면 왜 문제가 되는가?

<details>
<summary>정답과 해설</summary>

1. N1570 5.1.1.2의 번역 단계 3에서 각 주석은 공백 하나로 대체된다.
2. 다음 new-line character 전에서 끝난다. 다만 번역 단계 2에서 역슬래시-new-line이 먼저 제거되므로, 이어진 다음 물리적 줄의 일부도 같은 `//` 주석이 될 수 있다.
3. 블록 주석은 중첩되지 않으며 첫 `*/`가 주석을 끝내기 때문이다.
4. 큰따옴표 안은 문자열 리터럴이므로 슬래시와 별표는 출력 문자다.
5. 바뀌지 않는다. 들여쓰기는 스타일이고 실제 블록 범위는 중괄호와 문법이 정한다.
6. 닫는 중괄호는 함수 본문을 끝내는 문법 토큰이다. 공백은 이를 대신할 수 없다.

## 12. 핵심 정리

주석은 실행할 명령이 아니라 사람이 읽는 설명이며, **[C 표준]** 번역 단계 3에서 공백 하나로 대체된다. `//`는 C99부터 제공되며 줄 이어붙이기 후의 논리적 한 줄 범위다. `/* ... */`는 중첩되지 않는다. 문자열 리터럴 안의 주석처럼 보이는 기호는 문자다.

들여쓰기는 읽기 좋은 구조를 만드는 스타일이다. 중괄호와 세미콜론은 실제 C 문법이다. 이 구별을 지키며 자기소개 프로그램을 직접 작성한다.
