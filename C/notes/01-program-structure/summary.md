# Step 1-1. 첫 프로그램과 `int main(void)`

기준은 C17의 호스트 환경(hosted environment)이다. 이 Step에서는 첫 C 프로그램의 시작 함수와 종료를 구분한다.


## 핵심 개념

함수는 이름이 붙은 실행 단위다. **[C 표준]** 호스트 환경에서 프로그램이 시작하면 C 추상 환경은 지정된 `main` 함수를 호출한다. OS가 C 소스의 `main`을 직접 호출한다고 표현하면 시작 코드와 런타임의 역할을 섞게 된다. 실제 실행 파일의 첫 기계 명령도 보통 `main`의 첫 문장이 아니다.

`int main(void)`에서 `int`는 반환형, `main`은 시작 함수 이름, `(void)`는 매개변수가 없음을 뜻한다. `{`와 `}` 사이가 함수 본문이다. 초기 `main` 호출에서 `return 0;`을 실행하면 정상 종료한다. 화면 출력과 종료 상태는 별개이며, **[GNU/Linux 구현]** 셸에서는 정상 종료가 보통 상태 0으로 보인다.






# Step 1-2. `#include`와 표준 헤더


## 핵심 개념

`#include <stdio.h>`는 C 문장이 아니라 전처리 지시문이다. 전처리기는 지정한 헤더 내용을 이후 번역의 입력에 포함시킨다. 따라서 `#include`는 실행 중 파일을 읽거나 라이브러리를 가져오는 runtime import가 아니다.

`stdio.h`는 `puts` 같은 표준 입출력 함수의 **선언**을 제공한다. 선언은 함수의 이름, 매개변수, 반환형이라는 인터페이스 설명이며 함수의 기계 코드 구현이 아니다. 구현은 라이브러리 또는 다른 번역 단위에 있고, **[GCC 구현]** 일반적인 호스트 환경용 빌드에서는 링크 단계가 외부 참조를 C 라이브러리 구현과 연결한다.

`<stdio.h>`는 구현이 정한 시스템 헤더 검색 위치를 사용한다. `"local.h"`는 현재 파일 주변의 구현 정의 검색 경로를 먼저 고려할 수 있다. 표준 헤더에는 의도가 명확한 `<stdio.h>`를 쓴다.

## 문법

```c
#include <표준-헤더>
#include "프로젝트-헤더"
```

| 표현 | 처리 시점 | 주된 용도 |
|---|---|---|
| `#include <stdio.h>` | 전처리 | 구현이 제공하는 표준 헤더 |
| `#include "local.h"` | 전처리 | 프로젝트 헤더 |
| `puts("text");` | 실행 중 | 선언된 함수 호출 |

전처리 지시문 끝에는 C 문장처럼 세미콜론을 붙이지 않는다. 헤더 이름은 문자열 리터럴이 아니다.



# Step 1-3. statement, 중괄호, 세미콜론

기준은 C17 호스트 환경이다. 이 Step에서는 실행의 기본 문법 단위인 문장(statement)과 중괄호로 만든 블록을 읽는다.


## 핵심 개념

**[C 표준]** N1570 6.8에서 statement는 실행의 문법 단위다. expression statement, compound statement, selection statement, iteration statement, jump statement, labeled statement가 있다. 그러므로 모든 문장이 “식 + 세미콜론”인 것은 아니다.

`{`와 `}` 사이의 **복합 문장(compound statement)**, 즉 **블록**은 statement 하나다. 블록 안에는 statement뿐 아니라 선언(declaration)도 block item으로 올 수 있다. `int main(void) { ... }`의 `{ ... }`는 함수 정의의 **함수 본문**이며 복합 문장이다. 함수 정의를 닫는 `}` 뒤에는 세미콜론을 붙이지 않는다.

**[C 표준]** `;` 하나만으로 이루어진 **널 문장(null statement)**도 있다. 이는 식이 비어 있는 expression statement다. `printf("Hi\n");`는 함수 호출 식과 끝의 `;`로 이루어진 expression statement다. `return 0;`은 jump statement이고, 블록과 `if` 같은 제어문은 고유한 문법을 가진다.

## 자주 하는 실수

- **함수 정의의 `}` 뒤에 `;`을 붙인다.** 함수 정의는 본문을 닫는 `}`로 끝난다.
- **모든 `}` 뒤에 `;`을 붙인다.** 블록과 제어문에는 해당하지 않는다. 구조체 선언처럼 다른 문법에는 필요할 수 있으므로 문맥을 읽는다.
- **모든 statement를 식과 `;`로 본다.** 블록, 제어문, `return`은 그 형태가 아니다.
- **빈 줄을 널 문장으로 본다.** 빈 줄에는 토큰이 없고 널 문장에는 실제 `;` 토큰이 있다.
- **중괄호 하나를 빼고 다음 줄만 고친다.** 진단 위치가 뒤 토큰일 수 있으므로 먼저 `{`와 `}`의 짝을 확인한다.





# Step 1-4. `printf`와 여러 줄 출력

기준은 C17 호스트 환경이다. 이 Step에서는 `printf`로 보통 문자열을 표준 출력에 쓰고 줄바꿈으로 여러 줄을 만든다. 값 서식 지정은 Part 5에서 다룬다.


## 핵심 개념

**[C 표준]** `printf`는 `<stdio.h>`에 선언된 함수다. 첫 번째 인수인 format 문자열을 해석해 **stdout**(표준 출력 스트림)에 쓴다. 이 Step에서는 변환 지정자 없이 평범한 문자열과 줄바꿈만 사용한다.

문자열 리터럴 안의 `\n`은 소스에 `\`와 `n`을 그대로 출력하라는 뜻이 아니라 new-line character를 나타내는 escape sequence다. `printf("first\nsecond\n");`는 두 개의 new-line character를 출력하며, 일반적인 터미널에서는 보통 두 줄로 보인다.

**[C 표준]** 성공하면 `printf`는 stdout 스트림으로 전송한 문자 수를 반환하고, 출력 또는 인코딩 오류가 나면 음수를 반환한다. 여기서 전송은 스트림에 대한 결과이며, 문자가 물리 장치에 즉시 표시되거나 flush됐다는 뜻은 아니다. 이 반환값은 화면에 보이는 문자열이 아니며 여기서는 검사하지 않는다.

## 문법

```c
#include <stdio.h>

int main(void)
{
    printf("first\nsecond\n");
    return 0;
}
```

`printf(...)`는 함수 호출 식이고, 뒤의 `;`까지가 expression statement다. 문자열 마지막 `\n`은 마지막 줄 뒤의 줄바꿈도 요청한다. 이 Step에서는 `%d`, `%s` 같은 변환 지정자, 추가 인수, 출력 폭·정밀도를 쓰지 않는다. 이는 Part 5의 서식 문자열과 인자 대응 주제다.

## 최소 코드 예제

```c
#include <stdio.h>

int main(void)
{
    printf("Hello\nStart C17\n");
    return 0;
}
```

일반적인 터미널에서는 보통 다음 두 줄로 보인다. C 표준이 특정 화면 표시 방식을 요구하는 것은 아니다.

```text
Hello
Start C17
```

## 코드 해석

| 줄 | 토큰·구성 | 해석 |
|---|---|---|
| 1 | `# include < stdio.h >` | 전처리 지시문이다. `printf` 선언을 제공한다. 끝에 `;`을 붙이지 않는다. |
| 2 | 빈 줄 | 읽기 위한 공백이며 실행 문장이 아니다. |
| 3 | `int main ( void )` | 프로그램 진입 함수 정의의 머리다. |
| 4 | `{` | `main`의 복합 문장을 시작한다. |
| 5 | `printf ( "Hello\nStart C17\n" ) ;` | 함수 호출 식과 이를 끝내는 세미콜론이다. 두 `\n`은 각각 new-line character 하나다. |
| 6 | `return 0 ;` | `main`에서 성공 종료 값을 반환하는 jump statement다. |
| 7 | `}` | 함수 본문을 닫는다. 뒤에 세미콜론은 없다. |





# Step 1-5. 이스케이프 시퀀스 `\n`, `\t`, `\"`, `\\`

기준: C17, 호스트 환경(hosted environment). 이 Step에서는 문자열 리터럴 안에서 특수 문자를 소스에 표기하는 방법을 배운다.


## 핵심 개념

문자열 리터럴 안의 역슬래시 `\`는 이스케이프 시퀀스를 시작한다. 따라서 문자열 안에 큰따옴표 또는 역슬래시 자체를 쓰려면 별도 표기가 필요하다.

| 소스 표기 | 의미 | 문자열에 기여하는 문자 |
|---|---|---|
| `\n` | new-line escape sequence | 새 줄 문자 |
| `\t` | horizontal tab escape sequence | 수평 탭 문자 |
| `\"` | 큰따옴표 표기 | `"` |
| `\\` | 역슬래시 표기 | `\` |

**[C 표준]** 이 표기들은 실행 중 `puts`가 두 글자를 해석하는 명령이 아니다. 문자 및 문자열 리터럴의 이스케이프 시퀀스는 번역 중 처리되어 실행 문자 집합에 맞는 문자 시퀀스가 된다. 좁은 문자열 리터럴은 마지막 널 문자까지 포함하는 `char` 배열을 초기화한다.

`\n`은 소스에서 역슬래시와 `n`으로 쓰지만 문자열에는 새 줄 문자 하나를 뜻한다. 이것이 모든 환경에서 정확히 한 물리 바이트이거나 터미널 커서를 반드시 한 줄 아래로 움직인다는 뜻은 아니다. 텍스트 스트림과 출력 장치가 그 문자를 처리하는 방식은 환경에 따라 다를 수 있다.

`\t`도 수평 탭 문자 하나를 뜻한다. 흔한 터미널에서는 다음 탭 위치까지 공백처럼 보이지만, 보이는 간격은 현재 열, 탭 설정, 글꼴, 출력 장치에 따라 달라진다.

## 최소 코드 예제

`escape_sequences.c`의 전체 내용이다.

```c
#include <stdio.h>

int main(void)
{
    puts("first\nsecond\t\"quote\" \\ path");
    return 0;
}
```

일반적인 터미널에서는 `first` 다음 줄에 `second`, 탭으로 구분된 `"quote"`, 그리고 역슬래시가 보인다. 정확한 공백 폭과 화면 배치는 이식 가능한 기대값이 아니다.

## 코드 해석

| 줄 | 해석 |
|---|---|
| 1 | `puts`의 선언을 얻기 위해 표준 입출력 헤더를 포함한다. |
| 3 | 인수 없이 호출되고 `int`를 반환하는 초기 `main`을 정의한다. |
| 5 | 하나의 문자열 리터럴을 `puts`에 전달한다. |
| 5의 `\n` | 문자열 내용의 새 줄 문자 하나를 나타낸다. |
| 5의 `\t` | 문자열 내용의 수평 탭 문자 하나를 나타낸다. |
| 5의 `\"` | 문자열 내용의 큰따옴표 하나를 나타낸다. |
| 5의 `\\` | 문자열 내용의 역슬래시 하나를 나타낸다. |
| 6 | 초기 `main`에서 성공 종료를 나타내는 값 0을 반환한다. |

`puts`는 전달받은 문자열을 표준 출력에 쓰고 추가 새 줄 문자를 쓴다. 따라서 리터럴 속 `\n`과 `puts`가 추가하는 새 줄은 서로 다른 원인이다.




# Step 1-6. `return 0`과 종료 상태

기준: C17, 호스트 환경(hosted environment). 이 Step에서는 초기 `main` 함수가 반환하는 값과 프로그램 종료 상태를 구별해 이해한다.

## 핵심 개념

호스트 환경에서 프로그램 실행은 초기(initial) `main` 함수의 호출로 시작한다. `main`에서 `return 표현식;`을 실행하면 표현식의 값이 `main`의 반환 값이 된다.

**[C 표준]** 초기 `main`에서 반환하는 것은 `exit` 함수에 같은 값을 인수로 전달해 호출하는 것과 동등하다. 따라서 다음 두 형태는 종료 의미에서 동등하다.

```c
return 0;
```

```c
exit(0);
```

두 번째 형태에는 `exit`의 선언을 위한 `<stdlib.h>`가 필요하지만, 첫 번째 형태에는 필요 없다.

값 `0`은 성공적인 종료(successful termination)를 나타낸다. 성공 여부는 프로그램이 출력한 내용과 별도다. 아무것도 출력하지 않아도 성공 종료할 수 있고, 출력했어도 다른 값으로 종료할 수 있다.

**[C 표준]** C99 이후에는 초기 `main`의 마지막 `}`에 도달하는 것이 `return 0;`을 실행하는 것과 동등하다. 그러나 학습 초기에는 종료 의도를 명시하는 `return 0;`을 쓰면 코드 읽기가 쉽다.

호스트가 실제로 전달받는 표현과 셸이 관찰 가능한 상태 값은 구현과 환경에 따라 달라질 수 있다. Linux 셸에서 흔히 `$?`로 보이는 값은 유용한 관찰이지만, C의 `int` 값이 운영체제에 정확히 같은 바이트들로 직접 전달된다는 뜻은 아니다.

## 문법

```c
return 0;
```

- `return` 뒤의 `0`은 정수 표현식이다.
- 세미콜론 `;`은 `return` 문을 끝낸다.
- `main`의 반환형이 `int`이므로 반환 표현식은 `int`로 변환될 수 있어야 한다.
- 호스트 환경의 초기 `main`에서는 `return 값;`이 프로그램 종료와 연결된다. 다른 일반 함수의 `return`은 호출한 함수로 제어를 돌려줄 뿐이다.




# Step 1-7. 주석·들여쓰기·자기소개 실습

이번 Step에서는 Part 1에서 배운 프로그램 구조와 출력을 읽기 쉬운 자기소개 프로그램으로 묶는다. 기준은 C17 호스트 환경이며, 명령 관찰은 GCC가 있는 GNU/Linux 환경을 기준으로 한다.

## 핵심 개념

**주석(comment)**은 사람에게 코드의 의도나 이유를 설명하기 위한 소스 텍스트다. 주석 자체는 실행되지 않고 `printf` 출력에도 나타나지 않는다.

**[C 표준]** N1570 5.1.1.2의 번역 단계 3에서 소스는 전처리 토큰과 공백 시퀀스로 나뉘며, **각 주석은 공백 하나로 대체된다.** 따라서 주석은 프로그램의 출력 문장이 아니고, 인접한 토큰이 의도하지 않게 붙는 일을 막을 수 있다.

| 형태 | 범위 | 용도 | 주의점 |
|---|---|---|---|
| `//` | 번역 단계 2의 줄 이어붙이기 후, 다음 new-line character 전까지 | 짧은 논리적 한 줄 설명 | C99부터 제공된다. |
| `/* ... */` | `/*`부터 첫 `*/`까지 | 여러 줄 설명 | 중첩되지 않는다. |

**[C 표준]** `//` 주석은 C99부터 언어에 포함되었다. `/* ... */` 블록 주석은 중첩되지 않는다. 즉, 다음 코드는 바깥 주석 안에 안쪽 주석이 생기는 것이 아니다.

```c
/* 바깥 /* 안 */ 뒤 */
```

첫 `*/`에서 주석이 끝나므로 뒤의 텍스트는 C 코드로 해석될 수 있다.

문자열 리터럴 안의 `//`, `/*`, `*/`는 주석 구분자가 아니라 문자다.

```c
printf("// 이것은 출력 문자열입니다.\n");
printf("/* 이것도 출력 문자열입니다. */\n");
```

**들여쓰기(indentation)**는 줄 앞의 공백 또는 탭으로 블록 구조를 사람이 읽기 쉽게 만드는 스타일이다. 들여쓰기 폭은 C 문법이 아니다. 반면 `{`, `}`, `;`, `(`, `)`와 식별자·키워드 등의 토큰은 문법이다.

```c
int main(void)
{
    return 0;
}
```

위 코드에서 네 칸 들여쓰기는 스타일이고, 함수 본문을 실제로 정하는 것은 중괄호다.
