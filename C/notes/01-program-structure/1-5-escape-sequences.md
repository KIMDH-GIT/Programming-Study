# Step 1-5. 이스케이프 시퀀스 `\n`, `\t`, `\"`, `\\`

기준: C17, 호스트 환경(hosted environment). 이 Step에서는 문자열 리터럴 안에서 특수 문자를 소스에 표기하는 방법을 배운다.

## 1. 학습 목표

- `\n`, `\t`, `\"`, `\\`를 문자열 리터럴에 올바르게 작성한다.
- 이스케이프 시퀀스가 소스 표기이며 문자열의 문자 또는 코드 단위에 기여함을 설명한다.
- 줄바꿈과 탭의 화면 표시를 모든 환경에서 같은 동작으로 가정하지 않는다.
- 큰따옴표와 역슬래시를 포함한 문자열을 직접 빌드한다.

## 2. 선수 지식

- 문자열 리터럴이 큰따옴표로 시작하고 끝난다는 점을 안다.
- `puts`를 호출하는 기본 C 프로그램을 빌드하고 실행할 수 있다.
- Part 0의 GCC/Linux 빌드 절차를 사용할 수 있다.

## 3. 핵심 개념

문자열 리터럴 안의 역슬래시 `\`는 이스케이프 시퀀스를 시작한다. 따라서 문자열 안에 큰따옴표 또는 역슬래시 자체를 쓰려면 별도 표기가 필요하다.

| 소스 표기 | 의미 | 문자열에 기여하는 문자 |
|---|---|---|
| `\n` | new-line escape sequence | 새 줄 문자 |
| `\t` | horizontal tab escape sequence | 수평 탭 문자 |
| `\"` | 큰따옴표 표기 | `"` |
| `\\` | 역슬래시 표기 | `\` |

**[C 표준]** 이 표기들은 실행 중 `puts`가 두 글자를 해석하는 명령이 아니다. 문자 및 문자열 리터럴의 이스케이프 시퀀스는 번역 중 처리되어 실행 문자 집합에 맞는 문자 시퀀스가 된다. 좁은 문자열 리터럴은 마지막 널 문자까지 포함하는 `char` 배열을 초기화한다.

`\n`은 소스에서 역슬래시와 `n`으로 쓰지만 문자열에는 새 줄 문자 하나를 뜻한다. 이것이 모든 환경에서 정확히 한 물리 바이트이거나 터미널 커서를 반드시 한 줄 아래로 움직인다는 뜻은 아니다. 텍스트 스트림과 출력 장치가 그 문자를 처리하는 방식은 환경에 따라 다를 수 있다.

`\t`도 수평 탭 문자 하나를 뜻한다. 흔한 터미널에서는 다음 탭 위치까지 공백처럼 보이지만, 보이는 간격은 현재 열, 탭 설정, 글꼴, 출력 장치에 따라 달라진다.

## 4. 문법

```c
"first\nsecond"
"left\tright"
"She said: \"yes\""
"C:\\work\\note.txt"
```

- 이스케이프 시퀀스 안에는 공백을 넣지 않는다. `\ n`은 `\n`이 아니다.
- `\"`는 문자열을 끝내는 구분자가 아니라 문자열 내용의 큰따옴표 하나다.
- `"\\n"`은 줄바꿈 문자가 아니라 역슬래시와 `n` 두 문자를 담는다.
- `printf` 형식 문자열의 `%`에는 별도 규칙이 있으므로, 이 Step의 최소 예제는 `puts`를 사용한다.

## 5. 최소 코드 예제

`escape_sequences.c`의 전체 내용이다.

```c
#include <stdio.h>

int main(void)
{
    puts("first\nsecond\t\"quote\" \\ path");
    return 0;
}
```

일반적인 터미널에서는 `first` 다음 줄에 `second`, 탭으로 구분된 `"quote"`, 그리고 역슬래시가 보인다. 정확한 공백 폭과 화면 배치는 이식 가능한 기대값이 아니다.

## 6. 코드 해석

| 줄 | 해석 |
|---|---|
| 1 | `puts`의 선언을 얻기 위해 표준 입출력 헤더를 포함한다. |
| 3 | 인수 없이 호출되고 `int`를 반환하는 초기 `main`을 정의한다. |
| 5 | 하나의 문자열 리터럴을 `puts`에 전달한다. |
| 5의 `\n` | 문자열 내용의 새 줄 문자 하나를 나타낸다. |
| 5의 `\t` | 문자열 내용의 수평 탭 문자 하나를 나타낸다. |
| 5의 `\"` | 문자열 내용의 큰따옴표 하나를 나타낸다. |
| 5의 `\\` | 문자열 내용의 역슬래시 하나를 나타낸다. |
| 6 | 초기 `main`에서 성공 종료를 나타내는 값 0을 반환한다. |

`puts`는 전달받은 문자열을 표준 출력에 쓰고 추가 새 줄 문자를 쓴다. 따라서 리터럴 속 `\n`과 `puts`가 추가하는 새 줄은 서로 다른 원인이다.

## 7. 내부 동작

**번역 관점:** **[C 표준]** 소스는 전처리 토큰으로 처리된 뒤, 문자열 리터럴의 이스케이프 시퀀스가 실행 문자 집합에 맞게 변환된다. `\n`이라는 두 소스 문자가 프로그램 실행 중 두 문자로 남는 것이 아니다.

**메모리 관점:** 좁은 문자열 리터럴은 문자들의 시퀀스와 끝의 널 문자로 배열을 초기화한다. 예를 들어 `"\\n"`에는 역슬래시, `n`, 널 문자가 있고, `"\n"`에는 새 줄 문자와 널 문자가 있다.

**출력 관점:** `puts`는 표준 출력 스트림에 문자 시퀀스를 전달한다. 텍스트 스트림의 변환, 터미널 에뮬레이터의 제어 처리, 파일의 실제 바이트 표현은 C 소스 표기와 별개의 층이다. C 표준은 특정 터미널, 탭 폭, 운영체제 파일 형식을 요구하지 않는다.

## 8. 자주 하는 실수

- **`"\n"`과 `"\\n"`을 같은 문자열로 생각한다.** 앞은 새 줄 문자, 뒤는 두 문자 `\`와 `n`이다.
- **리터럴 안의 큰따옴표를 그대로 쓴다.** 내부 큰따옴표는 `\"`로 표기한다.
- **Windows 경로에 역슬래시를 하나만 쓴다.** C 문자열에서는 `\\`가 역슬래시 하나다.
- **`\t`를 공백 네 개 또는 여덟 개라고 단정한다.** 탭 문자는 공백 문자들의 고정 개수가 아니다.
- **`\n`을 모든 시스템에서 정확히 한 바이트라고 단정한다.** 소스 표기, 텍스트 스트림 변환, 물리 저장 형식을 구별한다.
- **화면에서 줄이 바뀌었으므로 CPU가 줄 단위로 문자열을 저장한다고 생각한다.** 화면 표시는 출력 장치의 해석 결과다.

## 9. 필수 실습

### 이스케이프 문자가 있는 출력 관찰

- **목적:** 네 이스케이프 시퀀스를 소스와 출력 결과에서 구별한다.
- **해야 할 일:** [실습 안내](../../exercises/01-program-structure/1-5/README.md)에 따라 `escape_sequences.c`를 직접 작성한다. `\n`, `\t`, `\"`, `\\`를 각각 한 번 이상 사용하고, 실제 출력에서 각 부분을 표시한 기록을 남긴다.
- **사용할 개념:** 문자열 리터럴, 이스케이프 시퀀스, 표준 출력, `puts`.
- **예상 관찰 결과:** 줄바꿈과 큰따옴표, 역슬래시가 보인다. 탭은 공백처럼 보일 수 있지만 정확한 폭은 환경마다 다를 수 있다.
- **확인 포인트:** `"\\n"`과 `"\n"`의 차이를 설명했는가? 탭 폭을 고정된 정답으로 기록하지 않았는가? 빌드와 실행을 모두 확인했는가?

## 10. 추가 실습

- ★ **표기 비교:** `"A\nB"`와 `"A\\nB"`를 각각 출력하고 화면 결과와 문자열 내용을 비교한다.
- ★ **경로 표기:** 실제 파일 접근은 하지 않고, 역슬래시를 두 번 써서 경로 모양의 문자열을 출력한다.
- ★★ **출력 대상 비교:** 표준 출력을 파일로 리다이렉션한 뒤 터미널 표시와 파일 내용을 구별해 기록한다. 파일의 바이트 표현을 C 표준의 고정 규칙으로 일반화하지 않는다.

## 11. 확인 문제

1. `\"`가 필요한 이유는 무엇인가?
2. `"\t"`와 `"    "`는 항상 같은 문자열인가?
3. `"\\n"`에는 어떤 문자들이 들어 있는가?
4. `\n`은 언제 처리되는가?
5. 터미널에서 `\t`의 너비가 달라질 수 있는 이유는 무엇인가?

<details>
<summary>정답과 해설 펼치기</summary>

1. 큰따옴표는 문자열 리터럴의 경계를 표시하므로, 내용으로 넣을 때는 `\"`로 표기해야 한다.
2. 아니다. 앞은 수평 탭 문자 하나이고 뒤는 공백 문자 네 개다.
3. 역슬래시, `n`, 그리고 문자열 끝의 널 문자가 들어 있다.
4. 문자 및 문자열 리터럴이 번역될 때 처리된다. 출력 함수가 소스의 두 글자를 나중에 해석하는 것이 아니다.
5. 탭 위치 설정, 현재 출력 열, 터미널 또는 다른 출력 장치의 처리 방식이 달라질 수 있기 때문이다.

## 12. 핵심 정리

- `\n`, `\t`, `\"`, `\\`는 문자열 리터럴 안의 이스케이프 시퀀스다.
- 이스케이프 시퀀스는 소스 표기이며 번역 후 문자열의 문자 또는 코드 단위에 기여한다.
- `\n`의 물리 바이트 수나 터미널 이동을 모든 환경의 동일한 사실로 단정하지 않는다.
- `\t`의 표시 간격은 출력 장치와 환경에 의존한다.
