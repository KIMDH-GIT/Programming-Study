# Step 1-8. Part 1 종합 복습

Part 1에서 배운 C 프로그램의 기본 구조와 출력 규칙을 한 번에 점검한다. 새 변수, 입력, 조건문, 반복문은 도입하지 않는다. 완성된 답안을 복사하지 않고 학습자가 직접 작성하는 자기소개 프로그램으로 개념을 연결한다.

## 1. 학습 목표

- `#include`, `main`, 중괄호, 문장, 세미콜론의 역할을 하나의 프로그램에서 설명한다.
- `printf` 문자열과 `\n`, `\t`, `\"`, `\\`의 역할을 구별해 사용한다.
- `return 0;`의 성공 종료와 화면 출력의 정확성을 별도로 확인한다.
- 주석·들여쓰기의 읽기성 역할과 C 문법의 역할을 분리해 검토한다.

## 2. 선수 지식

Part 1의 Step 1-1~1-7을 마친 뒤 진행한다.

- 첫 프로그램과 `int main(void)`
- `#include`와 표준 헤더

- `printf`와 여러 줄 출력

Part 2의 변수 선언은 아직 배우지 않았으므로 자기소개 항목은 문자열 리터럴로 직접 작성한다.

이식성 비교용 소스에는 기본 소스 문자 집합의 ASCII 문구를 사용한다. 한글 문구를 직접 쓰는 경우에는 컴파일러의 입력·실행 문자 집합과 터미널 인코딩 지원에 의존하는 구현 관찰로 기록한다.

**[GCC 구현]** `gcc -std=c17 -Wall -Wextra -pedantic part1_review.c -o part1_review`로 빌드할 수 있다.

**[GNU/Linux 구현]** 성공한 경우 `./part1_review`로 실행하고 출력과 셸 상태를 따로 확인한다.

## 3. 핵심 개념

Part 1 프로그램은 다음 질문에 답할 수 있어야 한다.

1. 어떤 선언을 포함하는가?
2. 어디서 실행을 시작하는가?
3. 어떤 문장을 어떤 순서로 실행하는가?
4. 문자를 어떻게 출력하는가?
5. 호스트에 어떤 종료 상태를 돌려주는가?

| Part 1 주제 | 프로그램에서 확인할 역할 | 혼동하지 말 것 |
|---|---|---|
| `int main(void)` | 호스트 환경의 프로그램 시작 함수 정의 | 최초 CPU 명령 자체라고 단정하지 않는다. |
| `#include <stdio.h>` | `printf` 선언 등 표준 입출력 인터페이스 제공 | 라이브러리 구현 전체를 텍스트로 복사하는 것은 아니다. |
| statement·`{}`·`;` | 문장 경계와 함수 본문 범위 | 줄 바꿈이나 들여쓰기가 문법을 대신하지 않는다. |
| `printf` | 형식 문자열의 문자를 표준 출력에 보낸다 | 빌드 성공이 출력 요구 충족을 뜻하지 않는다. |
| escape sequence | 문자열 안에서 줄 바꿈·탭·따옴표·역슬래시를 표현 | 탭 폭은 C 표준이 정하지 않는다. |
| `return 0;` | 초기 `main`에서 성공 종료를 나타낸다 | 출력 내용이 맞다는 증명은 아니다. |
| 주석·들여쓰기 | 의도와 구조를 사람이 읽기 쉽게 표시 | 중괄호·세미콜론을 대체하지 않는다. |

**[C 표준]** 호스트 환경의 프로그램 시작은 `main` 호출로 설명되며, 초기 호출에서 `main`이 반환한 값은 `exit`에 전달되는 것과 같다. `return 0;`은 성공 종료 상태다.

`printf`는 `<stdio.h>`에 선언된 표준 입출력 함수다. 이번 Step은 `printf` 반환값 처리보다 프로그램 구조와 정확한 출력을 점검한다.

## 4. 문법

아래는 구조를 보여 주는 뼈대이며, 필수 실습의 완성 프로그램이 아니다.

```c
#include <stdio.h>

int main(void)
{
    /* 출력 묶음의 목적 */
    printf("Item: value\n");
    return 0;
}
```

- `#include <stdio.h>`: 전처리 지시문이며 세미콜론을 붙이지 않는다.
- `int main(void)`: 매개변수를 받지 않고 `int`를 반환하는 시작 함수 정의다.
- `{`와 `}`: 함수 본문의 범위를 정한다.
- `printf("...");`: 호출 식을 세미콜론으로 끝낸 문장이다.
- `\n`: 줄 바꿈이다.
- `\t`: 수평 탭이다.
- `\"`: 문자열 안의 큰따옴표 문자다.
- `\\`: 문자열 안의 역슬래시 문자다.
- `//`: 번역 단계 2의 줄 이어붙이기 후, 다음 new-line character 전까지의 주석이다.
- `/* ... */`: 첫 `*/`까지의 블록 주석이며 중첩되지 않는다.

**[C 표준]** 주석은 번역 단계 3에서 공백 하나로 대체된다. 문자열 리터럴 내부의 `//`, `/*`, `*/`는 문자다.

## 5. 최소 코드 예제

다음은 여러 줄 출력과 이스케이프 시퀀스를 확인하는 최소 예제다. 자기소개 필수 항목을 모두 채운 완성 답안은 아니다.

```c
#include <stdio.h>

int main(void)
{
    printf("Title:\t\"Part 1\"\n");
    return 0;
}
```

일반적인 터미널에서는 `Title:` 뒤 탭 위치에 큰따옴표를 포함한 `Part 1`이 보이고 줄이 바뀐다.

**[GNU/Linux 구현]** 탭의 열 위치는 터미널 설정과 표시 폭에 따라 달라질 수 있다. `return 0;`의 성공 종료와 화면 내용이 요구와 맞는지는 별도로 확인한다.

## 6. 코드 해석

| 부분 | Part 1에서의 해석 | 검토 방법 |
|---|---|---|
| 헤더 포함 | `printf` 선언을 사용하기 위한 표준 헤더를 지정한다. | `<stdio.h>`의 철자와 `#include` 형태를 확인한다. |
| `main` 정의 | 호스트 환경의 시작 함수 본문을 제공한다. | `int main(void)`와 중괄호 짝을 확인한다. |
| 주석 | 출력 묶음의 이유를 독자에게 설명한다. | 출력에 나타나지 않고 코드와 어긋나지 않는지 본다. |
| `printf` 문장 | 문자열 리터럴의 문자를 순서대로 출력하도록 요청한다. | 각 호출의 괄호·큰따옴표·세미콜론을 확인한다. |
| 이스케이프 | 문자열에 그대로 쓰기 어려운 제어 문자나 구분 문자를 나타낸다. | `\n`, `\t`, `\"`, `\\`를 확인한다. |
| `return 0;` | `main`의 성공 반환을 지정한다. | 빌드·실행 상태를 확인한다. |

여러 줄은 `printf("첫 줄\n");`처럼 호출을 나눌 수 있고, `printf("첫 줄\n둘째 줄\n");`처럼 한 문자열에 넣을 수도 있다. 두 방식 모두 올바른 문자열과 문장 종료가 필요하다.

## 7. 내부 동작

**[C 표준] 전처리와 주석:** N1570 5.1.1.2의 단계 2에서 역슬래시-new-line을 제거해 줄을 이어 붙이고, 단계 3에서 각 주석을 공백 하나로 대체한다. `//`는 C99부터 제공되며 이 처리 뒤의 다음 new-line character 전까지다. 이어 `#include` 지시문이 처리된다. N1570 6.4.9의 `/* ... */`는 중첩되지 않는다. 문자열 리터럴 내부의 주석처럼 보이는 기호는 문자다.

**[C 표준] 문법과 호출:** 컴파일러는 토큰과 문법으로 함수 정의의 중괄호 범위, `printf` 호출의 괄호, 문장의 세미콜론을 해석한다. 들여쓰기 폭은 이 해석 규칙이 아니다. `<stdio.h>`의 선언을 바탕으로 `printf` 호출을 검사하고, 전체 프로그램 구성에는 표준 라이브러리의 정의가 필요하다.

**[GCC 구현] 번역:** GCC는 전처리, 컴파일, 어셈블, 링크를 하나의 드라이버 호출로 연결할 수 있다. 진단의 문구와 위치는 GCC 버전과 옵션에 따른 구현 결과다. 경고가 없다는 사실은 출력 요구를 만족한다는 증명이 아니다.

**[GNU/Linux 구현] 실행:** 일반적인 Linux 실행에서는 시작 코드와 런타임 준비 뒤 `main`이 호출되고 표준 출력은 보통 터미널에 연결된다. 출력이 화면에 보이는 시점, 탭의 폭, 셸의 상태 표시는 환경 관찰이다.

## 8. 자주 하는 실수

- `#include <stdio.h>;`처럼 전처리 지시문 끝에 세미콜론을 붙인다.
- `int main()`을 무조건 같은 표기로 취급한다. 이 과정에서는 `int main(void)`를 사용한다.
- `printf("안녕\n")` 뒤 세미콜론을 빠뜨린다.
- 역슬래시 하나를 출력하려고 문자열에 역슬래시 하나만 쓴다.
- 문자열 내부 큰따옴표 앞에 `\`를 쓰지 않는다.
- 문자열 속 `//` 또는 `/*`를 실제 주석으로 오해한다.
- 들여쓰기만 맞추고 중괄호 한쪽을 빼먹는다.
- 빌드 성공이나 상태 0만으로 항목·순서·출력 문자가 정확하다고 판단한다.

## 11. 확인 문제

1. `#include <stdio.h>`와 `printf(...);`는 각각 어느 처리 규칙에 속하는가?
2. `int main(void)`의 `void`는 무엇을 분명히 하는가?
3. `printf("A\nB\n");`와 두 개의 `printf` 호출은 어떤 점에서 같은 출력이 될 수 있는가?
4. `\"`와 `\\`는 문자열에서 각각 무엇을 표현하는가?
5. 주석이 공백 하나로 바뀌어도 왜 `"//"`는 출력될 수 있는가?
6. 들여쓰기와 중괄호 중 함수 본문 범위를 실제로 정하는 것은 무엇인가?
7. 빌드 성공과 `return 0;`만으로 출력 요구 충족을 증명할 수 없는 이유는 무엇인가?

<details>
<summary>정답과 해설</summary>

1. `#include`는 전처리 지시문이고, `printf(...);`는 함수 호출 식을 세미콜론으로 끝낸 C 문장이다.
2. `main`이 매개변수를 받지 않는다는 점을 분명히 한다.
3. 두 경우 모두 같은 문자와 줄 바꿈을 같은 순서로 표준 출력에 보낼 수 있다.
4. `\"`는 큰따옴표 문자이고 `\\`는 역슬래시 문자 하나다.
5. 큰따옴표 안의 `//`는 문자열 리터럴의 문자이므로 주석 구분자로 처리되지 않는다.
6. 중괄호와 C 문법이다. 들여쓰기는 사람이 구조를 읽게 하는 스타일이다.
7. 빌드 성공은 번역·연결의 성공이고 반환 0은 성공 상태 보고다. 항목 내용·순서·문자는 요구와 직접 비교해야 한다.

## 12. 핵심 정리

Part 1의 최소 프로그램은 `<stdio.h>` 포함, `int main(void)` 정의, 중괄호로 된 본문, 세미콜론으로 끝나는 `printf` 문장, `return 0;`으로 구성한다.

문자열에서는 이스케이프 시퀀스로 줄 바꿈, 탭, 큰따옴표, 역슬래시를 표현한다. 주석은 번역 단계 3에서 공백 하나로 바뀌고 들여쓰기는 스타일이지만, 중괄호와 세미콜론은 실제 C 문법이다. 빌드, 성공 종료, 요구한 출력의 일치는 각각 확인한다.
