# 30-10. `peek`
## 1. 학습 목표
- top을 제거하지 않고 읽는 `stack_peek`를 작성한다.
- 빈 stack과 NULL 인자를 status로 처리하고 읽기 전용 계약을 검증한다.
## 2. 선수 지식
30-8의 `push` 불변식과 30-9의 status·output 계약을 안다.
## 3. 핵심 개념
LIFO stack ADT의 `peek`는 다음에 pop할 값을 보여 주지만 node를 제거하지 않는다. `size == 0` iff `top == NULL`; nonempty top은 소유된 첫 node이며 chain은 acyclic·`NULL`-terminated이다. `size`는 `top`에서 도달 가능한 live node 수와 같으며, non-NULL stack 인자는 모든 연산 진입 전에 이 불변식을 만족해야 한다. 이 linked stack은 compiler/ABI/runtime call stack과 다르다.
## 4. 문법
```c
static int stack_peek(const Stack *stack, int *value);
```
`stack == NULL`, `value == NULL`, 빈 stack이면 0이고 유효한 output과 stack은 그대로다. 성공 시 별도의 살아 있는 writable `int` output에 top 값을 쓰고 1을 반환한다. output은 stack/node 저장소와 겹치지 않아야 한다. invalid non-NULL pointer는 검사할 수 없다. 성공해도 top·size·node 연결과 소유권은 변하지 않는다.
## 5. 최소 코드 예제
```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *next;
} Node;

typedef struct {
    Node *top;
    size_t size;
} Stack;

static int stack_push(Stack *stack, int value)
{
    if (stack == NULL || stack->size == SIZE_MAX) {
        return 0;
    }
    Node *node = malloc(sizeof *node);
    if (node == NULL) {
        return 0;
    }
    node->value = value;
    node->next = stack->top;
    stack->top = node;
    ++stack->size;
    return 1;
}

static int stack_peek(const Stack *stack, int *value)
{
    if (stack == NULL || value == NULL || stack->top == NULL) {
        return 0;
    }
    *value = stack->top->value;
    return 1;
}

/* Precondition: stack is non-NULL and points to a live writable Stack
   satisfying its ownership and chain invariant. An empty stack is allowed. */
static void stack_destroy(Stack *stack)
{
    Node *current = stack->top;
    while (current != NULL) {
        Node *next = current->next;
        free(current);
        current = next;
    }
    stack->top = NULL;
    stack->size = 0;
}

int main(void)
{
    Stack stack = {NULL, 0};
    int value = 99;
    int empty_status = stack_peek(&stack, &value);
    printf("empty=%d value=%d\n", empty_status, value);
    if (!stack_push(&stack, -1) || !stack_push(&stack, 8)) {
        stack_destroy(&stack);
        return 1;
    }
    Node *before = stack.top;
    size_t count_before = stack.size;
    int first_status = stack_peek(&stack, &value);
    printf("peek=%d value=%d size=%zu\n", first_status, value, stack.size);
    int second_status = stack_peek(&stack, &value);
    printf("again=%d value=%d unchanged=%d\n",
           second_status, value,
           stack.top == before && stack.size == count_before);
    stack_destroy(&stack);
    return 0;
}
```

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror main.c -o stack_peek
./stack_peek
```
## 6. 코드 해석
출력은 `empty=0 value=99`, `peek=1 value=8 size=2`, `again=1 value=8 unchanged=1` 순이다. 두 번 읽은 뒤에도 두 node 모두 stack이 소유하므로 종료 전 해제한다.
## 7. 내부 동작
**[Algorithm]** 현재 원소 수 `n`과 관계없이 top 하나를 읽어 시간 `O(1)`, 추가 공간 `O(1)`이다. 성공·실패 모두 top과 size는 그대로다.

**[C17]** `const Stack *`는 이 pointer를 통한 Stack 멤버 수정을 제한하지만 `Node *top`이 가리키는 node까지 자동으로 const로 만들지는 않는다. 구현은 node도 변경하지 않는다. `const`는 객체를 ROM에 배치한다는 뜻이 아니다. node의 lifetime은 `stack_destroy`에서 `free`할 때 끝난다.

**[구현 경계]** C17의 pointer·lifetime 계약은 allocator 내부 상태, OS virtual memory와 CPU cache 동작에 의존하지 않는다.
## 8. 자주 하는 실수
- `peek` 중 top을 다음 node로 옮기거나 size를 줄인다.
- 빈 상태에 top을 역참조하거나 `-1`을 실패 sentinel로 쓴다.
- `const Stack *`가 모든 node까지 깊게 const로 만든다고 생각한다.

2. 빈 stack의 output은 바뀌는가?
3. 두 번 peek한 결과가 같은 이유는?
4. `const Stack *`가 node까지 자동으로 const로 만들지 않는 이유는?
5. const가 ROM 배치를 보장하는가?
## 12. 핵심 정리
- peek는 status와 output으로 top 값을 읽되 node를 제거하지 않는다.
- 성공·실패 모두 stack의 top과 size를 보존한다.
