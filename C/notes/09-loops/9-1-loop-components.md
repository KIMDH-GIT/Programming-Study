# 9-1. 반복의 초기화·조건·변화

반복문은 같은 statement를 다시 쓰지 않고, 상태가 일정한 규칙으로 변하는 동안 실행한다.

## 1. 학습 목표
- 반복을 초기 상태, 조건, 본문, 변화로 나눈다.
- 반복 전후의 값을 손으로 추적한다.
- 종료 조건이 필요한 이유를 설명한다.

## 2. 선수 지식
Part 7의 식·대입·증감과 Part 8의 0/비0 조건 판단을 사용한다.

## 3. 핵심 개념
반복에는 보통 네 요소가 있다. **초기화**는 첫 검사 전 상태를 만들고, **조건**은 계속할지를 정하며, **본문**은 반복할 일을 수행하고, **변화**는 다음 검사가 언젠가 거짓이 되도록 상태를 바꾼다. C17에서 조건식은 scalar 식이며 0은 거짓, 0이 아닌 값은 참이다. 변화가 없거나 종료할 수 없는 조건이면 의도하지 않은 무한 반복이 된다.

## 4. 문법
```c
int count = 1;          /* 초기화 */
while (count <= 3) {    /* 조건 */
    statement;          /* 본문 */
    ++count;            /* 변화 */
}
```

## 5. 최소 코드 예제
```c
#include <stdio.h>

int main(void)
{
    int count = 1;
    while (count <= 3) {
        printf("%d\n", count);
        ++count;
    }
    return 0;
}
```

## 6. 코드 해석
`count`는 1에서 시작한다. 조건이 참이면 출력 후 1 증가하고 다시 검사한다. 1, 2, 3을 출력한 뒤 `count`가 4가 되면 조건이 거짓이어서 끝난다.

| 검사 시점의 `count` | `count <= 3` | 본문 | 변화 후 |
|---:|:---:|---|---:|
| 1 | 참 | 1 출력 | 2 |
| 2 | 참 | 2 출력 | 3 |
| 3 | 참 | 3 출력 | 4 |
| 4 | 거짓 | 실행 안 함 | - |

## 7. 내부 동작
[C 언어 관점] 매 검사에서 조건식을 평가하고 결과에 따라 본문 또는 다음 statement로 제어를 옮긴다. [컴파일러 관점] 같은 observable behavior를 보존하는 범위에서 분기·비교를 다른 기계어 형태로 최적화할 수 있다. 반복문 하나가 특정 CPU 명령 하나와 1:1 대응하지는 않는다.

## 8. 자주 하는 실수
- 변화를 빼서 조건이 계속 참이 되게 한다.
- 본문보다 변화가 먼저 일어난다고 착각한다.
- `count = 3`과 `count == 3`을 혼동한다. 대입 조건은 syntax error가 아니며 대입 결과 3이 참이지만 GCC가 경고할 수 있다.
- signed 정수가 범위를 넘도록 증가시키면 C17에서 undefined behavior다.

## 11. 확인 문제
1. 반복의 네 요소는 무엇인가?
2. 조건이 처음부터 0이면 어떤 일이 생기는가?
3. 예제의 조건 검사는 총 몇 번인가?
4. 변화가 종료 조건에서 멀어지면 어떤 문제가 생기는가?
5. signed overflow 예제를 실행 과제로 쓰면 안 되는 이유는 무엇인가?

## 12. 핵심 정리
반복은 초기화 → 조건 검사 → 본문 → 변화 → 재검사의 흐름으로 이해하고, 종료 가능한지 값으로 추적한다.
