# 9-6. 반복 범위와 off-by-one 오류

off-by-one은 경계 비교를 하나 잘못 선택해 한 번 많거나 적게 반복하는 오류다.

## 1. 학습 목표
- `<`와 `<=`의 반복 횟수를 계산한다.
- 반열린 범위와 닫힌 범위를 구분한다.
- 초기값·조건·실행·갱신 순서로 경계를 검증한다.

## 2. 선수 지식
Step 9-4의 `for` 평가 순서와 Part 8의 경계값 설계를 안다.

## 3. 핵심 개념
초기값 0에서 `i < 10`은 0~9로 10회, `i <= 10`은 0~10으로 11회다. “10까지”와 “10개”는 다르다. 원하는 값의 첫 값과 마지막 값을 먼저 적고, 마지막 유효 값 다음 검사까지 추적하면 암기보다 안전하다.

## 4. 문법
```c
for (int i = 0; i < 10; ++i) { /* 0 이상 10 미만 */ }
for (int i = 0; i <= 10; ++i) { /* 0 이상 10 이하 */ }
```

## 5. 최소 코드 예제
```c
#include <stdio.h>

int main(void)
{
    for (int i = 0; i < 3; ++i) {
        printf("%d\n", i);
    }
    return 0;
}
```

## 6. 코드 해석
| iteration | condition 전 `i` | `i < 3` | body | update 후 `i` |
|---:|---:|:---:|---|---:|
| 1 | 0 | 참 | 0 출력 | 1 |
| 2 | 1 | 참 | 1 출력 | 2 |
| 3 | 2 | 참 | 2 출력 | 3 |
| 종료 검사 | 3 | 거짓 | 실행 안 함 | - |

조건을 `i <= 3`으로 바꾸면 `i == 3`인 네 번째 본문이 추가된다.

## 7. 내부 동작
[C 언어 관점] 표준은 의도한 횟수를 알지 못하므로 두 조건 모두 올바른 프로그램일 수 있다. 오류는 요구 범위와 조건이 불일치할 때 생긴다. 컴파일러 경고만으로 일반적인 off-by-one을 모두 찾을 수 없다.

## 8. 자주 하는 실수
- N개 출력을 `0`부터 `<= N`으로 작성한다.
- 감소 반복에서 마지막 값과 종료 후 값을 혼동한다.
- 조건 검사 횟수와 본문 실행 횟수를 같다고 센다.
- 경계를 고치며 초기값까지 동시에 바꿔 새 오류를 만든다.

## 9. 필수 실습

## 10. 추가 실습
- ★ 1~5 포함 범위
- ★★ 5개의 짝수 출력
- ★★★ 감소 반복 `5`부터 `1`까지의 조건 두 가지 비교

## 11. 확인 문제
1. `i = 0; i < 10`의 본문 횟수는?
2. `i = 0; i <= 10`의 마지막 출력은?
3. 본문 10회일 때 조건 검사는 보통 몇 번인가?
4. 1~100을 포함하려면 어떤 초기값과 조건이 필요한가?
5. 컴파일러가 모든 off-by-one을 경고할 수 없는 이유는?

## 12. 핵심 정리
범위는 첫 값·마지막 값·종료 검사를 표로 추적하고 `<`와 `<=`를 의도에 맞게 선택한다.
