# 2-3. `long`, `long long`

기준은 C17 호스트 환경이다. 이번 Step은 큰 정수를 저장할 자료형을 고르는 연습이다. `long`이 항상 8바이트라는 가정 대신 **표준이 보장하는 범위**와 **현재 구현에서 관찰한 범위**를 구별한다.

## 1. 학습 목표

- `long`, `long long` 변수를 선언하고 범위 안의 값으로 초기화한다.
- `short`, `int`, `long`, `long long`의 크기 순서와 최소 보장 범위를 설명한다.
- `L`, `LL` 접미사와 `%ld`, `%lld`를 자료형에 맞게 사용한다.
- `<limits.h>`의 실제 한계값을 확인하고 한 컴퓨터의 결과를 모든 C 구현에 일반화하지 않는다.

## 2. 선수 지식

- [Part 1 복습](../01-program-structure/1-8-part-1-review.md)의 `<stdio.h>`, `int main(void)`, `printf`, `return 0;`.
- [커리큘럼 Part 2](../../C_CURRICULUM.md#part-2-변수와-자료형)의 2-1 변수 선언·초기화와 2-2 `char`, `short`, `int`.
- 선언 `int count = 12;`는 자료형과 이름을 정하고 처음 값을 넣는다. 이 Step에서는 자료형을 바꾸어 더 넓은 정수 범위를 선택한다.

입력 함수, 조건문, 반복문, 배열, 포인터, 동적 메모리는 필요 없다. 출력 확인용 `%ld`, `%lld`와 한계값 매크로만 미리 설명한다. 서식 지정 전체는 Part 5, `sizeof`와 한계값의 종합 실습은 2-6~2-9의 주제다.

## 3. 핵심 개념

### 이름이 다르면 반드시 크기도 다른가?

**[C 표준]** `long`은 `long int`, `signed long int`와 같은 자료형이다. `long long`은 `long long int`, `signed long long int`와 같은 자료형이다. `unsigned`를 붙이지 않은 이 두 자료형은 음수, 0, 양수를 표현하는 부호 있는 정수형이다. `long`과 `long long`은 크기가 같아도 서로 다른 자료형이다.

표준 부호 있는 정수형은 앞의 자료형 이상으로 저장 공간을 제공한다. `sizeof`는 자료형이나 객체의 크기를 C 바이트 단위로 구하는 연산자이며, 지금은 다음 관계를 읽는 데만 사용한다.

```text
sizeof(char) = 1
sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)
```

`<=`는 작거나 같다는 뜻이다. `int`와 `long`, 또는 `long`과 `long long`의 크기가 같아도 적법하다. 대응하는 순서의 signed 정수형에서 작은 순위 자료형의 값 범위는 큰 순위 자료형 범위에 포함된다. 즉 `long long`은 `long`의 모든 값을 표현할 수 있다. 순위가 높다고 크기가 반드시 더 큰 것은 아니다.

### 최소 보장 범위와 실제 범위

**[C 표준]** 다음 구간의 모든 정수는 적어도 표현할 수 있어야 한다. 이 표의 양 끝이 모든 구현의 정확한 최솟값·최댓값이라는 뜻은 아니다.

| 자료형 | 적어도 표현 가능한 구간 | 실제 범위를 나타내는 `<limits.h>` 매크로 |
|---|---|---|
| `signed char` | -127 ~ 127 | `SCHAR_MIN`, `SCHAR_MAX` |
| `short` | -32767 ~ 32767 | `SHRT_MIN`, `SHRT_MAX` |
| `int` | -32767 ~ 32767 | `INT_MIN`, `INT_MAX` |
| `long` | -2147483647 ~ 2147483647 | `LONG_MIN`, `LONG_MAX` |
| `long long` | -9223372036854775807 ~ 9223372036854775807 | `LLONG_MIN`, `LLONG_MAX` |

C17은 signed 표현을 2의 보수 하나로 제한하지 않으므로 최소 보장 구간의 음수 끝을 임의로 한 칸 더 넓히지 않는다. 흔한 2의 보수 64비트 `long long`의 실제 범위는 -9223372036854775808 ~ 9223372036854775807이다. 정확한 한계는 매크로로 확인한다. `char` 자체의 부호 유무는 구현에 따라 달라 위 표에는 명시적인 `signed char`를 썼다.

**[구현 정의/ABI 의존]** 자료형별 정확한 크기, 정수 표현, 한계는 대상 구현이 정한다. C 바이트의 비트 수 `CHAR_BIT`는 적어도 8이지만 반드시 8은 아니다. 따라서 최소 범위를 곧바로 모든 환경의 `sizeof` 값으로 바꾸면 안 된다.

다음은 `CHAR_BIT == 8`인 대표적인 데이터 모델의 **예**다. 이 표는 C17의 의무 규정이 아니다.

| 대표 모델 | `int` 바이트 | `long` 바이트 | `long long` 바이트 | 흔한 대상 |
|---|---:|---:|---:|---|
| ILP32 | 4 | 4 | 8 | 여러 32비트 ABI |
| LP64 | 4 | 8 | 8 | 일반적인 64비트 Linux ABI |
| LLP64 | 4 | 4 | 8 | 64비트 Windows ABI |

64비트 CPU라는 사실만으로 `long`을 8바이트라고 결론 내릴 수 없다. 모델 이름의 다른 구성 요소까지 외울 필요는 없다.

## 4. 문법

선언의 형태는 `자료형 이름 = 초기값;`이다.

| 선언 예 | 뜻 | 이 값의 출력 지정자 |
|---|---|---|
| `long distance = 2000000000L;` | `long` 변수와 `long` 정수 상수 | `%ld` |
| `long long population = 8000000000LL;` | `long long` 변수와 `long long` 정수 상수 | `%lld` |

`L`과 `LL`은 숫자에 붙는 정수 상수 접미사다. 글자 `l`은 숫자 `1`과 혼동하기 쉬워 대문자를 권한다. 값에 맞는 자료형으로 상수를 해석하도록 돕지만, 어떤 값이든 강제로 그 자료형에 들어가게 만들지는 않는다.

이 Step의 양의 **10진수** 상수에서 접미사가 없으면 `int`, `long`, `long long` 순으로 처음 표현 가능한 자료형을 고른다. `L`이면 `long`, `long long` 순으로 고르고 `LL`이면 `long long`을 사용한다. 여기서는 그 후보 범위에 들어가는 상수만 사용한다. `8000000000L`은 `long` 범위를 넘는 구현에서는 `long long`일 수 있으므로 접미사 `L`을 고정 크기 보증으로 읽으면 안 된다.

`printf("distance=%ld\n", distance);`에서 문자열 뒤의 `distance`가 출력할 값이다. `%ld`는 signed `long`, `%lld`는 signed `long long`에 대응한다. 크기가 같아도 `%d`로 대체하지 않는다. `%d`가 요구하는 것은 `int`다. 잘못된 인수 자료형으로 호출하면 정의되지 않은 동작이 될 수 있다.

## 5. 최소 코드 예제

`wide_values.c`로 저장하여 실행할 수 있는 완전한 예제다.

```c
#include <stdio.h>

int main(void)
{
    long distance = 2000000000L;
    long long population = 8000000000LL;

    printf("distance=%ld\n", distance);
    printf("population=%lld\n", population);
    return 0;
}
```

정상적인 표준 출력 환경에서 예상 결과는 다음과 같다. 두 초기값 모두 해당 자료형의 C17 최소 보장 범위에 들어가므로 이 출력은 `long`의 크기가 4인지 8인지에 의존하지 않는다.

```text
distance=2000000000
population=8000000000
```

## 6. 코드 해석

| 구성 | 해석 |
|---|---|
| `#include <stdio.h>` | `printf` 선언을 제공한다. |
| `int main(void)` | 호스트 환경에서 프로그램의 시작 함수다. |
| `long distance = 2000000000L;` | `long` 객체를 선언하고 20억으로 초기화한다. |
| `long long population = 8000000000LL;` | `long long` 객체를 선언하고 80억으로 초기화한다. |
| 첫 번째 `printf` | `distance` 값을 `%ld`로 10진수 출력한다. |
| 두 번째 `printf` | `population` 값을 `%lld`로 10진수 출력한다. |
| `return 0;` | 초기 `main` 호출을 성공 종료한다. |

20억은 표준이 `long`에 보장하지만 `int`에는 보장하지 않는 값이다. 80억은 `long long`에 보장하지만 `long`에는 보장하지 않는다. 이 차이가 자료형 선택의 이유다.

## 7. 내부 동작

1. **[C 표준/컴파일러]** 컴파일러는 정수 상수의 값·접미사를 보고 자료형을 정하고, 선언한 객체의 자료형으로 초기화한다. 왼쪽 변수를 큰 자료형으로 선언했다고 오른쪽의 모든 계산까지 그 자료형으로 바뀌지는 않는다. 계산과 변환의 상세 규칙은 Part 6에서 다룬다.
2. **[C 표준/메모리]** 객체는 그 자료형에 맞는 크기와 값 표현을 가진다. 숫자 `8000000000`은 십진수 글자 열 그대로 저장하는 것이 아니라 정수 값으로 표현한다. 실제 바이트 수와 바이트 순서는 대상 구현에 의존한다.
3. **[컴파일러/CPU]** 값은 레지스터에 놓이거나 최적화로 상수가 직접 전달될 수 있다. `main` 안의 모든 변수에 반드시 별도 메모리 칸을 남기는 것은 아니다. CPU가 한 번에 처리하는 폭보다 넓은 계산은 여러 명령으로 구현될 수 있다. 자료형 이름만으로 속도를 단정하지 않는다.
4. **[OS/ABI]** ABI는 자료형의 크기와 함수에 값을 전달하는 규약 등에 관여한다. 운영체제가 실행 때 숫자의 크기를 보고 `long`을 자동 확장하는 것이 아니다. 자료형의 범위는 번역 대상에 따라 정해진다.
5. **[표준 라이브러리]** `printf`는 서식과 전달된 값을 이용해 정수를 출력 문자로 변환한다. `%lld`는 저장 공간을 늘리는 명령이 아니다.

## 8. 자주 하는 실수

- **`long`은 언제나 8바이트다.** LLP64의 흔한 `long`은 4바이트다. 대상의 한계를 확인한다.
- **`long long`은 반드시 `long`의 두 배다.** 둘 다 8바이트인 구현도 흔하다.
- **`long count = 8000000000LL;`이면 어디서든 안전하다.** 상수는 표현 가능해도 목적지 `long`에는 안 들어갈 수 있다. 범위 밖 signed 변환은 구현 정의 결과 또는 구현 정의 신호이며, signed 산술 overflow와 같은 규칙이 아니다. 이 Step에서는 그런 변환을 피한다.
- **`printf("%d\n", distance);`를 쓴다.** `long`에는 `%ld`를 쓴다. 크기가 우연히 같아도 인수의 자료형 계약을 맞춰야 한다.
- **가장 작은 음수를 큰 양의 상수에 `-`만 붙여 만든다.** 양의 상수 자체가 먼저 해석된다. 경계값은 `LONG_MIN`, `LLONG_MIN`을 사용하면 안전하고 의도가 분명하다.
- **경고가 없으니 이식 가능하다.** 현재 구현에서 들어간 값이 다른 구현에도 들어간다는 뜻은 아니다.

## 9. 필수 실습

### A. 큰 값 출력

- **목적:** 값의 필요 범위에 맞는 자료형과 서식을 선택한다.
- **파일/해야 할 일:** [실습 안내](../../exercises/02-variables-and-types/2-3/README.md)에 따라 `wide_values.c`를 직접 작성하고 5절의 두 값을 각각 출력한다.
- **사용할 개념:** 선언, 초기화, `L`, `LL`, `%ld`, `%lld`.
- **예상 관찰 결과:** `distance=2000000000`, `population=8000000000`의 두 줄이다.
- **확인 포인트:** 80억을 담는 변수가 `long long`인가? 출력 지정자가 실제 변수 자료형과 맞는가?

`C/`에서 다음 디렉터리로 이동한 뒤 빌드한다. `&&`는 앞 명령이 성공한 때만 뒤 명령을 실행하는 셸 문법이다.

```sh
cd exercises/02-variables-and-types/2-3
gcc -std=c17 -Wall -Wextra -Wpedantic wide_values.c -o wide_values && ./wide_values
```

### B. 현재 한계값 확인

- **목적:** 최소 보장 범위와 구현의 실제 범위를 분리한다.
- **파일/해야 할 일:** `wide_limits.c`에 `<stdio.h>`와 `<limits.h>`를 포함한다. `LONG_MIN`, `LONG_MAX`는 `%ld`로, `LLONG_MIN`, `LLONG_MAX`는 `%lld`로 한 줄씩 이름과 함께 출력한다. 매크로는 표준 헤더가 제공하는 정수 상수 표현이며 함수처럼 `()`를 붙여 호출하지 않는다.
- **사용할 개념:** 표준 헤더, 한계 매크로, 자료형에 맞는 출력.
- **예상 관찰 결과:** 각 범위는 3절의 최소 구간을 포함한다. 두 자료형의 한계값이 같을 수도 있다. 정확한 숫자는 현재 구현의 관찰 결과로 기록한다.
- **확인 포인트:** `LONG_MAX + 1L`을 계산하지 않았는가? 한계값 관찰에 overflow 실험은 필요 없다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic wide_limits.c -o wide_limits && ./wide_limits
```

6. **설명:** 현재 환경의 `LONG_MAX`가 9223372036854775807이면 C17이 `long`에 그 값을 보장한다고 말할 수 있는가?

## 12. 핵심 정리

- `long`은 적어도 -2147483647 ~ 2147483647, `long long`은 적어도 -9223372036854775807 ~ 9223372036854775807을 표현한다.
- 자료형의 저장 크기 순서는 작거나 같음이다. 정확한 바이트 수는 구현에 따라 다르다.
- `L`·`LL`로 상수의 의도를 표시하고 `%ld`·`%lld`로 실제 인수 자료형을 맞춘다.
- 실제 경계는 `<limits.h>`로 확인하고 경계를 넘는 signed 계산을 실습하지 않는다.
