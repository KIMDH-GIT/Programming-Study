# 2-5. `float`, `double`, `long double`

기준은 C17 호스트 환경이다. 소수 부분이 있는 값을 저장하는 세 실수 부동소수점형을 배운다. **ISO C가 요구하는 성질**과 **흔한 IEEE 754 구현의 성질**을 구분한다. 크기 측정은 다음 Step, `<float.h>`의 상세 해석은 2-8에서 이어 간다.

## 1. 학습 목표

- `float`, `double`, `long double` 변수를 선언하고 초기화한다.
- 실수 상수의 접미사 없음, `f`, `L`이 결정하는 자료형을 설명한다.
- 범위, 정밀도, 출력 소수 자릿수를 서로 구별한다.
- `printf`에서 `float`와 `double`은 `%f`, `long double`은 `%Lf`로 출력한다.
- 관찰한 소수 근삿값이나 구현별 크기를 C 전체의 규칙으로 일반화하지 않는다.

- [헤더 포함](../01-program-structure/1-2-include-standard-headers.md), [출력과 줄바꿈](../01-program-structure/1-4-printf-multiline-output.md), [빌드와 실행](../00-compilation/0-7-build-and-run.md).

`double temperature = 23.5;`는 `temperature`라는 `double` 변수를 만들고 초기값을 주는 선언이다. 여기서 `=`는 같음을 묻는 기호가 아니다. 입력, 배열, 포인터, 조건문, 반복문, 동적 메모리는 필요하지 않다. Part 5의 출력 서식 중 이번 관찰에 필요한 것만 먼저 사용한다.

## 3. 핵심 개념

### 실수형이 모든 실수를 저장하는 것은 아니다

수학의 실수는 무한히 많지만 한 객체의 표현에는 유한한 저장 공간을 쓴다. 부동소수점형은 정해진 범위 안의 일부 값만 표현하며 나머지는 표현 가능한 값으로 근사해야 한다. 소수점을 쓸 수 있다는 말이 모든 소수를 정확히 저장한다는 뜻은 아니다.

- **범위(range):** 얼마나 큰 값, 얼마나 0에 가까운 작은 값을 표현할 수 있는가.
- **정밀도(precision):** 유효한 자릿값을 얼마나 보존할 수 있는가. 정수 부분까지 포함한 유효 숫자의 문제이지 소수점 아래 고정 자릿수의 문제가 아니다.
- **출력 정밀도:** `%.2f`처럼 화면에 소수점 아래 몇 자리를 표시할지 정하는 규칙. 저장형의 정밀도를 늘리지 않는다.

### 세 형의 관계

**[C 표준]** `float`가 표현할 수 있는 값의 집합은 `double`의 부분집합이고, `double`의 집합은 `long double`의 부분집합이다. 세 형은 서로 다른 자료형이지만 표현 능력이 반드시 엄격하게 커져야 하는 것은 아니다. `long double`이 `double`과 같은 표현 능력을 가질 수도 있다.

C의 최소 요구 사항은 `float`에 적어도 6자리, `double`과 `long double`에 적어도 10자리의 십진 정밀도를 요구한다. 이 숫자는 모든 십진 소수를 정확히 저장한다는 뜻이 아니라 표준이 정의하는 십진수 변환 정밀도의 하한이다. 세 형 모두 적어도 `1e-37`부터 `1e+37`에 해당하는 규모를 다룰 수 있는 범위를 요구하지만, 그 사이 모든 실수가 표현되는 것은 아니다. 실제 한계와 정밀도의 정량적 확인은 2-8에서 `<float.h>`로 한다.

**[흔한 IEEE 754 구현]** `float`가 binary32, `double`이 binary64인 환경에서는 유효 이진 자릿수가 각각 24, 53이다. 흔히 이를 십진 유효 숫자 약 7자리, 약 16자리라고 요약하지만, 이 요약은 C의 최소 보장도, 모든 값에서 정확히 보존되는 십진 자릿수도 아니다. `long double`은 같은 binary64, 확장 정밀도 형식, binary128 등 구현에 따라 다르다.

C17의 기본 규칙은 모든 구현에 IEEE 754, 2진 기수, 무한대 또는 NaN 지원을 강제하지 않는다. IEC 60559 부동소수점 규약을 따르는 구현을 위한 Annex F와 기본 C의 요구 사항을 혼동하지 않는다.

### 먼저 선택할 형

일반적인 소수 계산을 시작할 때는 `double`을 기본 선택으로 삼는 편이 단순하다. `float`는 저장 용량이나 외부 인터페이스 요구가 있을 때, `long double`은 대상 환경에서 실제 이득을 확인했을 때 선택한다. 어느 형도 일반적인 금액의 십진 소수를 자동으로 정확하게 만드는 형은 아니다.

## 4. 문법

| 선언 또는 상수 | 의미 |
|---|---|
| `float ratio = 0.5f;` | `float` 상수로 `float` 변수 초기화 |
| `double ratio = 0.5;` | 접미사 없는 실수 상수는 `double` |
| `long double ratio = 0.5L;` | `long double` 상수로 초기화 |
| `1.25e2` | `1.25 × 10²`, 즉 125를 나타내는 `double` 상수 |
| `1.25e-2f` | `0.0125`를 나타내는 `float` 상수 |

`f`와 `F`, `l`과 `L`은 각각 같은 역할이다. 숫자 `1`과 구별하기 쉽도록 `L`을 권한다. `2`는 정수 상수이고 `2.0`, `2e0`은 `double` 상수다. `float x = 0.1;`도 유효하지만, 오른쪽은 먼저 `double` 상수이고 초기화 때 `float`로 변환된다. 변수의 형이 상수의 형을 거꾸로 바꾸지는 않는다.

| `printf` 인수 | 사용할 서식 | 이유 |
|---|---|---|
| `float` | `%f`, `%.2f` | 가변 인수로 전달될 때 `double`로 승격된다. |
| `double` | `%f`, `%.2f` | `%f`가 요구하는 인수형이 `double`이다. |
| `long double` | `%Lf`, `%.2Lf` | 대문자 `L`이 `long double` 인수를 지정한다. |

`%f`는 기본적으로 소수점 아래 6자리를 표시한다. `.2`는 소수점 아래 2자리로 반올림하여 표시하라는 뜻이지 변수를 변경하라는 뜻이 아니다. `printf`의 `%lf`도 C17에서는 `%f`와 같은 효과지만 이 자료는 `%f`로 통일한다. 이 규칙을 `scanf` 입력에 옮기면 안 된다. 입력 서식은 Part 5에서 별도로 배운다.

## 5. 최소 코드 예제

`floating_types.c`에 저장한다.

```c
#include <stdio.h>

int main(void)
{
    float small = 1.25f;
    double ordinary = 1.25;
    long double extended = 1.25L;

    printf("float: %.2f\n", small);
    printf("double: %.2f\n", ordinary);
    printf("long double: %.2Lf\n", extended);
    return 0;
}
```

**[GCC/Linux 구현]** 파일이 있는 디렉터리에서 다음 명령으로 빌드하고 실행한다. `&&`는 빌드에 성공한 경우에만 실행하는 셸 문법이다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic floating_types.c -o floating_types && ./floating_types
printf 'status=%s\n' "$?"
```

정상 출력 환경에서 기대하는 출력은 다음과 같다. 같은 출력이 나와도 세 자료형의 모든 성질이 같다는 증거는 아니다.

```text
float: 1.25
double: 1.25
long double: 1.25
```

## 6. 코드 해석

| 구성 | 해석 |
|---|---|
| `#include <stdio.h>` | `printf` 선언을 제공한다. |
| `int main(void)` | 인수를 받지 않는 호스트 프로그램의 시작 함수다. |
| `float small = 1.25f;` | 변수형과 상수형을 모두 `float`로 지정한다. |
| `double ordinary = 1.25;` | 접미사 없는 상수를 사용한다. |
| `long double extended = 1.25L;` | 두 단어가 하나의 자료형 이름을 이룬다. |
| 첫 번째 `printf` | `small`의 값을 `double`로 승격하여 전달한다. 변수 자체는 여전히 `float`다. |
| 두 번째 `printf` | `double` 값을 `%f` 계열 서식으로 출력한다. |
| 세 번째 `printf` | `long double` 값에 `%Lf` 계열 서식을 맞춘다. |
| `return 0;` | 호스트 환경에 성공 종료를 알린다. |

## 7. 내부 동작

1. **[C 표준·번역]** 컴파일러는 상수 표기와 접미사로 상수의 형을 정한다. 십진 부동소수점 상수를 내부 값으로 바꾸는 과정도 표현 한계의 영향을 받는다. C17 기본 규칙만으로 모든 변환이 특정 IEEE 반올림 모드를 따른다고 단정하지 않는다.
2. **[C 표준·저장]** 선언된 형에 맞는 값을 변수에 저장한다. 더 정밀한 형으로 나중에 옮겨도 이전 저장에서 잃은 정보가 복구되지는 않는다. 계산 중의 중간값은 구현에 따라 자료형보다 넓은 범위·정밀도로 평가될 수 있으므로 저장형과 중간 계산을 구별한다.
3. **[흔한 2진 구현·메모리]** `0.1`의 2진 전개는 끝나지 않는다. 유한한 이진 유효 자릿수에는 이를 근사해서 저장한다. 십진 기수를 쓰는 구현에는 이 관찰을 그대로 적용할 수 없다.
4. **[구현·ABI·CPU]** 형식과 호출 규약에 따라 레지스터나 메모리로 값을 전달한다. `long double`이 하드웨어 확장 형식일 수도, 라이브러리 연산 대상일 수도 있다. 저장 공간에 패딩이 있을 수도 있어 크기만으로 정밀도를 알 수 없다. 소스에 변수가 있다고 반드시 독립된 메모리 접근 명령이 생기는 것도 아니다.
5. **[라이브러리·OS]** `printf`는 전달된 값을 십진 문자로 변환해 stdout에 쓴다. OS와 터미널은 그 문자를 보여 주는 환경이지 C 실수형의 정밀도를 결정하는 규칙 자체가 아니다.

## 8. 자주 하는 실수

- **`float`는 항상 4바이트라고 외운다.** 흔한 구현의 선택이다. 크기는 2-6에서 측정하고 한 C byte의 비트 수도 따로 확인한다.
- **`long double`이면 반드시 더 정확하다고 생각한다.** `double`과 표현 능력이 같을 수 있다.
- **`%.20f`를 쓰면 정밀도가 20자리로 늘어난다고 생각한다.** 더 많은 문자를 볼 뿐 저장 정보는 늘지 않는다.
- **`float` 인수에 `%Lf`를 쓴다.** 전달되는 형은 `double`이다. 기대형 불일치는 정의되지 않은 동작이므로 잘못된 예제를 실행해 결과를 비교하지 않는다.
- **`long double x = 0.1;`에서 상수까지 `long double`이라고 생각한다.** 상수는 `double`이며 `0.1L`과 다른 변환 경로다.
- **`0.1`이 근사되니 모든 소수가 부정확하다고 말한다.** 흔한 2진 형식에서도 `0.5`, `1.25`처럼 정확히 표현 가능한 값이 있다.
- **범위를 넘으면 반드시 무한대가 나온다고 생각한다.** 기본 C17만으로 그러한 결과를 보장할 수 없다. 범위 밖 값과 연산은 이 실습에서 만들지 않는다.

2. 거짓이다. 기본 C17은 해당 IEEE 형식을 강제하지 않으며 `long double`과 `double`의 표현 능력이 같을 수도 있다.
3. `1.250`으로 보인다. 출력 소수 자릿수만 바뀌며 `ordinary`는 계속 `double`이다.
4. `%Lf`로 바꾼다. `%f`는 `double`을 기대하지만 전달한 값은 `long double`이다. 잘못된 서식은 정의되지 않은 동작이다.
5. 아니다. `float`에 저장하면서 이미 잃은 정보는 가변 인수 승격으로 되살아나지 않는다.
6. 안 된다. 흔한 2진 구현에서 근사를 관찰한 것이며 기수, 정밀도, 변환 규칙에 따라 결과가 달라질 수 있다. 표시 자릿수도 저장 정밀도와 별개다.

</details>

## 12. 핵심 정리

- 접미사 없음은 `double`, `f`는 `float`, `L`은 `long double` 실수 상수를 만든다.
- C가 요구하는 표현 능력의 포함 관계는 엄격한 정밀도 증가나 고정 크기를 뜻하지 않는다.
- 범위, 저장 정밀도, 화면의 소수 자릿수는 서로 다르다.
- `printf`에서 `float`·`double`은 `%f`, `long double`은 `%Lf`를 쓴다.
- IEEE 754의 흔한 형식과 C17의 최소 요구 사항을 분리한다.
