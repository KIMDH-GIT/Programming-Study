# 2-2. `char`, `short`, `int`

기준은 C17의 호스트 환경이다. 세 정수형의 역할을 익히고, C 표준의 최소 요구와 특정 컴퓨터에서 관찰한 크기를 구분한다.

## 1. 학습 목표

- `char`, `short`, `int` 객체를 선언·초기화하고 값을 출력한다.
- `char`도 정수형이며 문자 표현에도 사용된다는 점을 설명한다.
- `short`와 `int`의 부호 기본값을 plain `char`의 부호와 구별한다.
- 최소 표현 범위와 실제 구현의 범위를 구별한다.
- “작은 자료형이면 무조건 빠르다”와 “64비트 컴퓨터의 `int`는 64비트다”라는 단정을 피한다.

## 2. 선수 지식

[2-1. 변수 선언·초기화와 이름 규칙](2-1-variable-declaration-initialization-identifiers.md)의 선언·초기화·대입·값 복사를 사용한다. 식별자는 이름이고, 객체는 값을 나타내는 저장 영역이며, 자료형은 표현 가능한 값과 연산 규칙을 정한다. `int count = 3;`은 객체의 선언·정의와 초기화이고, 이후 `count = 4;`는 대입이다.

`<stdio.h>`, `int main(void)`, `printf`, `\n`, `return 0;`을 사용한다. Linux 셸에서 GCC로 빌드한다. 입력이나 조건 분기, 반복은 필요 없다.

## 3. 핵심 개념

### 세 가지 기본 정수형

| 표기 | 의미와 용도 | 주의점 |
|---|---|---|
| `char` | 작은 정수와 기본 실행 문자 집합의 문자 표현 | plain `char`의 부호는 구현 정의 |
| `short` | `short int`와 같은 부호 있는 정수형 | 반드시 `int`보다 작지는 않음 |
| `int` | 일반적인 정수 계산에 사용하는 기본 부호 있는 정수형 | 반드시 32비트인 것은 아님 |

`short`, `short int`, `signed short`, `signed short int`는 같은 자료형을 지정한다. `int`, `signed`, `signed int`도 같은 자료형을 지정한다. 이름이나 사용 목적이 아니라 **선언한 자료형**이 값의 범위를 결정한다.

### plain `char`는 별도로 생각한다

**[C 표준]** `char`, `signed char`, `unsigned char`는 서로 다른 세 자료형이다. plain `char`는 구현이 정한 대로 `signed char` 또는 `unsigned char`와 같은 범위·표현·동작을 가진다. 어느 쪽인지는 **구현 정의**이므로 구현이 문서화해야 한다. 매 실행마다 임의로 선택하는 미지정 결과라는 뜻이 아니다.

따라서 `short`와 `int`는 부호를 생략해도 signed이지만, `char`까지 항상 signed라고 일반화하면 안 된다. 이번에는 plain `char`에 기본 문자 `'A'`나 7처럼 안전한 값을 넣고, 음수 저장이 필요하면 plain `char`에 의존하지 않는다. signed·unsigned의 본격적인 비교는 2-4에서 다룬다.

### C 표준의 최소 요구와 실제 크기

다음은 **[C17 표준의 최소 보장]**이다. “최소”는 해당 범위를 전부 표현할 수 있어야 한다는 뜻이지, 그 밖의 값을 표현할 수 없다는 뜻이 아니다.

| 자료형 | 반드시 표현 가능한 범위 | 저장 크기 관련 보장 |
|---|---|---|
| `signed char` | -127부터 127까지 | C의 1 byte |
| `unsigned char` | 0부터 255까지 | C의 1 byte |
| plain `char` | 적어도 0부터 127까지; 나머지는 구현의 부호 선택에 따름 | C의 1 byte |
| `short` | -32767부터 32767까지 | `char`보다 작지 않고 `int`보다 크지 않음 |
| `int` | -32767부터 32767까지 | `short`보다 작지 않음 |

C의 byte는 문자형 객체를 저장할 수 있는 주소 지정 가능한 저장 단위다. **항상 8비트라는 뜻은 아니다.** 한 byte의 비트 수인 `CHAR_BIT`는 최소 8이며 `<limits.h>`에서 제공한다. `sizeof`는 C byte 단위의 크기를 구하는 연산자로, 표준은 `sizeof(char) == 1`과 `sizeof(char) <= sizeof(short) <= sizeof(int)`를 보장한다. 실제 사용법은 2-6에서 배운다.

**[흔한 구현 예시, 표준 보장 아님]** 8비트 byte 환경에서 `char` 1 byte, `short` 2 byte, `int` 4 byte인 경우가 많다. 흔한 16비트 2의 보수 `short` 범위는 -32768부터 32767까지이고, 흔한 32비트 2의 보수 `int` 범위는 -2147483648부터 2147483647까지다. C17의 표만 보고 최소값을 -32768로 고정하면 안 된다. C17은 모든 signed 정수형이 2의 보수 표현일 것을 요구하지 않는다.

`short`와 `int`의 크기가 같아도 표준 위반이 아니다. 같은 크기여도 서로 다른 자료형이다. CPU가 64비트라는 사실만으로 `int`가 8 byte라는 결론을 낼 수 없다. 대상 ABI, 컴파일러와 옵션이 구현의 구체적인 선택에 관련된다.

## 4. 문법

함수 본문의 구문 조각이다.

```c
char grade = 'A';
short seats = 120;
int population = 30000;
```

- 작은따옴표의 `'A'`는 정수 문자 상수이며 C에서 자료형은 `int`다. 초기화할 때 `char` 값으로 변환된다.
- 큰따옴표의 `"A"`는 문자열 리터럴이다. `'A'`와 서로 바꿔 쓰지 않는다. 문자열의 자세한 구조는 Part 13에서 다룬다.
- `char`는 임의의 한글 글자 하나를 항상 저장하는 자료형이 아니다. UTF-8 같은 인코딩에서 한글 글자는 여러 byte가 필요할 수 있다.
- 문자 `'A'`의 수치가 65라는 것은 ASCII 계열의 사실이다. C 표준은 ASCII 자체를 의무화하지 않는다.

이번 출력에 필요한 규칙은 다음과 같다.

| 출력 대상 | 사용 방법 | 이유 |
|---|---|---|
| `int` | `%d` | 부호 있는 `int`를 10진수로 출력 |
| `short` | `%d` | `printf`에 전달할 때 정수 승격으로 `int`가 됨 |
| 예제의 `char` 문자 | `%c`와 `(int)grade` | `%c`가 받는 `int`를 명시적으로 준비 |

정수 승격은 작은 정수형의 값을 함수 인수 등에서 `int` 또는 `unsigned int`로 바꾸는 규칙이다. `short`의 모든 값은 `int`로 표현할 수 있어 여기서는 `int`로 승격한다. 원래 `short` 객체의 자료형이나 저장 크기가 바뀌는 것은 아니다.

plain `char`의 모든 값이 `int`에 들어가지 않는 구현에서는 `unsigned int`로 승격할 수 있다. 그래서 예제는 `(int)grade`로 전달할 값의 형식을 명시한다. `(int)`는 값을 `int`로 변환하는 캐스트 문법의 최소 예고다. 예제의 기본 문자 `'A'` 값은 `int`로 표현 가능하므로 안전하다. 이 표기를 임의의 큰 정수까지 안전하게 바꾸는 도구로 일반화하지 않는다. 자세한 변환은 Part 6에서 배운다.

## 5. 최소 코드 예제

`basic-integers.c`에 저장한다. 숫자는 위 최소 보장 범위 안에서 선택했다.

```c
#include <stdio.h>

int main(void)
{
    char grade = 'A';
    short seats = 120;
    int population = 30000;

    printf("grade=%c\n", (int)grade);
    printf("seats=%d\n", seats);
    printf("population=%d\n", population);
    seats = 100;
    printf("seats=%d\n", seats);
    return 0;
}
```

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic basic-integers.c -o basic-integers && ./basic-integers
```

정상 표준 출력 환경에서 예상 결과는 다음과 같다. 메모리 크기나 문자 코드의 숫자를 가정하지 않은 출력이다.

```text
grade=A
seats=120
population=30000
seats=100
```

## 6. 코드 해석

| 코드 | 의미 |
|---|---|
| `char grade = 'A';` | `grade`라는 이름의 `char` 객체를 기본 문자 값으로 초기화한다. |
| `short seats = 120;` | 부호 있는 `short` 객체를 120으로 초기화한다. |
| `int population = 30000;` | `int`의 최소 보장 범위 안에 있는 값을 저장한다. |
| `%c`, `(int)grade` | 준비한 `int` 값을 문자로 출력한다. |
| `%d`, `seats` | `short` 값을 `int`로 승격해 10진수로 출력한다. |
| `seats = 100;` | 기존 객체의 값만 바꾸며 `short` 자료형은 유지한다. |
| `return 0;` | 초기 `main` 호출의 정상 종료를 나타낸다. |

선언은 객체와 자료형의 관계를 정하고 초기화는 처음 값을 정한다. 대입은 기존 객체에 값을 저장하며 저장 공간을 늘리지 않는다. `population`이라는 이름을 써도 무제한 크기의 인구를 담을 수는 없다.

## 7. 내부 동작

1. **[C 표준·컴파일러]** 컴파일러는 선언된 자료형에 따라 상수의 변환, 대입과 출력 인수의 형식을 해석한다. 초기화 값이 대상 범위에 들어가는지 고려해야 한다.
2. **[C 표준·메모리]** 객체의 값과 그 값을 나타내는 저장 비트는 같은 개념이 아니다. C17의 표현 규칙과 구현의 선택에 따라 크기·범위가 정해진다. 이번에는 범위 밖 변환이나 overflow를 실행하지 않는다.
3. **[C 표준·출력]** `short` 인수는 `int`로 승격된다. 출력 함수에 전달되는 값의 형식과 원래 객체의 자료형을 구별한다.
4. **[구현·CPU]** 컴파일러는 대상 CPU의 명령과 레지스터를 활용한다. `short`라고 반드시 더 빠른 명령 하나로 처리되는 것은 아니다. 확장이나 변환이 필요할 수 있어 속도는 측정 없이 단정할 수 없다.
5. **[구현·OS/저장]** OS는 실행 환경과 메모리를 관리하지만 실행할 때마다 각 변수의 C 자료형을 결정하지 않는다. 지역 객체는 스택이나 레지스터에 대응할 수 있고 최적화로 별도 저장이 사라질 수도 있다. 모든 변수가 스택이라는 규칙은 없다.

## 8. 자주 하는 실수

- `char`는 문자만 저장할 수 있다고 생각한다. 정수형이며 문자 표현은 그 사용법 중 하나다.
- `char`와 `signed char`가 같은 자료형이라고 생각한다. 범위가 같아도 별개의 자료형이다.
- `short`는 항상 2 byte, `int`는 항상 4 byte라고 적는다. 구현 예시와 표준 보장을 분리한다.
- 1 byte를 항상 8비트라고 정의한다. C에서는 `CHAR_BIT`를 확인해야 한다.
- `short`의 최소 보장 범위에 -32768을 넣는다. C17의 최소 보장은 -32767부터다.
- 40000을 아무 `short`에 넣어도 된다고 생각한다. 최소 보장만으로는 표현할 수 없다. 범위 밖 변환의 결과를 이 Step에서 실험하지 않는다.
- `%d`로 출력하면 객체가 영구적으로 `int`가 된다고 생각한다. 인수 값의 승격과 원래 객체를 구분한다.
- `char`에 `'A'` 대신 `"A"`를 넣는다. 문자 상수와 문자열 리터럴은 다른 종류다.

- ★★★ **구현 문서 읽기:** 참고 자료의 GCC 정수 구현 문서에서 plain `char` 부호가 대상 ABI에 따라 정해지는 내용을 찾는다. “표준 보장”과 “내 대상의 선택”을 구분해 기록한다. 내 대상의 결론을 확인하지 못했다면 미확인으로 남기며 출력만으로 크기를 추측하지 않는다.

## 11. 확인 문제

1. **참/거짓:** `short`와 `short int`는 서로 다른 자료형이다.
2. **선택:** 모든 C17 구현에서 `int`로 표현 가능하다고 보장되는 값은 30000과 100000 중 무엇인가?
3. **빈칸:** C에서 `sizeof(char)`는 항상 ___이고, 한 byte의 비트 수는 최소 ___이다.
4. **출력 예측:** `short saved = 12; int copied = saved; saved = 7;` 뒤 `saved`와 `copied`를 `%d`로 출력하면 각각 무엇인가? `saved`의 자료형도 쓰라.
5. **오류 설명:** “부호를 생략했으므로 `char`는 반드시 signed다”를 고쳐 쓰라.
6. **서술:** `'A'`를 문자로 출력한 결과가 A였다는 사실만으로 그 수치가 65이고 `int`가 4 byte라고 결론 내릴 수 있는가?

<details>
<summary>정답과 해설</summary>

1. 거짓이다. 같은 부호 있는 정수형의 두 표기다.
2. 30000이다. `int`는 적어도 -32767부터 32767까지 표현한다. 100000을 표현하는 구현은 많지만 모든 구현에 대한 보장은 아니다.
3. 1, 8이다. `sizeof`의 단위는 C byte이며 실제 비트 수는 `CHAR_BIT`다.
4. 7과 12다. `saved` 객체는 여전히 `short`이며 출력에 전달되는 값은 `int`로 승격된다. `copied`는 별개의 객체다.
5. plain `char`의 부호는 구현 정의다. `short`와 `int`의 부호 생략 규칙을 그대로 적용할 수 없다. `char`, `signed char`, `unsigned char`는 별개의 자료형이다.
6. 아니다. 문자 코드와 정수형의 저장 크기는 별도 사실이다. ASCII의 65나 흔한 `int` 크기를 C 표준의 필수 조건으로 볼 수 없다.

</details>

## 12. 핵심 정리

`char`, `short`, `int`는 정수형이다. `short`와 `int`는 부호를 생략하면 signed이지만 plain `char`의 부호는 구현 정의다. C17은 최소 범위와 크기의 순서를 정하며 모든 구현의 byte 비트 수나 `int` 크기를 고정하지 않는다. 값의 대입과 출력 시 승격은 객체의 선언된 자료형을 바꾸지 않는다.

## 13. 다음 Step

다음은 **2-3. `long`, `long long`**이다. 더 큰 정수형의 최소 범위와 표기법을 배운다. `sizeof` 측정은 2-6, `<limits.h>`의 실제 범위 확인은 2-7, 구현별 종합 관찰은 2-9에서 다룬다.
