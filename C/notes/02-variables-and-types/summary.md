# 2-1. 변수 선언·초기화와 이름 규칙

기준은 C17의 호스트 환경이다. 이번 Step은 정수 값을 이름으로 다루는 첫 단계다. 이름, 객체, 값, 저장 공간을 구분하고 선언·초기화·대입을 직접 관찰한다.


## 핵심 개념

### 이름은 객체도 값도 아니다

`int score = 10;`을 `main` 본문에 쓴 상황을 기준으로 읽는다.

| 용어 | 의미 | 예제에서의 역할 |
|---|---|---|
| 식별자(identifier) | 소스에서 대상을 식별하는 이름 | `score` |
| 객체(object) | C 추상 기계에서 값을 나타낼 수 있는 데이터 저장 영역 | `score`로 지칭하는 정수 객체 |
| 자료형(type) | 표현 가능한 값과 허용되는 연산·해석을 정하는 분류 | `int` |
| 값(value) | 객체가 현재 나타내는 데이터 | 초기에는 정수 10 |
| 저장 공간(storage) | 객체의 표현을 담는 공간 | 크기·정렬·수명 등이 관련되며 이름 자체와 다름 |
| 선언(declaration) | 식별자의 의미와 자료형 같은 속성을 알리는 구문 | `int score = 10;` 전체 |
| 정의(definition) | 객체의 경우 그 객체의 저장 공간을 마련하는 선언 | 이 블록의 `score` 선언은 정의이기도 함 |
| 초기화(initialization) | 객체의 처음 값을 지정하는 일 | 선언의 `= 10` |
| 대입(assignment) | 이미 있는 수정 가능한 객체에 값을 저장하는 연산 | 이후의 `score = 20;` |

이 Step에서 **변수**는 이름으로 사용하는, 값을 바꿀 수 있는 객체를 뜻한다. 모든 식별자가 변수 이름인 것은 아니다. `main`과 `printf`도 식별자지만 여기서는 함수 이름이다. 객체에 언제나 소스상의 이름이 있어야 하는 것도 아니다. 이름 없는 객체는 뒤에서 다룬다.

**[C 표준]** 선언이 모두 객체 정의인 것은 아니다. 예를 들어 함수 선언은 정수 객체를 만드는 선언이 아니다. 지금 작성하는 `main` 내부의 `int score;`와 `int score = 10;`은 모두 객체의 선언이자 정의다. 선언과 정의의 전체 구분은 여러 파일을 다루는 Part 24에서 확장한다.

### 초기화와 대입은 같은 기호를 써도 다르다

- `int score = 10;`: 새 객체의 선언·정의와 초기화다.
- `score = 20;`: 기존 객체에 20을 저장하는 대입식 문장이다. 새 객체를 만들거나 자료형을 바꾸지 않는다.
- `printf("%d\n", score);`: 객체의 현재 값을 읽어 출력에 사용한다. 이름 자체를 출력하는 것이 아니다.

`%d`는 `int` 값을 부호 있는 10진수로 출력하는 변환 지정자다. 서식 문자열 다음에 출력할 값을 인수로 전달한다. `printf("score\n");`는 글자 `score`만 출력한다. 이번에는 `%d` 하나에 `int` 인수 하나를 정확히 대응시킨다.

### 값이 정해지기 전에 읽지 않는다

**[C 표준]** 여기서 사용하는 초기화 없는 자동 저장 기간의 지역 객체 `int score;`는 값이 0으로 정해지지 않는다. 값은 불확정(indeterminate) 상태다. 그 값을 출력해서 확인하는 것은 안전한 실험이 아니며 정의되지 않은 동작으로 이어질 수 있다. 일정한 쓰레기값이나 무작위 숫자가 나온다는 보장도 없다.

`int score;` 뒤에 값을 읽지 않고 `score = 10;`부터 실행하는 것은 가능하다. 이때 처음 저장한 값이라도 문법상 **대입**이지 선언의 **초기화**가 아니다. 처음부터 값을 알면 선언과 함께 초기화하는 습관을 권한다. 다른 저장 기간의 객체에 적용되는 기본 초기화 규칙을 모든 지역 변수에 일반화하지 않는다.

## 문법

다음은 함수 본문에 놓는 구문 조각이다.

```c
int score = 10;
score = 20;
int count;
count = 3;
```

`int`는 자료형 키워드, `score`와 `count`는 식별자, `10`, `20`, `3`은 정수 상수다. 각각의 선언과 문장 끝에 세미콜론을 쓴다. 이 자료에서는 가독성을 위해 한 선언에 변수 하나를 쓴다.

### 식별자 규칙과 이름 선택

초보 단계에서는 영문자, 숫자, 밑줄만 사용한다.

- 첫 글자는 영문자 또는 밑줄이어야 하고 숫자로 시작할 수 없다.
- 뒤에는 영문자, 숫자, 밑줄을 쓸 수 있다. 공백과 `-`는 이름에 넣지 않는다.
- 대소문자를 구분한다. `score`와 `Score`는 다른 이름이다.
- `int`, `return` 같은 키워드는 변수 이름으로 사용할 수 없다.
- 같은 블록에서 같은 이름의 지역 객체를 다시 정의하지 않는다. 값을 바꿀 때는 자료형을 반복하지 말고 대입한다.
- 선언한 이름은 그 이름이 보이는 범위에서 사용한다. 이번에는 모두 `main`의 같은 블록에서 선언 뒤에 사용한다.

**[C 표준]** 실제 식별자 문법에는 일부 비ASCII 문자 지원도 있지만 허용 범위와 이식성을 고려해 이 Step의 이름은 ASCII로 제한한다. 밑줄로 시작한다고 모두 자유롭게 쓸 수 있는 것은 아니다. `__`로 시작하거나 밑줄 다음이 대문자인 이름은 모든 용도로 예약되며, 나머지 밑줄 시작 이름도 파일 범위 등에서 예약 규칙이 있다. 이번에는 **밑줄로 시작하는 이름을 아예 선택하지 않는다.**

| 후보 | 판단 |
|---|---|
| `student_count`, `score2` | 사용할 수 있고 뜻도 표현할 수 있음 |
| `2score` | 숫자로 시작하므로 불가 |
| `student-count` | 하나의 식별자가 아님 |
| `return` | 키워드이므로 불가 |
| `__score`, `_Score` | 문법 모양과 별개로 구현에 예약된 이름 |
| `printf` | 표준 라이브러리 이름과 충돌하므로 사용자 변수 이름으로 피함 |

이름에 단위를 담는 `elapsed_seconds`는 `x`보다 의미를 전달하기 쉽다. 이름의 의미가 자료형의 범위를 늘려 주지는 않는다.









# 2-2. `char`, `short`, `int`

기준은 C17의 호스트 환경이다. 세 정수형의 역할을 익히고, C 표준의 최소 요구와 특정 컴퓨터에서 관찰한 크기를 구분한다.

## 핵심 개념

### 세 가지 기본 정수형

| 표기 | 의미와 용도 | 주의점 |
|---|---|---|
| `char` | 작은 정수와 기본 실행 문자 집합의 문자 표현 | plain `char`의 부호는 구현 정의 |
| `short` | `short int`와 같은 부호 있는 정수형 | 반드시 `int`보다 작지는 않음 |
| `int` | 일반적인 정수 계산에 사용하는 기본 부호 있는 정수형 | 반드시 32비트인 것은 아님 |

`short`, `short int`, `signed short`, `signed short int`는 같은 자료형을 지정한다. `int`, `signed`, `signed int`도 같은 자료형을 지정한다. 이름이나 사용 목적이 아니라 **선언한 자료형**이 값의 범위를 결정한다.

### plain `char`는 별도로 생각한다

**[C 표준]** `char`, `signed char`, `unsigned char`는 서로 다른 세 자료형이다. plain `char`는 구현이 정한 대로 `signed char` 또는 `unsigned char`와 같은 범위·표현·동작을 가진다. 어느 쪽인지는 **구현 정의**이므로 구현이 문서화해야 한다. 매 실행마다 임의로 선택하는 미지정 결과라는 뜻이 아니다.

따라서 `short`와 `int`는 부호를 생략해도 signed이지만, `char`까지 항상 signed라고 일반화하면 안 된다. 이번에는 plain `char`에 기본 문자 `'A'`나 7처럼 안전한 값을 넣고, 음수 저장이 필요하면 plain `char`에 의존하지 않는다. signed·unsigned의 본격적인 비교는 2-4에서 다룬다.

### C 표준의 최소 요구와 실제 크기

다음은 **[C17 표준의 최소 보장]**이다. “최소”는 해당 범위를 전부 표현할 수 있어야 한다는 뜻이지, 그 밖의 값을 표현할 수 없다는 뜻이 아니다.

| 자료형 | 반드시 표현 가능한 범위 | 저장 크기 관련 보장 |
|---|---|---|
| `signed char` | -127부터 127까지 | C의 1 byte |
| `unsigned char` | 0부터 255까지 | C의 1 byte |
| plain `char` | 적어도 0부터 127까지; 나머지는 구현의 부호 선택에 따름 | C의 1 byte |
| `short` | -32767부터 32767까지 | `char`보다 작지 않고 `int`보다 크지 않음 |
| `int` | -32767부터 32767까지 | `short`보다 작지 않음 |

C의 byte는 문자형 객체를 저장할 수 있는 주소 지정 가능한 저장 단위다. **항상 8비트라는 뜻은 아니다.** 한 byte의 비트 수인 `CHAR_BIT`는 최소 8이며 `<limits.h>`에서 제공한다. `sizeof`는 C byte 단위의 크기를 구하는 연산자로, 표준은 `sizeof(char) == 1`과 `sizeof(char) <= sizeof(short) <= sizeof(int)`를 보장한다. 실제 사용법은 2-6에서 배운다.

**[흔한 구현 예시, 표준 보장 아님]** 8비트 byte 환경에서 `char` 1 byte, `short` 2 byte, `int` 4 byte인 경우가 많다. 흔한 16비트 2의 보수 `short` 범위는 -32768부터 32767까지이고, 흔한 32비트 2의 보수 `int` 범위는 -2147483648부터 2147483647까지다. C17의 표만 보고 최소값을 -32768로 고정하면 안 된다. C17은 모든 signed 정수형이 2의 보수 표현일 것을 요구하지 않는다.

`short`와 `int`의 크기가 같아도 표준 위반이 아니다. 같은 크기여도 서로 다른 자료형이다. CPU가 64비트라는 사실만으로 `int`가 8 byte라는 결론을 낼 수 없다. 대상 ABI, 컴파일러와 옵션이 구현의 구체적인 선택에 관련된다.

## 문법

함수 본문의 구문 조각이다.

```c
char grade = 'A';
short seats = 120;
int population = 30000;
```

- 작은따옴표의 `'A'`는 정수 문자 상수이며 C에서 자료형은 `int`다. 초기화할 때 `char` 값으로 변환된다.
- 큰따옴표의 `"A"`는 문자열 리터럴이다. `'A'`와 서로 바꿔 쓰지 않는다. 문자열의 자세한 구조는 Part 13에서 다룬다.
- `char`는 임의의 한글 글자 하나를 항상 저장하는 자료형이 아니다. UTF-8 같은 인코딩에서 한글 글자는 여러 byte가 필요할 수 있다.
- 문자 `'A'`의 수치가 65라는 것은 ASCII 계열의 사실이다. C 표준은 ASCII 자체를 의무화하지 않는다.

이번 출력에 필요한 규칙은 다음과 같다.

| 출력 대상 | 사용 방법 | 이유 |
|---|---|---|
| `int` | `%d` | 부호 있는 `int`를 10진수로 출력 |
| `short` | `%d` | `printf`에 전달할 때 정수 승격으로 `int`가 됨 |
| 예제의 `char` 문자 | `%c`와 `(int)grade` | `%c`가 받는 `int`를 명시적으로 준비 |

정수 승격은 작은 정수형의 값을 함수 인수 등에서 `int` 또는 `unsigned int`로 바꾸는 규칙이다. `short`의 모든 값은 `int`로 표현할 수 있어 여기서는 `int`로 승격한다. 원래 `short` 객체의 자료형이나 저장 크기가 바뀌는 것은 아니다.

plain `char`의 모든 값이 `int`에 들어가지 않는 구현에서는 `unsigned int`로 승격할 수 있다. 그래서 예제는 `(int)grade`로 전달할 값의 형식을 명시한다. `(int)`는 값을 `int`로 변환하는 캐스트 문법의 최소 예고다. 예제의 기본 문자 `'A'` 값은 `int`로 표현 가능하므로 안전하다. 이 표기를 임의의 큰 정수까지 안전하게 바꾸는 도구로 일반화하지 않는다. 자세한 변환은 Part 6에서 배운다.

## 최소 코드 예제

`basic-integers.c`에 저장한다. 숫자는 위 최소 보장 범위 안에서 선택했다.

```c
#include <stdio.h>

int main(void)
{
    char grade = 'A';
    short seats = 120;
    int population = 30000;

    printf("grade=%c\n", (int)grade);
    printf("seats=%d\n", seats);
    printf("population=%d\n", population);
    seats = 100;
    printf("seats=%d\n", seats);
    return 0;
}
```

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic basic-integers.c -o basic-integers && ./basic-integers
```

정상 표준 출력 환경에서 예상 결과는 다음과 같다. 메모리 크기나 문자 코드의 숫자를 가정하지 않은 출력이다.

```text
grade=A
seats=120
population=30000
seats=100
```

## 코드 해석

| 코드 | 의미 |
|---|---|
| `char grade = 'A';` | `grade`라는 이름의 `char` 객체를 기본 문자 값으로 초기화한다. |
| `short seats = 120;` | 부호 있는 `short` 객체를 120으로 초기화한다. |
| `int population = 30000;` | `int`의 최소 보장 범위 안에 있는 값을 저장한다. |
| `%c`, `(int)grade` | 준비한 `int` 값을 문자로 출력한다. |
| `%d`, `seats` | `short` 값을 `int`로 승격해 10진수로 출력한다. |
| `seats = 100;` | 기존 객체의 값만 바꾸며 `short` 자료형은 유지한다. |
| `return 0;` | 초기 `main` 호출의 정상 종료를 나타낸다. |

선언은 객체와 자료형의 관계를 정하고 초기화는 처음 값을 정한다. 대입은 기존 객체에 값을 저장하며 저장 공간을 늘리지 않는다. `population`이라는 이름을 써도 무제한 크기의 인구를 담을 수는 없다.


## 자주 하는 실수

- `char`는 문자만 저장할 수 있다고 생각한다. 정수형이며 문자 표현은 그 사용법 중 하나다.
- `char`와 `signed char`가 같은 자료형이라고 생각한다. 범위가 같아도 별개의 자료형이다.
- `short`는 항상 2 byte, `int`는 항상 4 byte라고 적는다. 구현 예시와 표준 보장을 분리한다.
- 1 byte를 항상 8비트라고 정의한다. C에서는 `CHAR_BIT`를 확인해야 한다.
- `short`의 최소 보장 범위에 -32768을 넣는다. C17의 최소 보장은 -32767부터다.
- 40000을 아무 `short`에 넣어도 된다고 생각한다. 최소 보장만으로는 표현할 수 없다. 범위 밖 변환의 결과를 이 Step에서 실험하지 않는다.
- `%d`로 출력하면 객체가 영구적으로 `int`가 된다고 생각한다. 인수 값의 승격과 원래 객체를 구분한다.
- `char`에 `'A'` 대신 `"A"`를 넣는다. 문자 상수와 문자열 리터럴은 다른 종류다.



# 2-3. `long`, `long long`

기준은 C17 호스트 환경이다. 이번 Step은 큰 정수를 저장할 자료형을 고르는 연습이다. `long`이 항상 8바이트라는 가정 대신 **표준이 보장하는 범위**와 **현재 구현에서 관찰한 범위**를 구별한다.

## 핵심 개념

### 이름이 다르면 반드시 크기도 다른가?

**[C 표준]** `long`은 `long int`, `signed long int`와 같은 자료형이다. `long long`은 `long long int`, `signed long long int`와 같은 자료형이다. `unsigned`를 붙이지 않은 이 두 자료형은 음수, 0, 양수를 표현하는 부호 있는 정수형이다. `long`과 `long long`은 크기가 같아도 서로 다른 자료형이다.

표준 부호 있는 정수형은 앞의 자료형 이상으로 저장 공간을 제공한다. `sizeof`는 자료형이나 객체의 크기를 C 바이트 단위로 구하는 연산자이며, 지금은 다음 관계를 읽는 데만 사용한다.

```text
sizeof(char) = 1
sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)
```

`<=`는 작거나 같다는 뜻이다. `int`와 `long`, 또는 `long`과 `long long`의 크기가 같아도 적법하다. 대응하는 순서의 signed 정수형에서 작은 순위 자료형의 값 범위는 큰 순위 자료형 범위에 포함된다. 즉 `long long`은 `long`의 모든 값을 표현할 수 있다. 순위가 높다고 크기가 반드시 더 큰 것은 아니다.

### 최소 보장 범위와 실제 범위

**[C 표준]** 다음 구간의 모든 정수는 적어도 표현할 수 있어야 한다. 이 표의 양 끝이 모든 구현의 정확한 최솟값·최댓값이라는 뜻은 아니다.

| 자료형 | 적어도 표현 가능한 구간 | 실제 범위를 나타내는 `<limits.h>` 매크로 |
|---|---|---|
| `signed char` | -127 ~ 127 | `SCHAR_MIN`, `SCHAR_MAX` |
| `short` | -32767 ~ 32767 | `SHRT_MIN`, `SHRT_MAX` |
| `int` | -32767 ~ 32767 | `INT_MIN`, `INT_MAX` |
| `long` | -2147483647 ~ 2147483647 | `LONG_MIN`, `LONG_MAX` |
| `long long` | -9223372036854775807 ~ 9223372036854775807 | `LLONG_MIN`, `LLONG_MAX` |

C17은 signed 표현을 2의 보수 하나로 제한하지 않으므로 최소 보장 구간의 음수 끝을 임의로 한 칸 더 넓히지 않는다. 흔한 2의 보수 64비트 `long long`의 실제 범위는 -9223372036854775808 ~ 9223372036854775807이다. 정확한 한계는 매크로로 확인한다. `char` 자체의 부호 유무는 구현에 따라 달라 위 표에는 명시적인 `signed char`를 썼다.

**[구현 정의/ABI 의존]** 자료형별 정확한 크기, 정수 표현, 한계는 대상 구현이 정한다. C 바이트의 비트 수 `CHAR_BIT`는 적어도 8이지만 반드시 8은 아니다. 따라서 최소 범위를 곧바로 모든 환경의 `sizeof` 값으로 바꾸면 안 된다.

다음은 `CHAR_BIT == 8`인 대표적인 데이터 모델의 **예**다. 이 표는 C17의 의무 규정이 아니다.

| 대표 모델 | `int` 바이트 | `long` 바이트 | `long long` 바이트 | 흔한 대상 |
|---|---:|---:|---:|---|
| ILP32 | 4 | 4 | 8 | 여러 32비트 ABI |
| LP64 | 4 | 8 | 8 | 일반적인 64비트 Linux ABI |
| LLP64 | 4 | 4 | 8 | 64비트 Windows ABI |

64비트 CPU라는 사실만으로 `long`을 8바이트라고 결론 내릴 수 없다. 모델 이름의 다른 구성 요소까지 외울 필요는 없다.

## 문법

선언의 형태는 `자료형 이름 = 초기값;`이다.

| 선언 예 | 뜻 | 이 값의 출력 지정자 |
|---|---|---|
| `long distance = 2000000000L;` | `long` 변수와 `long` 정수 상수 | `%ld` |
| `long long population = 8000000000LL;` | `long long` 변수와 `long long` 정수 상수 | `%lld` |

`L`과 `LL`은 숫자에 붙는 정수 상수 접미사다. 글자 `l`은 숫자 `1`과 혼동하기 쉬워 대문자를 권한다. 값에 맞는 자료형으로 상수를 해석하도록 돕지만, 어떤 값이든 강제로 그 자료형에 들어가게 만들지는 않는다.

이 Step의 양의 **10진수** 상수에서 접미사가 없으면 `int`, `long`, `long long` 순으로 처음 표현 가능한 자료형을 고른다. `L`이면 `long`, `long long` 순으로 고르고 `LL`이면 `long long`을 사용한다. 여기서는 그 후보 범위에 들어가는 상수만 사용한다. `8000000000L`은 `long` 범위를 넘는 구현에서는 `long long`일 수 있으므로 접미사 `L`을 고정 크기 보증으로 읽으면 안 된다.

`printf("distance=%ld\n", distance);`에서 문자열 뒤의 `distance`가 출력할 값이다. `%ld`는 signed `long`, `%lld`는 signed `long long`에 대응한다. 크기가 같아도 `%d`로 대체하지 않는다. `%d`가 요구하는 것은 `int`다. 잘못된 인수 자료형으로 호출하면 정의되지 않은 동작이 될 수 있다.

## 최소 코드 예제

`wide_values.c`로 저장하여 실행할 수 있는 완전한 예제다.

```c
#include <stdio.h>

int main(void)
{
    long distance = 2000000000L;
    long long population = 8000000000LL;

    printf("distance=%ld\n", distance);
    printf("population=%lld\n", population);
    return 0;
}
```

정상적인 표준 출력 환경에서 예상 결과는 다음과 같다. 두 초기값 모두 해당 자료형의 C17 최소 보장 범위에 들어가므로 이 출력은 `long`의 크기가 4인지 8인지에 의존하지 않는다.

```text
distance=2000000000
population=8000000000
```

## 코드 해석

| 구성 | 해석 |
|---|---|
| `#include <stdio.h>` | `printf` 선언을 제공한다. |
| `int main(void)` | 호스트 환경에서 프로그램의 시작 함수다. |
| `long distance = 2000000000L;` | `long` 객체를 선언하고 20억으로 초기화한다. |
| `long long population = 8000000000LL;` | `long long` 객체를 선언하고 80억으로 초기화한다. |
| 첫 번째 `printf` | `distance` 값을 `%ld`로 10진수 출력한다. |
| 두 번째 `printf` | `population` 값을 `%lld`로 10진수 출력한다. |
| `return 0;` | 초기 `main` 호출을 성공 종료한다. |

20억은 표준이 `long`에 보장하지만 `int`에는 보장하지 않는 값이다. 80억은 `long long`에 보장하지만 `long`에는 보장하지 않는다. 이 차이가 자료형 선택의 이유다.



# 2-4. `signed`와 `unsigned`

기준은 C17 호스트 환경이다. 부호의 유무는 음수를 출력할 수 있는지뿐 아니라 값의 범위와 산술 규칙도 결정한다. 이번 Step에서는 단순 선언·초기화·출력과 덧셈·뺄셈만으로 그 차이를 확인한다.

## 핵심 개념

### 부호 있는 형과 없는 형

**[C 표준]** signed 정수형은 음수, 0, 양수를 표현한다. unsigned 정수형은 0과 양수를 표현한다. 대응하는 signed/unsigned 정수형은 같은 저장 공간과 정렬 요구를 갖지만 값의 범위는 다르다. `unsigned`는 저장 공간을 자동으로 늘리는 기능이 아니다.

| 표기 | 같은 자료형을 나타내는 표기 | 출력 지정자 |
|---|---|---|
| `int` | `signed`, `signed int` | `%d` |
| `unsigned int` | `unsigned` | `%u` |
| `long` | `signed long`, `signed long int` | `%ld` |
| `unsigned long` | `unsigned long int` | `%lu` |
| `long long` | `signed long long`, `signed long long int` | `%lld` |
| `unsigned long long` | `unsigned long long int` | `%llu` |

`short`도 `signed short`와 같은 형이다. 단, **plain `char`는 예외**다. `char`, `signed char`, `unsigned char`는 서로 다른 세 자료형이며, plain `char`의 범위·표현이 어느 쪽과 같은지는 구현 정의다. 이번 출력 실습은 정수 승격을 별도로 다룰 필요가 없는 `int` 이상을 사용한다.

### C17에서 보장하는 범위

다음은 최소 보장 구간이다. 실제 signed 최솟값·최댓값 및 unsigned 최댓값은 `<limits.h>`로 확인한다.

| 대응 형 | signed가 적어도 표현하는 구간 | unsigned가 적어도 표현하는 구간 |
|---|---|---|
| `signed char` / `unsigned char` | -127 ~ 127 | 0 ~ 255 |
| `short` / `unsigned short` | -32767 ~ 32767 | 0 ~ 65535 |
| `int` / `unsigned int` | -32767 ~ 32767 | 0 ~ 65535 |
| `long` / `unsigned long` | -2147483647 ~ 2147483647 | 0 ~ 4294967295 |
| `long long` / `unsigned long long` | -9223372036854775807 ~ 9223372036854775807 | 0 ~ 18446744073709551615 |

**[C 표준]** unsigned 정수형에 값 표현용 비트가 N개 있으면 정확한 범위는 0 ~ 2^N - 1이다. 여기서 `^`는 수학 표기의 거듭제곱이며 C 코드의 거듭제곱 연산자가 아니다. 저장 공간에는 패딩 비트가 있을 수 있으므로 일반적으로 N을 곧바로 `sizeof(자료형) * CHAR_BIT`라고 단정하지 않는다.

signed 정수형의 부호 비트를 제외한 값 비트가 M개이면 최댓값은 2^M - 1이다. C17이 허용하는 부호와 크기 표현 또는 1의 보수에서는 최솟값이 -(2^M - 1)이다. 일반적인 2의 보수에서는 -2^M이지만, C17은 그 특수 표현을 정상 값이 아닌 트랩 표현으로 두는 구현도 허용한다. 따라서 정확한 최솟값은 한계 매크로로 확인한다. C17은 2의 보수만을 강제하지 않는다. 패딩 없는 흔한 32비트 2의 보수 구현에서는 `int`가 -2147483648 ~ 2147483647, `unsigned int`가 0 ~ 4294967295이지만 이는 특정 구현의 사례다.

### unsigned 모듈러 산술

**[C 표준]** 연산이 unsigned 자료형에서 수행될 때 수학적 결과가 범위를 벗어나면 최댓값보다 1 큰 수를 법으로 줄인 값이 된다. 즉 `unsigned int`의 법은 수학적으로 `UINT_MAX + 1`이다.

- `UINT_MAX + 1U`의 C 계산 결과는 0이다.
- `0U - 1U`의 결과는 `UINT_MAX`다.
- `UINT_MAX`의 실제 숫자가 환경마다 달라도 위 두 관계는 같다.

`U`는 unsigned 정수 상수 접미사이며 여기서 `0U`, `1U`의 자료형은 `unsigned int`다. 수학적인 법 `UINT_MAX + 1`은 `unsigned int`로 표현할 수 없다. C 식 `UINT_MAX + 1U`을 계산해 법 자체를 저장하려 하면 이미 0으로 순환한다.

**[정의되지 않은 동작]** signed 산술에서 표현 범위를 넘기는 것은 별개다. `INT_MAX + 1`은 C17이 순환 결과를 보장하지 않는 signed overflow다. 예측 가능한 음수가 된다고 기대하거나 실습의 정상 경로로 실행하지 않는다.

**변환과 연산도 구별한다.** 음수를 unsigned 자료형으로 변환하면 그 자료형의 최댓값보다 1 큰 수를 반복해서 더하거나 빼서 범위 안의 값을 얻는다. 따라서 `unsigned int converted = -1;`의 값은 `UINT_MAX`다. 음수를 저장한 것이 아니라 unsigned 범위의 값으로 변환된 것이다. 반대로 범위 밖 정수를 signed 자료형으로 변환하면 구현 정의 결과 또는 구현 정의 신호가 발생할 수 있다. 이는 signed 산술 overflow의 UB 규칙과 다르다.

주의: `unsigned char`나 `unsigned short`는 연산 전에 `int`로 승격될 수 있다. 그러므로 “unsigned 변수를 사용한 식은 전부 unsigned 연산”이라고 외우지 않는다. 이번 예제는 양쪽 피연산자를 `unsigned int`로 맞춰 이 혼동을 피한다.

## 문법

| 선언 예 | 의미 |
|---|---|
| `signed int change = -3;` | 음수 변화량을 표현한다. `int`로 써도 같다. |
| `unsigned int count = 3U;` | 음수가 없는 개수를 표현한다. |
| `unsigned long budget = 4000000000UL;` | unsigned `long` 상수로 초기화한다. |
| `unsigned long long total = 10000000000ULL;` | unsigned `long long` 상수로 초기화한다. |

예시 값은 모두 해당 형의 최소 보장 범위 안이다. `UL`, `ULL`은 각각 unsigned와 길이 접미사를 함께 쓴 것이다. 접미사는 변수나 서식 문자열에 붙이지 않고 숫자에 붙인다.

`printf("count=%u\n", count);`에서 `%u`는 unsigned `int` 값을 십진수로 출력한다. `%d`를 `%u`로 바꾸는 것은 자료형 변환이 아니다. 반드시 선언한 변수의 자료형에 맞춰야 한다.

## 최소 코드 예제

`signed_unsigned.c`에 저장하여 실행할 수 있다.

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    signed int change = -3;
    unsigned int count = 3U;
    unsigned int maximum = UINT_MAX;
    unsigned int wrapped = maximum + 1U;
    unsigned int below_zero = 0U - 1U;

    printf("change=%d\n", change);
    printf("count=%u\n", count);
    printf("maximum=%u\n", maximum);
    printf("wrapped=%u\n", wrapped);
    printf("below_zero=%u\n", below_zero);
    return 0;
}
```

**[구현 사례]** `UINT_MAX`가 4294967295인 환경의 출력이다.

```text
change=-3
count=3
maximum=4294967295
wrapped=0
below_zero=4294967295
```

C17에서 변하지 않는 관찰은 `change=-3`, `count=3`, `wrapped=0`이며, `maximum`과 `below_zero`의 숫자는 항상 서로 같다. 최댓값의 십진수 자릿수 자체는 구현에 의존한다.

## 코드 해석

| 구성 | 해석 |
|---|---|
| `<stdio.h>` | `printf` 선언을 제공한다. |
| `<limits.h>` | 현재 구현의 정수형 한계값 매크로를 제공한다. |
| `change`, `count` | 부호 있는 변화량과 부호 없는 개수를 구별한다. |
| `maximum = UINT_MAX` | `unsigned int`의 실제 최댓값으로 초기화한다. `UINT_MAX`는 함수 호출이 아니다. |
| `maximum + 1U` | 두 피연산자가 `unsigned int`이므로 해당 형의 법으로 계산하여 0이다. |
| `0U - 1U` | unsigned `int` 연산에서 0 바로 아래 값이 최댓값으로 순환한다. |
| 다섯 `printf` | signed 값은 `%d`, unsigned 값은 `%u`로 출력한다. |
| `return 0;` | 성공 종료한다. 산술 결과와 종료 상태는 별개다. |

## 자주 하는 실수

- **unsigned는 더 큰 정수형이다.** 대응하는 signed와 저장 크기는 같다. 표현 가능한 값의 범위가 다르다.
- **부호를 생략하면 언제나 signed다.** `char`는 예외이며 별도의 자료형이다.
- **unsigned니까 음수 대입은 반드시 오류다.** 음수의 unsigned 변환은 정의되어 있다. 경고가 나올 수는 있지만 문법 차원의 음수 입력 금지 장치가 아니다.
- **`count`가 0일 때 1을 빼도 개수이니 0이 된다.** unsigned `int` 연산에서는 `UINT_MAX`로 순환한다. 정의된 계산이라도 업무 의미상 오류일 수 있다.
- **signed 최대값에 1을 더해 순환을 확인한다.** 정의되지 않은 동작이다. 이번 예제의 unsigned 계산과 구별한다.
- **서식만 바꿔 같은 값을 signed/unsigned로 변환한다.** 출력 함수에 잘못된 자료형을 전달할 수 있다. 자료형에 맞는 서식을 유지한다.
- **작은 unsigned 형의 계산도 항상 그 폭에서 순환한다.** 정수 승격 때문에 틀릴 수 있다. 예제의 `unsigned int`를 임의로 `unsigned char`로 바꾸지 않는다.





# 2-5. `float`, `double`, `long double`

기준은 C17 호스트 환경이다. 소수 부분이 있는 값을 저장하는 세 실수 부동소수점형을 배운다. **ISO C가 요구하는 성질**과 **흔한 IEEE 754 구현의 성질**을 구분한다. 크기 측정은 다음 Step, `<float.h>`의 상세 해석은 2-8에서 이어 간다.

## 핵심 개념

### 실수형이 모든 실수를 저장하는 것은 아니다

수학의 실수는 무한히 많지만 한 객체의 표현에는 유한한 저장 공간을 쓴다. 부동소수점형은 정해진 범위 안의 일부 값만 표현하며 나머지는 표현 가능한 값으로 근사해야 한다. 소수점을 쓸 수 있다는 말이 모든 소수를 정확히 저장한다는 뜻은 아니다.

- **범위(range):** 얼마나 큰 값, 얼마나 0에 가까운 작은 값을 표현할 수 있는가.
- **정밀도(precision):** 유효한 자릿값을 얼마나 보존할 수 있는가. 정수 부분까지 포함한 유효 숫자의 문제이지 소수점 아래 고정 자릿수의 문제가 아니다.
- **출력 정밀도:** `%.2f`처럼 화면에 소수점 아래 몇 자리를 표시할지 정하는 규칙. 저장형의 정밀도를 늘리지 않는다.

### 세 형의 관계

**[C 표준]** `float`가 표현할 수 있는 값의 집합은 `double`의 부분집합이고, `double`의 집합은 `long double`의 부분집합이다. 세 형은 서로 다른 자료형이지만 표현 능력이 반드시 엄격하게 커져야 하는 것은 아니다. `long double`이 `double`과 같은 표현 능력을 가질 수도 있다.

C의 최소 요구 사항은 `float`에 적어도 6자리, `double`과 `long double`에 적어도 10자리의 십진 정밀도를 요구한다. 이 숫자는 모든 십진 소수를 정확히 저장한다는 뜻이 아니라 표준이 정의하는 십진수 변환 정밀도의 하한이다. 세 형 모두 적어도 `1e-37`부터 `1e+37`에 해당하는 규모를 다룰 수 있는 범위를 요구하지만, 그 사이 모든 실수가 표현되는 것은 아니다. 실제 한계와 정밀도의 정량적 확인은 2-8에서 `<float.h>`로 한다.

**[흔한 IEEE 754 구현]** `float`가 binary32, `double`이 binary64인 환경에서는 유효 이진 자릿수가 각각 24, 53이다. 흔히 이를 십진 유효 숫자 약 7자리, 약 16자리라고 요약하지만, 이 요약은 C의 최소 보장도, 모든 값에서 정확히 보존되는 십진 자릿수도 아니다. `long double`은 같은 binary64, 확장 정밀도 형식, binary128 등 구현에 따라 다르다.

C17의 기본 규칙은 모든 구현에 IEEE 754, 2진 기수, 무한대 또는 NaN 지원을 강제하지 않는다. IEC 60559 부동소수점 규약을 따르는 구현을 위한 Annex F와 기본 C의 요구 사항을 혼동하지 않는다.

### 먼저 선택할 형

일반적인 소수 계산을 시작할 때는 `double`을 기본 선택으로 삼는 편이 단순하다. `float`는 저장 용량이나 외부 인터페이스 요구가 있을 때, `long double`은 대상 환경에서 실제 이득을 확인했을 때 선택한다. 어느 형도 일반적인 금액의 십진 소수를 자동으로 정확하게 만드는 형은 아니다.

## 문법

| 선언 또는 상수 | 의미 |
|---|---|
| `float ratio = 0.5f;` | `float` 상수로 `float` 변수 초기화 |
| `double ratio = 0.5;` | 접미사 없는 실수 상수는 `double` |
| `long double ratio = 0.5L;` | `long double` 상수로 초기화 |
| `1.25e2` | `1.25 × 10²`, 즉 125를 나타내는 `double` 상수 |
| `1.25e-2f` | `0.0125`를 나타내는 `float` 상수 |

`f`와 `F`, `l`과 `L`은 각각 같은 역할이다. 숫자 `1`과 구별하기 쉽도록 `L`을 권한다. `2`는 정수 상수이고 `2.0`, `2e0`은 `double` 상수다. `float x = 0.1;`도 유효하지만, 오른쪽은 먼저 `double` 상수이고 초기화 때 `float`로 변환된다. 변수의 형이 상수의 형을 거꾸로 바꾸지는 않는다.

| `printf` 인수 | 사용할 서식 | 이유 |
|---|---|---|
| `float` | `%f`, `%.2f` | 가변 인수로 전달될 때 `double`로 승격된다. |
| `double` | `%f`, `%.2f` | `%f`가 요구하는 인수형이 `double`이다. |
| `long double` | `%Lf`, `%.2Lf` | 대문자 `L`이 `long double` 인수를 지정한다. |

`%f`는 기본적으로 소수점 아래 6자리를 표시한다. `.2`는 소수점 아래 2자리로 반올림하여 표시하라는 뜻이지 변수를 변경하라는 뜻이 아니다. `printf`의 `%lf`도 C17에서는 `%f`와 같은 효과지만 이 자료는 `%f`로 통일한다. 이 규칙을 `scanf` 입력에 옮기면 안 된다. 입력 서식은 Part 5에서 별도로 배운다.

## 최소 코드 예제

`floating_types.c`에 저장한다.

```c
#include <stdio.h>

int main(void)
{
    float small = 1.25f;
    double ordinary = 1.25;
    long double extended = 1.25L;

    printf("float: %.2f\n", small);
    printf("double: %.2f\n", ordinary);
    printf("long double: %.2Lf\n", extended);
    return 0;
}
```

**[GCC/Linux 구현]** 파일이 있는 디렉터리에서 다음 명령으로 빌드하고 실행한다. `&&`는 빌드에 성공한 경우에만 실행하는 셸 문법이다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic floating_types.c -o floating_types && ./floating_types
printf 'status=%s\n' "$?"
```

정상 출력 환경에서 기대하는 출력은 다음과 같다. 같은 출력이 나와도 세 자료형의 모든 성질이 같다는 증거는 아니다.

```text
float: 1.25
double: 1.25
long double: 1.25
```

## 코드 해석

| 구성 | 해석 |
|---|---|
| `#include <stdio.h>` | `printf` 선언을 제공한다. |
| `int main(void)` | 인수를 받지 않는 호스트 프로그램의 시작 함수다. |
| `float small = 1.25f;` | 변수형과 상수형을 모두 `float`로 지정한다. |
| `double ordinary = 1.25;` | 접미사 없는 상수를 사용한다. |
| `long double extended = 1.25L;` | 두 단어가 하나의 자료형 이름을 이룬다. |
| 첫 번째 `printf` | `small`의 값을 `double`로 승격하여 전달한다. 변수 자체는 여전히 `float`다. |
| 두 번째 `printf` | `double` 값을 `%f` 계열 서식으로 출력한다. |
| 세 번째 `printf` | `long double` 값에 `%Lf` 계열 서식을 맞춘다. |
| `return 0;` | 호스트 환경에 성공 종료를 알린다. |

## 8. 자주 하는 실수

- **`float`는 항상 4바이트라고 외운다.** 흔한 구현의 선택이다. 크기는 2-6에서 측정하고 한 C byte의 비트 수도 따로 확인한다.
- **`long double`이면 반드시 더 정확하다고 생각한다.** `double`과 표현 능력이 같을 수 있다.
- **`%.20f`를 쓰면 정밀도가 20자리로 늘어난다고 생각한다.** 더 많은 문자를 볼 뿐 저장 정보는 늘지 않는다.
- **`float` 인수에 `%Lf`를 쓴다.** 전달되는 형은 `double`이다. 기대형 불일치는 정의되지 않은 동작이므로 잘못된 예제를 실행해 결과를 비교하지 않는다.
- **`long double x = 0.1;`에서 상수까지 `long double`이라고 생각한다.** 상수는 `double`이며 `0.1L`과 다른 변환 경로다.
- **`0.1`이 근사되니 모든 소수가 부정확하다고 말한다.** 흔한 2진 형식에서도 `0.5`, `1.25`처럼 정확히 표현 가능한 값이 있다.
- **범위를 넘으면 반드시 무한대가 나온다고 생각한다.** 기본 C17만으로 그러한 결과를 보장할 수 없다. 범위 밖 값과 연산은 이 실습에서 만들지 않는다.
