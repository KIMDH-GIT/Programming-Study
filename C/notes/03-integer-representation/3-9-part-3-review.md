# 3-9. Part 3 종합 복습

C17에서 정수를 읽고 쓰는 표기, 정수형이 표현하는 값, 산술 규칙을 하나의 흐름으로 연결한다. 종이에 적은 비트열과 C 객체의 실제 표현을 구별하고, 구현에 관계없이 보장되는 unsigned 규칙과 C17에서 구현이 선택할 수 있는 signed 표현을 분리한다.

## 1. 학습 목표

- bit, C byte, `CHAR_BIT`, 저장 공간, 값 비트를 서로 구별한다.
- 자릿값을 이용해 2진수와 10진수를 양방향으로 변환한다.
- 2진수 네 자리와 16진수 한 자리의 대응을 이용해 두 진법을 변환한다.
- C17의 10진·8진·16진 정수 리터럴을 값 및 자료형과 함께 읽는다.
- 값 비트가 N개인 unsigned 정수형의 범위와 모듈러 산술을 설명한다.
- 2의 보수 모델을 계산하되, C17이 signed 표현을 하나로 고정하지 않는다는 한계를 말한다.
- 같은 모양의 비트열도 자료형과 표현 규칙에 따라 다른 값이 될 수 있음을 설명한다.
- unsigned 순환은 정의된 동작이고 signed overflow는 정의되지 않은 동작임을 코드에서 구별한다.

## 2. 선수 지식과 범위

Step 3-1~3-8의 종합 복습이다. Part 2에서 배운 선언·초기화, `signed`와 `unsigned`, `sizeof`, `size_t`, C byte, `CHAR_BIT`, `<limits.h>`, 정수 출력 서식을 사용한다. Part 1의 `<stdio.h>`, `int main(void)`, `printf`, `return 0;`도 그대로 사용한다.

이번 Part에서 비트열은 **수학적 표기와 개념 모델**로 다룬다. 비트 AND·OR·XOR·NOT 연산자와 왼쪽·오른쪽 shift는 사용하거나 가르치지 않으며 **Part 21 비트 연산**으로 미룬다. 객체를 byte별로 관찰하는 방법과 endianness는 **Part 20**으로 미룬다. 고정 폭 정수형과 관련 헤더는 **Part 4**의 내용이므로 여기서 도입하지 않는다.

따라서 `101101₂`는 종이에 쓴 2진 표기이지 C17 정수 리터럴이 아니다. 이번 코드는 배운 10진·8진·16진 리터럴과 안전한 unsigned 덧셈·뺄셈만 사용한다.

### 3.2 bit, C byte, 저장 공간

- **bit:** 두 상태 0과 1로 나타내는 이진 정보 단위다.
- **C byte:** `sizeof`가 세는 주소 지정 가능한 저장 단위다. `sizeof(char)`는 언제나 1 C byte다.
- **`CHAR_BIT`:** 한 C byte에 들어 있는 bit 수이며 `<limits.h>`가 제공한다. C17은 8 이상을 보장하지만 정확히 8이라고 고정하지 않는다.
- **저장 비트 수:** 기본형 객체라면 `sizeof(형)`의 C byte 수와 `CHAR_BIT`를 수학적으로 곱해 구할 수 있다.
- **값 비트:** 값의 크기를 표현하는 데 참여하는 비트다. 저장 공간에는 부호 비트와 padding bit도 있을 수 있으므로 저장 비트 수와 같다고 단정하지 않는다.

예를 들어 어떤 구현에서 `sizeof(unsigned int)`가 4이고 `CHAR_BIT`가 8이면 객체 표현의 저장 공간은 32비트다. 그러나 이 관찰만으로 일반 정수형에 padding bit가 없다고 결론 내리지는 않는다. unsigned의 실제 최댓값은 `UINT_MAX`, signed의 경계는 `INT_MIN`과 `INT_MAX`로 확인한다.

### 3.3 자릿값과 진법 변환

기수 b의 수에서 오른쪽 끝 자리는 b의 0제곱, 그 왼쪽은 b의 1제곱, 다음은 b의 2제곱의 가중치를 가진다. 예를 들어 `101101₂`는 다음 합이다.

```text
1×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1 = 45
```

2진수에서 10진수로 바꿀 때는 1인 자리의 가중치를 더한다. 10진 양의 정수를 2진수로 바꿀 때는 2로 계속 나눈 나머지를 아래에서 위로 읽는다. 0은 별도로 `0₂`이며, 앞쪽 0은 값에 영향을 주지 않는다.

| 45를 2로 나누는 과정 | 몫 | 나머지 |
|---|---:|---:|
| 45 ÷ 2 | 22 | 1 |
| 22 ÷ 2 | 11 | 0 |
| 11 ÷ 2 | 5 | 1 |
| 5 ÷ 2 | 2 | 1 |
| 2 ÷ 2 | 1 | 0 |
| 1 ÷ 2 | 0 | 1 |

나머지를 역순으로 읽으면 `101101₂`다. 이 절차는 수학적 변환이며 C 코드의 나눗셈 반복을 요구하지 않는다.

### 3.4 16진수와 2진수

16은 2의 네 번 곱과 같으므로 16진수 한 자리는 정확히 2진수 네 자리에 대응한다.

| 16진 | 2진 | 16진 | 2진 |
|---:|:---:|---:|:---:|
| 0 | 0000 | 8 | 1000 |
| 1 | 0001 | 9 | 1001 |
| 2 | 0010 | A | 1010 |
| 3 | 0011 | B | 1011 |
| 4 | 0100 | C | 1100 |
| 5 | 0101 | D | 1101 |
| 6 | 0110 | E | 1110 |
| 7 | 0111 | F | 1111 |

`0010 1101₂`를 네 자리씩 읽으면 `2D₁₆`이다. 반대로 `0x2D`의 숫자 부분은 `0010 1101₂`로 펼칠 수 있다. 값만 쓸 때 앞쪽 `0010`의 앞 0을 생략해도 되지만, 정해진 폭의 패턴을 비교할 때는 폭을 맞추기 위해 유지할 수 있다. 대문자 A~F와 소문자 a~f는 같은 숫자값 10~15를 나타낸다.

### 3.5 C17의 10진·8진·16진 정수 리터럴

| C 소스 표기 | 기수 | 수학적 값 | 읽을 때 주의점 |
|---|---:|---:|---|
| `42` | 10 | 42 | 0이 아닌 숫자로 시작한다. |
| `052` | 8 | 42 | 앞의 0이 8진 표기를 시작한다. |
| `0x2A` | 16 | 42 | `0x` 또는 `0X` 뒤에 16진 숫자가 온다. |
| `42U` | 10 | 42 | `U`가 unsigned 후보 형을 선택하게 한다. |
| `052U` | 8 | 42 | 기수 표시와 접미사는 별개다. |
| `0x2AU` | 16 | 42 | A는 숫자, U는 접미사다. |

C17에는 `0b`로 시작하는 표준 2진 정수 리터럴이 없다. 컴파일러 확장을 C17 문법으로 보고하지 않는다. 8진 숫자에는 0~7만 쓸 수 있으므로 `08`은 올바른 8진 정수 리터럴이 아니다. `0` 하나는 값 0을 나타내는 8진 상수 문법에 속하지만 어느 진법으로 읽어도 값은 같다.

접미사가 없는 10진 상수는 값을 표현할 수 있는 첫 형을 `int`, `long int`, `long long int` 순으로 찾는다. 접미사가 없는 8진·16진 상수는 `int`, `unsigned int`, `long int`, `unsigned long int`, `long long int`, `unsigned long long int` 순으로 찾는다. `U`를 붙이면 unsigned 후보만 사용한다. 같은 값이라도 표기 기수와 접미사 때문에 선택 가능한 자료형 순서가 다를 수 있다.

### 3.6 N-bit unsigned 범위

N개의 값 비트는 각각 두 상태를 가지므로 서로 다른 조합은 2<sup>N</sup>개다. 모든 값 비트가 0인 패턴을 0으로, 모두 1인 패턴을 최댓값으로 읽는 순수 이진 표현에서 범위는 다음과 같다.

```text
0 이상 2ᴺ - 1 이하
```

| 값 비트 N | 조합 수 | unsigned 범위 | 예시 최댓값 패턴 |
|---:|---:|---:|:---:|
| 3 | 8 | 0~7 | 111 |
| 4 | 16 | 0~15 | 1111 |
| 8 | 256 | 0~255 | 11111111 |

여기서 N은 **값 비트 수**다. `sizeof`와 `CHAR_BIT`의 곱인 저장 비트 수를 근거 없이 N으로 대입하지 않는다. C17의 unsigned 정수형은 순수 이진 표현을 사용하며, padding bit가 있을 수 있다. 현재 구현의 N을 역으로 확인하려면 해당 unsigned 최댓값과 구현 문서를 함께 본다.

### 3.7 2의 보수 모델과 C17 signed 대안

패딩이 없는 총 8비트 모델에서 signed 값의 크기 부분이 7비트라면 양수 범위는 0~127이다. 2의 보수 모델에서는 음수 쪽이 한 값 더 있어 -128~127이다. 양수 x에 대응하는 음수 패턴은 개념적으로 2<sup>8</sup>에서 x를 뺀 값을 8자리 순수 이진수로 적어 얻을 수 있다. 예를 들어 -5의 모델 패턴은 `11111011`이다.

그러나 **C17은 signed 정수 표현을 2의 보수 하나로 제한하지 않는다.** 부호와 크기, 1의 보수, 2의 보수 표현을 허용한다. 부호 비트 이외의 값 비트가 M개라면 최댓값은 2<sup>M</sup>-1이다. 부호와 크기 및 1의 보수의 특별한 패턴은 음의 0 또는 trap representation일 수 있다. 2의 보수에서도 부호 비트만 1인 패턴은 추가 최솟값 -2<sup>M</sup> 또는 trap representation일 수 있다. 실제 경계는 `<limits.h>`의 매크로로 확인한다.

다음은 **패딩 없는 개념적 8-bit 패턴**을 서로 다른 규칙으로 읽은 비교다. 실제 C 객체를 관찰한 결과가 아니다.

| 패턴 | unsigned | 부호와 크기 | 1의 보수 | 2의 보수 |
|:---:|---:|---:|---:|---:|
| `00101010` | 42 | 42 | 42 | 42 |
| `10000001` | 129 | -1 | -126 | -127 |
| `11111111` | 255 | -127 | 음의 0 후보 | -1 |

대응하는 signed·unsigned 형에서 공통으로 표현 가능한 음이 아닌 값은 같은 값과 같은 표현을 갖는다. 하지만 임의의 패턴을 signed 값으로 읽은 결과는 구현의 signed 표현, padding, trap 가능성을 알아야 한다. 선언의 철자나 `printf` 서식만 바꾸는 행위를 안전한 “같은 패턴 재해석”으로 취급하지 않는다. 값 변환 규칙과 객체 표현 관찰은 서로 다른 주제다.

### 3.8 unsigned 모듈러와 signed overflow

unsigned 정수형의 산술은 그 형이 표현할 수 있는 값의 개수, 즉 최댓값보다 1 큰 수를 법으로 계산한다. `unsigned int`에서는 다음 관계가 C17에 의해 정의된다.

- `UINT_MAX + 1U`의 결과는 0이다.
- `0U - 1U`의 결과는 `UINT_MAX`다.
- 실제 `UINT_MAX` 숫자가 구현마다 달라도 두 관계는 유지된다.

반대로 `INT_MAX + 1`과 같이 signed 연산의 수학적 결과가 결과형 범위를 벗어나면 C17에서 정의되지 않은 동작이다. 2의 보수 CPU에서 우연히 최솟값처럼 보였다는 관찰은 C의 보장이 아니다. 컴파일러 경고, 최적화 수준, 한 번의 실행 결과로 UB의 값을 정할 수 없다. 경계를 관찰하려면 `INT_MIN`, `INT_MAX`를 출력하고 범위를 넘는 식은 실행하지 않는다.

unsigned 순환이 정의되어 있다는 사실도 업무상 값이 옳다는 뜻은 아니다. 재고가 0일 때 1을 빼서 큰 값이 되는 계산은 언어 차원에서는 정의되어도 프로그램 요구에는 어긋날 수 있다.

## 4. 문법

### 리터럴·변수·출력 대응

| 목적 | C17 예 | 결과 또는 서식 |
|---|---|---|
| 같은 값의 10진 표기 | `unsigned int a = 42U;` | `%u`, 값 42 |
| 같은 값의 8진 표기 | `unsigned int b = 052U;` | `%u`, 값 42 |
| 같은 값의 16진 표기 | `unsigned int c = 0x2AU;` | `%u`, 값 42 |
| 실제 unsigned 최댓값 | `unsigned int maximum = UINT_MAX;` | `%u` |
| 정의된 다음 값 | `unsigned int wrapped = maximum + 1U;` | 값 0 |
| 정의된 0 아래 값 | `unsigned int below_zero = 0U - 1U;` | 값 `UINT_MAX` |
| C byte당 bit 수 | `(int)CHAR_BIT` | `%d` |
| 객체의 C byte 수 | `sizeof(unsigned int)` | `%zu` |

`U`와 `u`는 같은 접미사지만 다른 접미사와 섞을 때 읽기 쉬운 대문자를 일관되게 쓰는 편이 좋다. 16진 숫자의 `A`는 숫자 10이고 마지막 `U`는 unsigned 접미사다. 출력 서식은 값을 표시하는 진법과 전달 인수의 형을 모두 만족해야 한다. 이번 최소 예제는 이미 배운 `%d`, `%u`, `%zu`만 사용한다.

## 5. 최소 코드 예제

`part3_probe.c`로 작성할 수 있는 안전한 최소 예제다. 2진 리터럴, 비트 연산, shift, 포인터, 배열, 조건문, 반복문을 사용하지 않는다.

```c
#include <limits.h>
#include <stdio.h>

int main(void)
{
    unsigned int decimal = 42U;
    unsigned int octal = 052U;
    unsigned int hexadecimal = 0x2AU;
    unsigned int maximum = UINT_MAX;
    unsigned int wrapped = maximum + 1U;
    unsigned int below_zero = 0U - 1U;

    printf("CHAR_BIT=%d\n", (int)CHAR_BIT);
    printf("unsigned_int_bytes=%zu\n", sizeof(unsigned int));
    printf("same_value=%u,%u,%u\n", decimal, octal, hexadecimal);
    printf("maximum=%u\n", maximum);
    printf("wrapped=%u\n", wrapped);
    printf("below_zero=%u\n", below_zero);
    return 0;
}
```

모든 초기값과 연산은 C17에서 정의된다. 정상 표준 출력 환경에서는 `same_value=42,42,42`, `wrapped=0`이 보이고 `below_zero`는 `maximum`과 같은 숫자다. `CHAR_BIT`, 객체의 C byte 수, `UINT_MAX`의 구체적인 값은 대상 구현의 관찰이다.

## 6. 코드 해석

1. `<limits.h>`는 `CHAR_BIT`와 `UINT_MAX`, `<stdio.h>`는 `printf` 선언을 제공한다.
2. `decimal`, `octal`, `hexadecimal`은 소스 표기가 다르지만 같은 수학적 값 42로 초기화된다.
3. 세 리터럴의 `U` 때문에 값이 `unsigned int` 후보에 맞으며 세 변수의 선언과 `%u`가 일치한다.
4. `maximum`은 숫자를 하드코딩하지 않고 현재 구현의 `unsigned int` 최댓값을 사용한다.
5. `maximum + 1U`는 unsigned `int` 산술이므로 0으로 순환한다. signed overflow 실험이 아니다.
6. `0U - 1U`도 unsigned `int` 산술이며 결과는 `UINT_MAX`다.
7. `sizeof(unsigned int)`는 C byte 수를 `size_t` 값으로 만들기 때문에 `%zu`로 출력한다.
8. 프로그램은 비트열을 직접 관찰하지 않는다. 같은 숫자 출력은 세 객체의 byte 배열이 모든 구현에서 같다는 실험이 아니라 세 리터럴 값의 동등성을 확인한다.
9. `return 0;`은 성공 종료를 보고하며 개념 설명과 관찰표가 완성되었다는 자동 판정은 아니다.

## 7. 내부 동작

**[C 표준·번역]** 컴파일러는 전처리 뒤 정수 상수의 기수, 숫자, 접미사를 해석하고 값을 표현할 수 있는 후보 자료형을 선택한다. `052U`를 먼저 문자열 “052”로 저장했다가 실행 중 8진 변환하는 것이 아니다. 세 리터럴은 번역된 프로그램에서 같은 값을 제공한다.

**[C 추상 기계·표현]** unsigned 정수형은 순수 이진 표현을 사용하며 산술은 정해진 법으로 줄어든다. signed 정수형은 C17에서 세 표현 대안과 padding·특수 표현 가능성이 남아 있다. 추상적인 값, 객체 표현, 출력된 문자 순서는 같은 개념이 아니다.

**[컴파일러]** 상수와 결과를 번역 중 계산하여 `printf`에 바로 전달할 수도 있고 변수를 레지스터 또는 메모리에 둘 수도 있다. 최적화 방식이 달라도 정의된 관찰 결과는 유지해야 한다. signed overflow가 없다고 가정하는 최적화는 C17 규칙과 충돌하지 않으므로 UB에 기대는 코드는 최적화에서 특히 예측할 수 없다.

**[CPU·ABI 구현]** CPU 명령이 일정 폭에서 순환하는 것처럼 보여도 C 자료형의 폭, padding, signed 표현, 호출 규약은 대상 구현과 ABI의 선택을 함께 받는다. “64-bit CPU”라는 말만으로 `unsigned int`의 값 비트 수를 정하지 않는다.

**[OS·입출력]** OS는 프로그램 실행과 표준 출력 환경을 제공하지만 리터럴의 진법이나 C 산술 규칙을 정하지 않는다. 출력된 `42`는 `%u`가 만든 10진 문자 표현이며 메모리에 10진 숫자 글자가 저장되어 있었다는 뜻이 아니다.

## 8. 자주 하는 실수

- `sizeof(char) == 1`을 1비트 또는 반드시 8비트라고 읽는다. 1 C byte이고 실제 bit 수는 `CHAR_BIT`다.
- 저장 비트 수를 모두 값 비트라고 가정한다. padding과 signed의 부호 표현 가능성을 분리한다.
- `1010`을 C17의 2진 리터럴로 쓴다. 접두사가 없으므로 C에서는 십진수 천십이다.
- `0b1010`을 표준 C17 문법이라고 한다. 구현 확장 여부와 표준 문법을 구별한다.
- 앞의 0을 보기 좋게 붙여 `052`를 십진수 52로 생각하거나 `08`을 쓴다.
- 16진수 한 자리를 두 bit 또는 여덟 bit로 대응시킨다. 한 자리는 네 bit다.
- N-bit unsigned의 N을 검증 없이 `sizeof(형)`과 `CHAR_BIT`의 곱으로 둔다.
- 2의 보수 표를 모든 C17 signed 정수형의 의무 표현이라고 한다.
- 출력 서식만 바꾸면 같은 객체 표현을 다른 형으로 안전하게 재해석한다고 생각한다.
- `UINT_MAX + 1U`의 정의된 결과를 근거로 `INT_MAX + 1`도 순환한다고 예상한다.
- unsigned 순환은 정의되므로 재고·길이 계산도 논리적으로 안전하다고 결론 낸다.
- 비트 연산, shift, byte 순서, 고정 폭 정수형을 이번 복습에 끌어와 선수 지식 범위를 넘긴다.

## 11. 확인 문제

1. `sizeof(char) == 1`과 `CHAR_BIT == 8`은 각각 어떤 단위를 말하며 둘째 식은 모든 C17 구현에서 참인가?
2. `110101₂`를 10진수로 바꾸고 자릿값의 합을 쓰라.
3. `7B₁₆`을 여덟 자리 2진수로 바꾸라. 앞쪽 0을 유지하는 이유도 쓰라.
4. `31`, `037`, `0x1F`는 어떤 값을 나타내는가? `031`도 같은가?
5. 값 비트가 6개인 unsigned 모델의 조합 수와 범위는 무엇인가?
6. 개념적 패턴 `10000001`의 signed 값이 C17 전체에서 하나로 확정되지 않는 이유는 무엇인가?
7. `UINT_MAX + 1U`와 `INT_MAX + 1`의 동작 분류를 각각 말하라.

<details>
<summary>정답과 해설</summary>

1. 첫째의 1은 C byte 수이고 `CHAR_BIT`는 C byte당 bit 수다. C17은 `CHAR_BIT`가 8 이상임을 보장할 뿐 정확히 8로 고정하지 않는다.
2. `32 + 16 + 4 + 1 = 53`이므로 53이다.
3. `01111011₂`다. 16진 두 자리를 각각 네 자리로 대응시키는 폭을 보이기 위해 앞쪽 0을 유지한다.
4. 앞의 세 표기는 모두 31이다. `031`은 8진수이므로 25다.
5. 64개이며 범위는 0~63이다.
6. C17은 부호와 크기, 1의 보수, 2의 보수를 허용하고 padding과 특수 표현 가능성도 있기 때문이다. 비트열은 폭과 해석 규칙 없이 signed 값을 하나로 정하지 못한다.
7. unsigned 식은 정의된 모듈러 산술로 0이 된다. signed 식은 표현 범위를 넘으므로 정의되지 않은 동작이다.

</details>

## 12. 핵심 정리

Part 3의 완료 기준은 흔한 32-bit 2의 보수 숫자를 외우는 것이 아니라 **표기, 값, 자료형, 객체 표현, 산술 동작을 구별하는 것**이다. 자릿값으로 진법을 변환하고, 16진 한 자리를 2진 네 자리와 대응시키며, C 리터럴의 접두 형태와 접미사로 기수와 후보 자료형을 읽는다.

값 비트 N개의 unsigned 범위는 0~2<sup>N</sup>-1이고 산술은 2<sup>N</sup>을 법으로 한다. C17 signed 표현은 2의 보수로만 고정되지 않으며 실제 범위는 한계 매크로로 확인한다. unsigned 순환은 정의되어 있지만 signed overflow는 UB다. 어느 쪽도 프로그램의 논리적 경계 검사를 대신하지 않는다.
