# 5-10. 문자·문자열 입력과 buffer 한계

`scanf`의 `%c`는 문자 하나를, `%s`는 공백 전까지의 문자열을 읽는다. 문자열 입력은 목적지 배열의 크기를 넘지 않도록 필드 폭을 반드시 제한해야 한다.

## 1. 학습 목표

- `%c`와 `%s`의 공백 처리 차이를 설명한다.
- `%Ns`의 필드 폭과 배열 용량 관계를 계산한다.
- 문자열 입력 뒤 null 문자 공간을 남긴다.

## 2. 선수 지식

Step 5-4의 문자·문자열과 Step 5-7의 입력 구조를 사용한다. 배열과 문자열의 전체 규칙은 Part 11과 Part 13에서 다룬다.

## 3. 핵심 개념

`%c`는 공백도 문자로 읽으므로 앞선 줄바꿈을 건너뛰려면 `" %c"`처럼 서식의 공백을 사용할 수 있다. `%s`는 선행 공백을 건너뛰고 다음 공백 전까지 읽은 뒤 `'\0'`을 붙인다.

`char word[16]`에는 최대 15문자와 종료 null 문자가 들어가므로 `%15s`를 사용한다. 폭 없는 `%s`는 입력 길이를 제한하지 못해 배열 범위를 넘을 위험이 있다.

## 4. 문법

```c
scanf(" %c %15s", &letter, word);
```

배열 이름에는 여기서 별도의 `&`를 붙이지 않는다. 배열과 포인터의 관계는 Part 15에서 설명한다.

## 5. 최소 코드 예제

```c
#include <stdio.h>

int main(void)
{
    char letter = '?';
    char word[16] = "";
    int matched;

    matched = scanf(" %c %15s", &letter, word);
    printf("matched=%d letter=%c word=%s\n", matched, letter, word);
    return 0;
}
```

## 6. 코드 해석

1. 배열은 빈 문자열로 초기화한다.
2. 서식 앞 공백이 입력의 공백 문자를 건너뛴다.
3. `%15s`는 최대 15문자를 저장하고 null 문자를 덧붙인다.
4. 정상 입력 두 항목이면 반환값은 2다.

## 7. 내부 동작

표준 입력에는 사용자가 누른 줄바꿈도 문자로 남을 수 있다. `%s`는 공백을 포함한 한 줄 전체를 읽는 도구가 아니다. 긴 token의 나머지는 입력 스트림에 남을 수 있으며 이후 문자열 입력은 `fgets`를 배울 때 더 안전하게 다룬다.

## 8. 자주 하는 실수

- `%c` 앞에 남은 줄바꿈을 예상하지 못한다.
- `char word[16]`에 `%16s`를 사용한다.
- 폭 없는 `%s`로 임의 길이 입력을 받는다.
- `%s`가 공백 포함 한 줄을 읽는다고 생각한다.

## 9. 필수 실습

## 10. 추가 실습

- ★ **기초:** 공백이 있는 입력에서 `%s`가 멈추는 위치를 본다.
- ★★ **응용:** 15자와 16자 token을 비교한다.
- ★★★ **도전:** 남은 입력이 다음 변환에 미치는 영향을 기록한다.

## 11. 확인 문제

1. `%c`는 공백을 자동으로 건너뛰는가?
2. 16칸 배열에 안전한 `%s` 폭은 얼마인가?
3. 종료 null 문자 공간은 왜 필요한가?
4. `%s`로 공백 포함 한 줄 전체를 읽을 수 있는가?

## 12. 핵심 정리

문자 입력의 공백 처리와 문자열 입력의 용량 제한을 명시해야 한다. N칸 배열에는 최대 `N-1` 폭의 `%s`를 사용한다.
