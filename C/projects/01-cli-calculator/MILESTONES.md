# Milestones

## Milestone 1 — 프로그램 계약과 첫 정상 입력

### 목표

구현 전에 사용자 관점의 기능, 입력, 출력, 종료 규칙을 정하고 한 번의 정상 계산에 필요한 최소 흐름을 직접 설계한다.

### 관련 P1 Step

- P1-1. 기능·입력·종료 규칙

### 사용할 기존 Part

- Part 5: 표준 입출력과 format contract
- Part 7: 산술 연산
- Part 8: 조건에 따른 흐름

### 필수 기능

- 필수 연산과 사용자 입력 순서를 자신의 말로 정의한다.
- 한 번의 유효한 요청이 결과까지 이어지는 정상 behavior를 정한다.
- 종료 요청을 어떤 입력으로 구분할지 결정한다.

### 완료 조건

- 정상 입력 한 종류와 종료 요청의 contract가 문서화되어 있다.
- 첫 정상 경로를 실행해 기대한 연산 결과를 관찰했다.
- 세부 구현 선택과 그 이유를 `DEVLOG.md`에 기록했다.

### 검증해야 할 동작

- 유효한 연산 선택과 두 피연산자가 한 번의 결과로 이어진다.
- 피연산자 순서가 필요한 연산에서 순서가 보존된다.
- 종료 요청은 계산 요청으로 처리되지 않는다.

### 사용자가 직접 생각할 질문

- 입력 한 건의 시작과 끝을 무엇으로 구분할 것인가?
- 메뉴 표현과 내부 연산 표현을 같게 할지 분리할지?
- 이 milestone에서 빠뜨리기 쉬운 정상 경로 test 두 개는 무엇인가?

## Milestone 2 — 입력 성공·실패·EOF 구분

### 목표

입력 결과를 사용하기 전에 성공, 변환 실패, EOF를 구분하고 각 경우의 observable behavior를 설계한다.

### 관련 P1 Step

- P1-2. `scanf` 반환값과 EOF
- P1-3. 잘못된 입력과 0으로 나누기 중 잘못된 입력

### 사용할 기존 Part

- Part 5: 입력 함수 반환값과 입력 검증
- Part 8: 오류 분기
- Part 9: 입력 반복

### 필수 기능

- 연산 선택과 피연산자 입력의 성공 여부를 판별한다.
- 잘못된 입력이 들어왔을 때 이후 입력을 어떻게 이어 갈지 정한다.
- 입력 과정 어느 지점에서든 EOF가 발생하면 정의된 종료 behavior를 보인다.

### 완료 조건

- 성공, 변환 실패, EOF가 서로 다른 경로로 관찰된다.
- 실패한 입력의 값이 계산에 사용되지 않는다.
- 오류 후 계속한다면 다음 요청이 이전 실패 상태의 영향을 받지 않는다.

### 검증해야 할 동작

- 숫자가 아닌 입력을 결과로 처리하지 않는다.
- 첫 입력과 중간 피연산자 입력에서의 EOF가 안전하게 종료된다.
- 입력 실패 후 이전 피연산자가 재사용되지 않는다.

### 사용자가 직접 생각할 질문

- 선택한 입력 API에서 변환되지 않은 입력은 어디에 남는가?
- EOF와 일반 입력 오류를 같은 status로 다뤄도 contract가 명확한가?
- 이 milestone에서 누락될 수 있는 경계 test를 최소 두 개 추가한다면?

## Milestone 3 — 연산과 오류 처리

### 목표

네 필수 연산을 구현하고, 지원하지 않는 연산과 0으로 나누기를 정상 결과와 명확히 구분한다.

### 관련 P1 Step

- P1-3. 잘못된 입력과 0으로 나누기
- P1-4. 연산 함수 구현

### 사용할 기존 Part

- Part 6: 형 변환과 signed/unsigned 관계
- Part 7: 산술 연산과 나눗셈 경계
- Part 8: 연산 선택과 오류 분기
- Part 10: 함수 contract

### 필수 기능

- 덧셈, 뺄셈, 곱셈, 나눗셈의 의미를 선택한 숫자 표현에 맞게 정의한다.
- invalid operator를 거부한다.
- divisor가 0인 나눗셈을 평가하지 않는다.
- 연산 성공과 실패를 caller가 구분할 방법을 직접 설계한다.

### 완료 조건

- 네 연산의 정상 test가 통과한다.
- invalid operator와 0으로 나누기가 정상 결과를 만들지 않는다.
- 선택한 자료형의 범위와 나눗셈 규칙이 문서화되어 있다.

### 검증해야 할 동작

- 음수, 0, 피연산자 순서를 포함한 연산 결과가 contract와 일치한다.
- 오류 경로에서 성공 결과처럼 보이는 값을 출력하지 않는다.
- 연산 로직을 입출력과 분리할지 결정한 이유가 설명되어 있다.

### 사용자가 직접 생각할 질문

- 연산 실패를 값 하나로 표현하면 정상 결과와 충돌할 가능성이 있는가?
- 선택한 숫자 자료형에서 어떤 연산 경계가 있는가?
- 이 milestone의 범위·부호 관련 test를 최소 두 개 직접 추가한다면?

## Milestone 4 — 메뉴와 반복 실행 통합

### 목표

입력, 연산, 출력, 오류 처리를 하나의 반복 가능한 사용자 흐름으로 연결한다.

### 관련 P1 Step

- P1-5. 메뉴와 함수 연결
- P1-6. 반복 실행

### 사용할 기존 Part

- Part 8: 메뉴 분기와 상태 구분
- Part 9: 반복과 종료 조건
- Part 10: 역할 분리와 함수 호출

### 필수 기능

- 사용자가 계산을 반복할 수 있다.
- 각 반복에서 입력과 오류 상태를 새 요청에 맞게 관리한다.
- 명시적 종료와 EOF 종료가 반복을 끝낸다.
- 메뉴와 연산 동작 사이의 mapping을 일관되게 유지한다.

### 완료 조건

- 연속된 두 번 이상의 정상 계산이 동작한다.
- 정상 계산 뒤 오류, 오류 뒤 정상 계산이 서로 영향을 주지 않는다.
- 종료 요청 후 추가 입력을 요구하지 않는다.

### 검증해야 할 동작

- repeated operation에서 각 결과가 해당 요청의 입력만 사용한다.
- invalid input 후 복구 정책이 반복 전체에서 일관된다.
- 명시적 종료와 EOF 모두 무한 반복 없이 종료된다.

### 사용자가 직접 생각할 질문

- 반복 한 회가 소유하는 상태는 무엇이며 언제 초기화해야 하는가?
- menu 출력과 입력 요청을 어느 책임에 둘 것인가?
- 여러 요청을 조합했을 때만 드러날 test를 최소 두 개 추가한다면?

## Milestone 5 — warning 제거와 종합 검증

### 목표

strict build를 통과시키고 정상·오류·반복·종료 경로를 하나의 최종 test set으로 검증한다.

### 관련 P1 Step

- P1-7. warning 없는 build
- P1-8. 정상·오류·종료 경로 최종 검증

### 사용할 기존 Part

- Part 0: compile과 executable
- Part 5: format과 입력 contract
- Part 27: Undefined Behavior와 compile 성공의 차이
- Part 28: warning, debugger, 결함 재현·재검증

### 필수 기능

- baseline compile option을 모두 사용한다.
- 모든 warning의 원인을 이해하고 수정한다.
- `TEST_PLAN.md`의 필수 test를 실행한다.
- milestone 1~4에서 직접 추가한 test를 다시 실행한다.
- 최종 설계와 남은 한계를 문서화한다.

### 완료 조건

- `gcc -std=c17 -Wall -Wextra -Wpedantic -Werror` baseline build가 성공한다.
- 정상·잘못된 입력·EOF·invalid operator·0으로 나누기·반복·종료 test가 통과한다.
- executable과 object file이 Git stage에 포함되지 않는다.
- `DEVLOG.md`에 최종 회고와 검증 결과가 기록되어 있다.

### 검증해야 할 동작

- clean build에서 warning과 error가 없다.
- 각 오류 뒤에도 정의한 계속/종료 정책이 유지된다.
- 전체 test를 한 번의 우연한 성공이 아니라 독립적으로 재현할 수 있다.

### 사용자가 직접 생각할 질문

- compiler가 잡지 못하지만 C17 correctness를 해칠 수 있는 경로는 무엇인가?
- 현재 test가 구현 세부사항이 아니라 behavior를 검증하는가?
- 최종 regression test를 최소 두 개 더 추가한다면 어떤 경로 조합인가?
