# Test Plan

## 테스트 원칙

- test는 특정 함수·메뉴 번호나 파일 형식의 정답이 아니라 사용자에게 보이는 behavior를 검증한다.
- 각 test는 별도의 초기 DB와 필요한 경우 별도의 임시 저장 파일을 준비해 이전 test의 상태에 의존하지 않는다.
- 입력 표기와 기대 출력은 학습자가 선택한 데이터·오류·저장 contract에 맞게 구체화한다.
- 실패 경로에서 다른 레코드와 파일 상태가 어떻게 되는지도 확인한다.
- 기대 behavior를 만족시키는 구현 코드는 이 문서에 제공하지 않는다.

## 필수 Test Cases

### T-001 — 빈 DB

- Test ID: T-001
- 목적: 학생이 없는 상태의 조회와 목록을 확인한다.
- 입력 또는 초기 상태: 레코드가 없는 DB
- 수행 동작: List와 Search를 수행한다.
- 기대 behavior: 목록은 비어 있음을 알리고 검색은 찾지 못함을 알리며 DB는 비어 있다.
- 검증 이유: 크기 0의 경계와 빈 상태의 출력 contract를 확인한다.
- 관련 milestone: Milestone 1, Milestone 3, Milestone 4

### T-002 — 단일 레코드 추가

- Test ID: T-002
- 목적: 첫 동적 할당과 Add 정상 경로를 확인한다.
- 입력 또는 초기 상태: 빈 DB, 유효한 학생 한 명
- 수행 동작: 학생을 추가하고 목록과 검색으로 확인한다.
- 기대 behavior: 한 명만 보이고 입력한 학생을 찾을 수 있다.
- 검증 이유: 최초 추가에서 크기·데이터 저장이 올바른지 확인한다.
- 관련 milestone: Milestone 2, Milestone 3, Milestone 4

### T-003 — 여러 레코드 추가

- Test ID: T-003
- 목적: 추가 중 확장과 이전 데이터 보존을 확인한다.
- 입력 또는 초기 상태: 빈 DB, 서로 다른 ID의 유효한 학생 여러 명
- 수행 동작: 순서대로 추가한 뒤 List를 수행한다.
- 기대 behavior: 모든 학생이 한 번씩 나타나고 각 필드가 유지된다.
- 검증 이유: 용량 경계에서 레코드 소실·중복을 발견한다.
- 관련 milestone: Milestone 2, Milestone 4

### T-004 — 중복 ID 정책

- Test ID: T-004
- 목적: 같은 ID의 재입력을 정의한 정책과 비교한다.
- 입력 또는 초기 상태: 학생 한 명이 있는 DB, 같은 ID의 새 입력
- 수행 동작: Add를 다시 수행하고 결과와 DB를 조회한다.
- 기대 behavior: 정한 거부 또는 갱신 정책이 일관되게 적용되며 충돌하는 ID가 중복 저장되지 않는다.
- 검증 이유: 중복 검사와 결과 보고를 확인한다.
- 관련 milestone: Milestone 1, Milestone 2

### T-005 — 찾은 학생 검색

- Test ID: T-005
- 목적: 검색 성공과 데이터 보존을 확인한다.
- 입력 또는 초기 상태: 서로 다른 학생 여러 명이 있는 DB
- 수행 동작: 존재하는 검색 키로 Search를 수행한다.
- 기대 behavior: 해당 학생의 정보가 나오고 DB가 변경되지 않는다.
- 검증 이유: 검색 기준과 조회 전용 contract를 확인한다.
- 관련 milestone: Milestone 3

### T-006 — 없는 학생 검색

- Test ID: T-006
- 목적: 검색 실패를 다른 오류와 구분한다.
- 입력 또는 초기 상태: 학생이 있는 DB, 존재하지 않는 검색 키
- 수행 동작: Search를 수행한다.
- 기대 behavior: 찾지 못함이 보고되고 다른 학생은 유지된다.
- 검증 이유: 범위 끝까지 찾지 못한 경로를 확인한다.
- 관련 milestone: Milestone 3

### T-007 — 삭제 후 상태

- Test ID: T-007
- 목적: 수정 뒤 레코드와 크기 일관성을 확인한다.
- 입력 또는 초기 상태: 서로 다른 학생 여러 명이 있는 DB
- 수행 동작: 중간 학생을 Delete하고 목록과 남은 학생을 검색한다.
- 기대 behavior: 삭제한 학생만 사라지고 남은 학생의 정보가 유지된다.
- 검증 이유: 이동·크기 갱신에 따른 상태 오염을 발견한다.
- 관련 milestone: Milestone 3, Milestone 4

### T-008 — 없는 대상 삭제와 마지막 삭제

- Test ID: T-008
- 목적: Delete의 실패와 빈 상태 전환을 확인한다.
- 입력 또는 초기 상태: 학생 한 명이 있는 DB
- 수행 동작: 없는 학생을 삭제한 다음 유일한 학생을 삭제한다.
- 기대 behavior: 첫 요청은 DB를 바꾸지 않고, 두 번째 뒤에는 빈 DB가 된다.
- 검증 이유: 없는 대상과 크기 1에서의 경계를 검증한다.
- 관련 milestone: Milestone 3

### T-009 — 잘못된 입력

- Test ID: T-009
- 목적: 입력 오류 뒤 상태 보존을 확인한다.
- 입력 또는 초기 상태: 유효한 학생이 있는 DB, contract 밖의 학생 정보 또는 명령
- 수행 동작: 잘못된 입력을 제출하고 DB를 다시 조회한다.
- 기대 behavior: 오류가 정상 처리와 구분되고 기존 DB가 오염되지 않는다.
- 검증 이유: 불완전하거나 유효하지 않은 레코드의 유입을 막는다.
- 관련 milestone: Milestone 1, Milestone 2

### T-010 — 정렬

- Test ID: T-010
- 목적: 선택한 정렬 기준과 보존 조건을 확인한다.
- 입력 또는 초기 상태: 정렬 기준에 대해 섞인 순서의 여러 학생
- 수행 동작: Sort한 뒤 List와 Search를 수행한다.
- 기대 behavior: 정의한 순서·동률 정책대로 나열되며 모든 학생의 정보가 유지된다.
- 검증 이유: 비교·교환 오류와 정렬 중 레코드 손실을 발견한다.
- 관련 milestone: Milestone 4

### T-011 — Save와 Load

- Test ID: T-011
- 목적: 명시한 파일 형식의 왕복을 확인한다.
- 입력 또는 초기 상태: 빈 DB, 단일 DB, 여러 학생 DB를 각각 독립적으로 준비
- 수행 동작: 각 상태를 Save하고 새 상태에 Load한다.
- 기대 behavior: 각 경우의 학생 수와 문서화한 필드가 보존된다.
- 검증 이유: 빈 파일·단일·복수 레코드의 파일 경계를 확인한다.
- 관련 milestone: Milestone 5

### T-012 — 손상된 파일

- Test ID: T-012
- 목적: Load의 파싱 실패를 확인한다.
- 입력 또는 초기 상태: 정한 형식에 맞지 않거나 중간에 끊긴 파일
- 수행 동작: Load를 시도하고 이후 DB를 조회한다.
- 기대 behavior: 실패가 보고되고 DB는 문서화한 실패 시 상태를 유지한다.
- 검증 이유: 부분 읽기를 묵시적으로 성공으로 처리하는 결함을 발견한다.
- 관련 milestone: Milestone 5, Milestone 6

### T-013 — 파일 접근 오류

- Test ID: T-013
- 목적: 읽기·쓰기 경로의 파일 오류를 확인한다.
- 입력 또는 초기 상태: 선택한 파일 경로에 대해 접근이 불가능한 상황
- 수행 동작: Load와 Save의 오류 상황을 각각 재현한다.
- 기대 behavior: 각 실패가 성공과 구분되고 DB 및 기존 파일은 정의한 정책대로 유지된다.
- 검증 이유: 열기·읽기·쓰기 실패를 누락하지 않도록 한다.
- 관련 milestone: Milestone 5, Milestone 6

### T-014 — 수정 후 재실행

- Test ID: T-014
- 목적: 시작 시 복원과 종료 후 데이터 유지를 확인한다.
- 입력 또는 초기 상태: 서로 다른 학생이 저장된 DB
- 수행 동작: 실행해 Add·Delete를 수행하고 정책에 따라 Save·종료한 뒤 다시 실행한다.
- 기대 behavior: 시작 시 수정 후의 저장된 상태가 복원되고 삭제한 학생은 돌아오지 않는다.
- 검증 이유: 메모리 상태만 바뀌고 파일이 갱신되지 않는 오류를 발견한다.
- 관련 milestone: Milestone 5, Milestone 6

### T-015 — 첫 실행과 종료 정리

- Test ID: T-015
- 목적: 저장 파일이 없는 시작과 종료 시 자원 정리를 확인한다.
- 입력 또는 초기 상태: 저장 파일이 없는 첫 실행
- 수행 동작: 시작한 뒤 정의한 종료 요청을 수행하고 자원 상태를 확인한다.
- 기대 behavior: 첫 실행이 파일 오류와 구분되며 종료 후 소유한 메모리·파일 자원이 남지 않는다.
- 검증 이유: 초기 상태 오판과 누수·이중 해제를 확인한다.
- 관련 milestone: Milestone 6

### T-016 — warning 없는 다중 파일 build

- Test ID: T-016
- 목적: 공개 interface와 translation unit 연결을 확인한다.
- 입력 또는 초기 상태: 모든 source·header가 준비된 clean 상태
- 수행 동작: 모든 필요한 translation unit을 `gcc -std=c17 -Wall -Wextra -Wpedantic -Werror` baseline으로 build한다.
- 기대 behavior: compile·link error와 warning 없이 실행 파일이 생성된다.
- 검증 이유: 선언·정의 불일치, 중복 정의, 누락된 link와 warning을 확인한다.
- 관련 milestone: Milestone 6
