## 준비

이 디렉터리에서 학습자가 직접 작성할 파일 이름은 **`part1_review.c`**다. 이 README와 노트는 완성 답안 소스를 제공하지 않는다. Part 1 밖의 변수, 입력, 조건문, 반복문은 사용하지 않는다.

이식성 비교에는 ASCII 문구를 사용한다. 한글 문구를 직접 쓰면 컴파일러의 문자 집합·인코딩과 터미널 표시 지원에 의존한다는 점을 기록한다.

**[GNU/Linux 구현]** 저장소의 `C/`에서 다음처럼 이동하고, 편집기로 `part1_review.c`를 직접 작성한다.

```sh
cd exercises/01-program-structure/1-8
gcc -std=c17 -Wall -Wextra -pedantic part1_review.c -o part1_review
./part1_review
printf 'run status=%s\n' "$?"
```

**[GCC 구현]** 빌드 명령의 경고·진단은 GCC 버전과 옵션에 따라 달라질 수 있다. 빌드가 실패하면 오래된 `part1_review`를 실행하지 말고 먼저 소스를 고친다.

## 필수 과제

- **목적:** Part 1의 기본 구조, 출력, 이스케이프 시퀀스, 종료, 주석·들여쓰기를 하나의 학습자 작성 프로그램으로 통합하고 검토한다.
- **해야 할 일:** `part1_review.c`에 `<stdio.h>`와 `int main(void)`를 작성한다. 이름, 관심 분야, C를 배우는 이유, 좋아하는 문장 하나를 네 줄 이상으로 정한 순서대로 출력한다. 실제 필요한 위치에 `\n`과 `\t`, `\"`, `\\` 중 하나 이상을 사용한다. `//`와 비중첩 `/* ... */` 주석을 각각 하나 이상 넣고, 모든 호출 문장을 세미콜론으로 끝내며, 한 가지 들여쓰기 규칙을 유지한다. `return 0;`으로 끝낸 뒤 빌드 상태, 실행 상태, 항목·순서를 기록한다.
- **사용할 개념:** `#include <stdio.h>`, `int main(void)`, statement·중괄호·세미콜론, `printf`, 문자열 리터럴, `\n`·`\t`·`\"`·`\\`, `return 0;`, `//`, `/* ... */`, 들여쓰기.
- **예상 관찰 결과:** 정한 순서의 네 줄 이상이 출력되고 주석은 출력되지 않으며 정상 실행은 성공 상태로 끝난다. 탭의 화면 폭은 **[GNU/Linux 구현]**의 터미널 관찰이다.
- **확인 포인트:** `<stdio.h>`에 세미콜론을 붙이지 않았는가? `main`의 중괄호와 각 `printf`의 괄호·큰따옴표·세미콜론이 짝인가? 문자열 안 주석처럼 보이는 기호를 정확히 출력하는가? 들여쓰기와 실제 블록 문법을 구별했는가? 성공 상태와 요구한 출력이 모두 맞는가?
