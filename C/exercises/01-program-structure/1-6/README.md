# Step 1-6 실습: `return 0`과 종료 상태

이론: [1-6 `return 0`과 종료 상태](../../../notes/01-program-structure/1-6-return-zero-exit-status.md)

완성 소스는 제공하지 않는다. 이 디렉터리에 학습자 본인이 `return_zero.c`를 작성한다.

## 준비

`C/` 디렉터리에서 시작한다.

```sh
cd exercises/01-program-structure/1-6
gcc --version
```

이후 명령은 이 실습 디렉터리에서 실행한다. 셸의 종료 상태 표시는 GCC/Linux 환경에서의 관찰이다.

## 필수 실습: 출력 없는 성공 종료 확인

- **목적:** 초기 `main`의 `return 0;`과 셸에서 관찰하는 성공 종료 상태를 연결한다.
- **해야 할 일:** `return_zero.c`에 출력 함수 없이 초기 `main`이 `return 0;`으로 끝나는 C17 프로그램을 직접 작성한다. 빌드하고 실행한 뒤, 다른 명령을 실행하기 전에 `$?`를 기록한다. 출력이 없어도 성공 종료할 수 있는 이유를 한 문장으로 쓴다.
- **사용할 개념:** 초기 `main`, `int`, `return 0;`, 성공 종료, `$?`.
- **예상 관찰 결과:** 일반적인 GCC/Linux 셸에서는 화면 출력 없이 프로그램이 끝나고 직후 상태가 `0`으로 보인다. 이는 C 정수 값의 바이트가 운영체제에 그대로 전달되었다는 증거가 아니다.
- **확인 포인트:** `return 0;`을 단순한 프로그램 중지로 설명하지 않았는가? 초기 `main`의 반환이 `exit(0)`과 동등함을 기록했는가? `$?`를 즉시 읽었는가?

```sh
gcc -std=c17 -Wall -Wextra -pedantic return_zero.c -o return_zero
printf 'build status=%s\n' "$?"
./return_zero
printf 'run status=%s\n' "$?"
```

`run status`는 `./return_zero` 직후의 상태를 출력한다. 실행과 상태 확인 사이에 다른 명령을 넣지 않는다.

## 기록할 내용

| 관찰 항목 | 기록 |
|---|---|
| 빌드 명령의 직후 상태 | |
| 프로그램의 표준 출력 | |
| 실행 직후 상태 | |
| `return 0;`의 의미 | |
| 이 환경 관찰로 일반화할 수 없는 점 | |

호스트가 실제로 사용하는 종료 상태 표현과 셸이 표시하는 값은 구현과 환경에 따라 달라질 수 있다.

## 추가 실습

- ★ 별도 파일에서 초기 `main`의 마지막 `}`에 도달하는 C99 이후 형태를 작성하고 `return 0;` 형태와 비교한다.
- ★ 프로그램 실행 뒤 `$?`를 기록하고, 이어서 다른 성공 명령을 실행한 뒤 다시 `$?`를 기록한다. 두 값의 대상이 무엇인지 설명한다.
- ★★ 별도 연습 파일에서 0이 아닌 값을 반환하고 이 셸에서 보이는 상태를 기록한다. 이를 모든 호스트의 동일한 상태 표현으로 일반화하지 않는다.

## 완료 기준

- [ ] `return_zero.c`를 직접 작성했다.
- [ ] 출력과 종료 상태를 별도로 기록했다.
- [ ] 실행 직후 `$?`를 읽었다.
- [ ] 초기 `main`의 반환이 `exit(값)`과 동등함을 설명했다.
- [ ] C99 이후 초기 `main` 끝 도달이 `return 0;`과 동등함을 설명했다.
