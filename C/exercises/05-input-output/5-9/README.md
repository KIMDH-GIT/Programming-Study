# 5-9 실습: 부동소수점 입력

이론: [5-9 note](../../../notes/05-input-output/5-9-floating-input-formats.md)

## 실습 목적
세 입력 서식과 포인터형을 정확히 맞춘다.

## 작성할 파일
`floating_input.c`

## 해야 할 일

1. 다음 초기값으로 객체를 선언한다.
   - `float a = -1.0F`
   - `double b = -2.0`
   - `long double c = -3.0L`
2. 입력 `%f %lf %Lf`와 각 객체의 주소를 사용해 세 값을 읽는다.
3. `matched`, `a`, `b`, `c`를 각각 알맞은 출력 서식으로 소수 둘째 자리까지 출력한다.
4. 정상 입력, 두 번째 변환의 matching failure, 첫 변환의 matching failure를 각각 새 프로세스로 실행한다.
5. 각 실행에서 반환값과 바뀐 객체·초기값을 유지한 객체를 기록한다.

## 사용할 개념
입력 `%f`·`%lf`·`%Lf`, 출력 `%f`·`%Lf`, `float *`, `double *`, `long double *`, assignment count.

## 컴파일 방법

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror floating_input.c -o floating_input
```

## 실행 방법

정상 입력:

```sh
printf '%s\n' '1.25 2.5 3.75' | ./floating_input
```

두 번째 변환의 matching failure:

```sh
printf '%s\n' '1.25 nope 3.75' | ./floating_input
```

첫 변환의 matching failure:

```sh
printf '%s\n' 'nope 2.5 3.75' | ./floating_input
```

## 예상 관찰 결과

| 사례 | `matched` | `a` | `b` | `c` |
|---|---:|---:|---:|---:|
| `1.25 2.5 3.75` | 3 | 1.25 | 2.50 | 3.75 |
| `1.25 nope 3.75` | 1 | 1.25 | -2.00 | -3.00 |
| `nope 2.5 3.75` | 0 | -1.00 | -2.00 | -3.00 |

중간 변환이 실패하면 뒤 변환은 진행되지 않는다. 출력에서 `float a`는 기본 인수 승격으로 `double`이 되어 `%f`와 맞지만, 입력에서는 `float *`가 필요하므로 `%f`를 사용한다.

## 확인 포인트

- 입력 서식과 주소형이 맞는가?
- 출력 규칙과 구별했는가?
- 반환값과 실제 변경된 객체 수가 일치하는가?
- 두 번째 변환 실패 뒤 `b`와 `c`가 초기값을 유지하는가?
- 입력 `%lf`와 출력 `%f`를 같은 규칙으로 설명하지 않았는가?

## 추가 실습

- ★ **기초:** 세 객체에 같은 값 `1.5`를 입력해 포인터형만 다른 이유를 설명한다.
- ★★ **응용:** 긴 소수를 입력하고 세 저장형의 출력 결과를 비교한다.
- ★★★ **도전:** 형별 정밀도를 기록한다.

## 완료 기준

- [ ] strict C17 옵션과 `-Werror`에서 진단 없이 compile된다.
- [ ] 세 실행 사례를 모두 기록했다.
- [ ] 정상 입력에서 `matched=3`과 세 기대값을 확인했다.
- [ ] 두 번째 실패에서 `matched=1`, `b=-2.00`, `c=-3.00`을 확인했다.
- [ ] 첫 실패에서 `matched=0`과 세 초기값 유지를 확인했다.
- [ ] 입력 세 지정이 요구하는 포인터형을 정확히 설명했다.
- [ ] 출력에서 `float`가 `%f`와 맞는 기본 인수 승격을 설명했다.
- [ ] 답안 소스를 제공하지 않았다.
