# Step 0-8 실습: 단계별 오류 구분

이론: [0-8 단계별 오류 구분](../../../notes/00-compilation/0-8-build-errors.md).

## 준비

**[GCC/Linux 구현]** GCC와 GNU 어셈블러·링커를 사용하는 Linux 환경 기준이다. 저장소의 `C/`에서 이동하고 노트의 정상 기준 예제를 `hello.c`로 직접 작성한다.

```sh
cd exercises/00-compilation/0-8
gcc -std=c17 -Wall -Wextra -pedantic hello.c -o hello && ./hello
gcc -std=c17 -c hello.c -o hello.o
```

각 명령의 성공을 확인한다. 상태를 남길 때는 바로 다음 명령을 실행한다.

```sh
printf 'status=%s\n' "$?"
```

## 필수 과제

- **목적:** 각 결함이 처음 드러나는 도구 단계를 증거로 구분한다.
- **해야 할 일:** 매 실험마다 정상 소스의 새 복사본을 만들고 노트 4절의 해당 결함 하나만 적용한다. 아래 검사 명령을 실행하고 첫 관련 진단과 직후 상태를 적는다. 마지막에 결함 복사본 하나를 정상으로 되돌려 같은 검사가 성공하는지 확인한다.
- **사용할 개념:** 전처리, 문법, 제약 조건, 어셈블, 선언·정의, 외부 심볼, 링크.
- **예상 관찰 결과:** 의도한 단계에서 실패한다. 정의 누락 실험은 오브젝트 생성과 링크 결과가 서로 다르다. 정확한 진단 문장은 환경마다 달라질 수 있다.
- **확인 포인트:** 결함을 겹치지 않았는가? 실제로 실패한 명령을 적었는가? 실패 뒤 다음 단계나 오래된 결과물을 실행하지 않았는가?

아래는 **각 파일을 노트에 따라 준비한 후 개별 실행할 검사 명령**이다. 한꺼번에 붙여 넣어 앞 실험의 상태를 잃지 않는다. 완성된 결함 소스나 수정 정답은 제공하지 않는다.

| 준비할 실험 파일 | 할 일 | 검사 명령 |
|---|---|---|
| `preprocess.c` | 명시적인 전처리 진단 지시문 추가 | `gcc -E preprocess.c -o preprocess.i` |
| `syntax.c` | 호출 문장의 세미콜론 하나 삭제 | `gcc -std=c17 -S syntax.c -o syntax.s` |
| `constraint.c` | 반환식에서 선언되지 않은 이름 사용 | `gcc -std=c17 -pedantic-errors -S constraint.c -o constraint.s` |
| `bad.s` | 노트의 GNU as 오류 지시문을 직접 작성 | `gcc -c bad.s -o bad.o` |
| `missing.c` | 선언만 있는 외부 함수를 호출하고 정의는 제공하지 않기 | `gcc -std=c17 -c missing.c -o missing.o` |
| `missing.o` | 위 오브젝트 생성 성공을 확인한 뒤 링크 | `gcc missing.o -o missing` |
| 정상 `hello.o` | 동일 오브젝트를 두 번 명시적으로 입력 | `gcc hello.o hello.o -o duplicate` |

## 빈 기록표

각 실험에 한 행씩 작성한다. 정의 누락 실험은 성공한 오브젝트 생성도 함께 기록한다.

| 변경 내용 | 실행 명령 | 마지막 성공 단계 | 첫 실패 단계 | 첫 관련 진단 | 직후 상태 |
|---|---|---|---|---|---|
| | | | | | |

## 추가 과제

- ★ 서로 다른 복사본에서 출력만 변경한 경우와 반환값만 1로 바꾼 경우를 비교한다. 출력과 종료 상태를 별도로 기록하고 논리 오류와 프로그램이 보고한 비성공 상태를 구별한다.
- ★★ 정상 실행 파일의 **별도 복사본**에만 실행 권한을 제거해 실행 요청 실패를 관찰한다. 예를 들어 복사본을 `permission-demo`로 만들었다면 `chmod a-x permission-demo`, `./permission-demo`, `chmod u+x permission-demo` 순서로 작업하되 실행 직후 상태를 먼저 기록한다. 이는 Linux 권한 실험이지 동적 로더 실험이 아니다.

## 완료 기준과 안전 범위

전처리, C 문법·제약 조건, 어셈블러, 링커 정의 누락·중복 정의를 구분한 기록이 있어야 한다. 노트의 로딩 실패·실행 중 실패·논리 오류 설명도 각 한 문장으로 요약한다. 로더와 공유 라이브러리는 시스템에서 제거하거나 수정하지 않는다. 충돌 재현을 위해 정의되지 않은 동작을 작성하지 않는다. 셸 메시지와 종료 상태는 **[GCC/Linux 구현]** 관찰로 적는다.
