# Step 0-5 실습: 어셈블러와 `.o`

이론: [어셈블러와 `.o` 파일](../../../notes/00-compilation/0-5-assembler.md)

## 준비

- GCC와 GNU Binutils의 `readelf`, `nm`, `objdump`가 있는 GNU/Linux 환경을 사용한다.
- 이 디렉터리에서 노트의 최소 예제를 직접 입력해 `unit.c`로 저장한다. 완성 소스와 정답 출력은 제공하지 않는다.
- 이미 존재하는 파일은 덮어쓰지 않도록 이름을 조정한다.
- **[C 표준]**은 ELF 목적 파일을 요구하지 않는다. 아래 ELF/도구 출력 및 x86-64 재배치 이름은 모두 **[GCC/Linux 구현: GNU/Linux 관찰]**이다.

## 필수 실습: 기계어와 연결 정보

- **목적:** 목적 파일 안의 코드와 섹션/심벌/재배치 정보를 구별한다.
- **해야 할 일:** 두 경로로 목적 파일을 만든다. 조사 도구를 실행하여 파일 형식, 코드/데이터 섹션, `main`과 `puts`의 상태, 재배치 참조를 기록한다.
- **사용할 개념:** `-c`, 재배치 가능 목적 파일, 섹션, 심벌, 재배치, 역어셈블
- **예상 관찰 결과:** `.o`는 일반적으로 ELF 재배치 가능 파일이며 외부 참조를 남겨 둔 상태로 생성된다. 출력 주소, 섹션 개수, 재배치 종류는 시스템에 따라 다르다.
- **확인 포인트:** 미정의 심벌을 컴파일 실패와 혼동하지 않는다. 재배치 하나를 골라 어떤 대상에 대한 후속 계산 정보인지 설명한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -S unit.c -o unit.s
gcc -c unit.s -o unit.o
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -c unit.c -o unit-direct.o
readelf -h unit.o
readelf -S unit.o
nm unit.o
readelf -r unit.o
objdump -dr unit.o
```

관찰 기록은 다음 항목으로 나눈다. 값은 직접 도구 출력에서 찾아 적는다.

| 항목 | 기록할 내용 |
|---|---|
| ELF 헤더 | 파일 종류와 대상 기계 |
| 섹션 | 코드 또는 데이터와 관련된 이름 및 역할 |
| 심벌 | 정의된 이름과 외부 정의가 필요한 이름 |
| 재배치 | 참조 대상과 후속 계산이 필요한 이유 |
| 역어셈블 | 원래 `.s`와 달리 기계어를 해석한 출력이라는 근거 |

`.o`는 텍스트 파일이 아니므로 `cat` 대신 조사 도구를 사용한다. 이번 Step에서 `.o`를 직접 실행하거나 실행 권한을 바꿀 필요는 없다.

## 추가 실습

- **★:** `nm unit-direct.o`를 실행하여 `unit.o`와 핵심 정의/참조를 비교한다. 파일 전체의 동일성은 요구하지 않는다.
- **★★:** `unit.c`의 복사본을 `unit-no-call.c`로 만들고 `puts` 호출 한 줄을 제거한다. 다음 명령으로 원본과 다른 이름의 `.o`를 만든 뒤 심벌과 재배치를 비교한다. 호출을 없애도 모든 재배치가 사라져야 하는 것은 아니다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -c unit-no-call.c -o unit-no-call.o
nm unit-no-call.o
readelf -r unit-no-call.o
```

## 완료 체크

- [ ] `.c` 입력의 `-c`와 `.s` 입력의 `-c`가 수행하는 단계를 설명했다.
- [ ] 섹션, 심벌, 재배치를 별도 개념으로 기록했다.
- [ ] 역어셈블 출력의 주소를 실행 중 가상 주소라고 단정하지 않았다.
- [ ] 외부 심벌 정의를 연결할 다음 단계가 무엇인지 답했다.
- [ ] 노트의 확인 문제를 풀고 해설과 비교했다.
