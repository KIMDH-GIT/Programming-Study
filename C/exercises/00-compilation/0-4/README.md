# Step 0-4 실습: 컴파일러와 `.s`

이론: [컴파일러와 `.s` 파일](../../../notes/00-compilation/0-4-compiler.md)

## 준비

- GCC가 있는 GNU/Linux 환경에서 이 디렉터리를 작업 위치로 사용한다.
- 노트의 최소 예제를 직접 입력하여 `hello.c`로 저장한다. 이 문서는 완성 소스나 정답 산출물을 제공하지 않는다.
- 기존 학습 파일이 있다면 덮어쓰지 않도록 작업용 이름을 정하고 아래 명령의 입력/출력 이름을 함께 바꾼다.
- C 코드는 C17 예제이며 아래 셸 명령과 어셈블리 관찰은 **[GCC/Linux 구현]**이다. ISA나 `.s` 형식은 **[C 표준]**의 보장이 아니다.

## 필수 실습: 두 입력 경로 관찰

- **목적:** 전처리된 C와 어셈블리 소스를 구별하고 `-S`의 정지 지점을 확인한다.
- **해야 할 일:** 아래 명령을 실행한 뒤 편집기로 두 `.s`를 연다. 함수 이름, 문자열, 외부 함수 참조를 찾아 각각 어떤 역할인지 기록한다.
- **사용할 개념:** 전처리, 번역 단위, 좁은 의미의 컴파일, `-S`, 어셈블러 지시문
- **예상 관찰 결과:** 읽을 수 있는 `.s`가 생기고 프로그램 자체는 실행되지 않는다. 환경에 따라 어셈블리 철자와 배치가 달라진다.
- **확인 포인트:** 명령 실행 전후 파일 목록을 비교한다. 새 목적 파일이나 실행 파일이 없는 이유를 설명하고 문자열이 데이터로 들어 있는 것과 실행 출력의 차이를 쓴다.

```sh
pwd
ls
gcc --version
gcc -dumpmachine
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -S hello.c -o hello.s
gcc -std=c17 -E hello.c -o hello.i
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -S hello.i -o hello-from-i.s
ls
less hello.s
less hello-from-i.s
```

`less`는 `q`로 종료한다. 두 파일의 바이트 단위 일치는 통과 조건이 아니다. 경로 등 메타데이터가 달라질 수 있다. x86-64에서 보이는 `call` 같은 명령어 철자를 다른 대상에도 기대하지 않는다.

## 추가 실습

- **★:** 문자열만 바꾼 복사본으로 `.s`를 생성하고 데이터가 바뀐 곳을 찾는다.
- **★★:** 다음 명령으로 최적화 수준을 바꿔 비교한다. 결과가 반드시 짧아지거나 특정 줄이 반드시 사라진다고 가정하지 않는다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -O2 -S hello.c -o hello-O2.s
diff -u hello.s hello-O2.s
```

`diff`의 종료 상태 1은 차이가 있다는 뜻이며 컴파일 실패가 아니다. 원래 C가 뜻하는 출력 동작이 유지되어야 한다는 기준으로 차이를 해석한다.

## 완료 체크

- [ ] GCC 버전과 대상 정보를 기록했다.
- [ ] `.i`와 `.s`의 언어와 생성 단계를 구별했다.
- [ ] 어셈블러 지시문과 CPU 명령어가 다름을 설명했다.
- [ ] `.s`를 실행하거나 실행 권한으로 문제를 해결하려 하지 않았다.
- [ ] 노트의 확인 문제에 답한 뒤 접힌 해설과 비교했다.
