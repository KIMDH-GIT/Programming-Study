# Step 0-6 실습: 링커·라이브러리와 실행 파일

이론: [링커·라이브러리와 실행 파일](../../../notes/00-compilation/0-6-linker-and-libraries.md)

## 준비

- GCC, GNU Binutils와 C 라이브러리 개발 환경이 설치된 GNU/Linux를 사용한다.
- 이 디렉터리에서 노트의 최소 예제를 직접 입력해 `hello.c`로 저장한다.
- 기존 파일이 있다면 이름을 바꾸어 보존한다. 완성 소스, 정답용 `.o`, 실행 파일은 이 안내에 포함하지 않는다.
- 예제의 호스트 환경 C 코드는 **[C 표준]**에 따른다. ELF, `readelf`, `nm`, `.a`, `.so`, 시작 코드의 이름은 **[GCC/Linux 구현: GNU/Linux 관찰]**이다.

## 필수 실습: 별도로 링크하고 실행하기

- **목적:** 목적 파일 생성, 링크, 프로그램 실행의 경계를 관찰한다.
- **해야 할 일:** 아래 명령을 실행한다. 목적 파일의 외부 참조를 조사하고, 생성된 실행 파일의 종류와 동적 의존성을 확인한다. 실행 출력과 바로 뒤의 종료 상태를 기록한다. GCC의 하위 명령 표시에서 시작 코드와 기본 라이브러리에 관련된 입력을 찾아본다.
- **사용할 개념:** GCC 드라이버, 심벌 해결, libc, 공유 라이브러리 의존성, 시작 코드, 프로세스 실행
- **예상 관찰 결과:** 링크 이후 실행 가능한 파일이 생긴다. 프로그램 실행 시에만 예제 문자열이 출력된다. 일반적인 동적 연결 환경에서는 실행 파일에 공유 라이브러리 의존성이 기록된다.
- **확인 포인트:** 헤더의 선언, 목적 파일의 미정의 참조, 라이브러리의 정의를 연결해 설명한다. `DYN`만 보고 라이브러리라고 단정하지 않는다. 환경의 연결 방식은 실제 도구 출력으로 판단한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -c hello.c -o hello.o
nm hello.o
gcc hello.o -o hello
readelf -h hello
readelf -l hello
readelf -d hello
gcc -### hello.o -o hello
./hello
echo $?
```

`gcc -###`는 실제 명령을 수행하지 않는 조사 옵션이며 주로 표준 오류로 출력한다. `echo $?`는 반드시 `./hello` 바로 뒤에서 실행한다. 정적 연결 환경이라면 동적 섹션이 없을 수 있으므로 특정 `NEEDED` 항목의 존재를 모든 환경의 통과 조건으로 삼지 않는다.

## 추가 실습

### ★ 헤더 비교

```sh
readelf -h hello.o
readelf -h hello
```

파일 종류와 진입점 필드를 비교한다. 실행 파일의 진입점이 C의 `main` 주소라는 보장이 있는지 노트를 근거로 답한다.

### ★★ 사용자 정적 라이브러리 연결

이 실습은 C 라이브러리 전체를 정적으로 연결하는 작업이 아니다. 아래 요구 사항을 만족하는 두 소스를 직접 작성한 뒤 명령을 실행한다. 이 안내는 완성 소스를 제공하지 않는다.

1. `greet.c`: `<stdio.h>`를 사용하고 `void greet(void)`를 정의한다. 함수 안에서 `puts`로 짧은 인사말을 출력한다.
2. `main.c`: `void greet(void);`를 선언하고 `int main(void)`에서 호출한다. 성공 종료 값을 반환한다.
3. 두 파일을 따로 컴파일하고 `greet.o`만 아카이브에 넣는다.
4. 아카이브를 명시하여 링크하고 실행한다. 최종 파일의 libc 의존성이 남는지 조사한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -c greet.c -o greet.o
gcc -std=c17 -Wall -Wextra -Wpedantic -c main.c -o main.o
ar rcs libgreet.a greet.o
ar t libgreet.a
gcc main.o ./libgreet.a -o app
./app
readelf -d app
```

아카이브가 그 안의 함수를 참조하는 목적 파일보다 뒤에 위치한 이유를 설명한다. 같은 디렉터리에 `libgreet.so`가 없다면 `gcc main.o -L. -lgreet -o app-by-name`도 비교할 수 있다. `-L`는 링크 시 검색 경로이며 실행 시 공유 라이브러리 검색 경로가 아니다. `.so` 직접 제작이나 `-static` 실험은 요구하지 않는다.
