# Step 0-1 실습: 전체 컴파일 과정 개요

이론: [0-1 전체 컴파일 과정 개요](../../../notes/00-compilation/0-1-compilation-overview.md)

완성 소스나 정답 표는 제공하지 않는다. C17 코드와 관찰 기록을 직접 작성한다. 아래 명령은 GCC/Linux용이며 ISO C 표준의 명령이 아니다.

## 준비

`C/` 디렉터리에서 시작한다.

```sh
cd exercises/00-compilation/0-1
gcc --version
```

편집기로 `hello.c`를 만들고 노트의 최소 예제를 직접 입력한다. 출력 문구를 자신이 선택한 ASCII 문구로 변경한다. 이하 명령은 이 실습 디렉터리에서 실행한다.

## 필수 실습: 단계별 산출물 기록

- **목적:** 같은 소스가 번역 과정에서 어떤 표현으로 바뀌는지 확인한다.
- **해야 할 일:** 아래 명령을 한 줄씩 실행하고 성공 여부를 확인한다. 각 산출물의 이름, 생성 명령, 텍스트 여부, 역할을 자신의 기록 표에 채운다. 실패하면 먼저 오류를 해결하고 다음 명령으로 넘어간다.
- **사용할 개념:** 전처리, 컴파일, 어셈블, 링크, 빌드와 실행의 구별.

```sh
gcc -std=c17 -Wall -Wextra -pedantic -E hello.c -o hello.i
gcc -std=c17 -Wall -Wextra -pedantic -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello
./hello
ls -l hello.c hello.i hello.s hello.o hello
file hello.c hello.i hello.s hello.o hello
```

`file`은 Linux 파일 형식 판별 도구다. 없다면 텍스트 파일 열람과 생성 명령으로 역할을 확인한다. 바이너리인 `.o`와 실행 파일을 `cat`으로 터미널에 출력하지 않는다. `.i`와 `.s`는 편집기나 `less`로 열며 세부 어셈블리 해독은 요구하지 않는다.

별도 이름으로 전체 빌드를 수행한다.

```sh
gcc -std=c17 -Wall -Wextra -pedantic hello.c -o hello-direct && ./hello-direct
```

- **예상 관찰 결과:** 텍스트 산출물과 바이너리 산출물이 구별되고 두 빌드 경로의 프로그램 출력이 일치한다. 단계별 GCC 명령 자체는 프로그램의 인사말을 출력하지 않는다.
- **확인 포인트:** `-o`가 단계 선택 옵션이 아님을 설명할 수 있는가? `.o`와 실행 파일을 구별했는가? 출력의 일치와 바이너리 파일의 바이트 단위 일치를 혼동하지 않았는가?

## 추가 실습

- ★ 실행 파일 이름을 바꿔 빌드하고 실행한다. 파일 이름과 소스 의미의 관계를 기록한다.
- ★★ `gcc -### -std=c17 hello.c -o hello`를 실행하고 표시된 내부 도구 호출을 분류한다. 이 옵션은 실제 빌드를 수행하지 않으며 출력은 표준 오류로 간다.

## 완료 기준

- [ ] 다섯 종류의 파일과 단계별 명령을 자기 말로 연결했다.
- [ ] 두 빌드 경로로 만든 프로그램의 실제 출력을 비교했다.
- [ ] ISO C의 추상적 번역 단계와 GCC의 실용 파이프라인이 같지 않음을 설명했다.
- [ ] 노트의 확인 문제를 먼저 답한 뒤 접힌 해설과 비교했다.
