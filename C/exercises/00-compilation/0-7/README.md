# Step 0-7 실습: 전체 빌드와 실행

이론: [0-7 전체 빌드와 실행](../../../notes/00-compilation/0-7-build-and-run.md).

## 준비

- **[GCC/Linux 구현]** Linux 셸과 GCC 개발 환경을 사용한다.
- 저장소의 `C/` 디렉터리를 기준으로 아래 작업 디렉터리로 이동한다.
- 노트의 최소 예제를 읽고 `hello.c`를 직접 작성한다. 이 안내에는 완성 소스를 제공하지 않는다.

```sh
cd exercises/00-compilation/0-7
gcc --version
```

## 필수 과제

- **목적:** 빌드와 실행, 출력과 종료 상태를 나누어 확인한다.
- **해야 할 일:** 아래 절차를 수행하고 문자열을 변경한 뒤 재빌드하여 변화가 반영되는지 기록한다.
- **사용할 개념:** GCC 드라이버, `-o`, 상대 경로, 표준 출력, 셸 `$?`, `&&`.
- **예상 관찰 결과:** 정상 빌드는 보통 텍스트 없이 성공하며 실행은 소스에 지정한 한 줄을 출력한다. 정상 예제의 Linux 실행 상태는 0이다.
- **확인 포인트:** GCC의 상태와 프로그램의 상태를 서로 다른 항목에 적었는가? 실행한 파일이 이번에 만든 파일인가?

다음 두 줄을 차례로 실행한다. 상태 기록 사이에 다른 명령을 넣지 않는다.

```sh
gcc hello.c -o hello
printf 'build status=%s\n' "$?"
```

빌드 상태가 0일 때만 실행한다.

```sh
./hello
printf 'run status=%s\n' "$?"
```

문자열을 수정한 뒤 다음으로 재빌드·실행한다. `&&`는 빌드 성공 시에만 실행한다.

```sh
gcc -std=c17 -Wall -Wextra -pedantic hello.c -o hello && ./hello
```

## 추가 과제

- ★ 노트의 단계별 명령으로 별도의 `hello-staged`를 만들고 출력·상태를 비교한다.
- ★★ 정상 소스의 새 복사본에 문법 결함을 하나 넣어 별도 출력 이름으로 빌드를 시도한다. 실패 진단과 기존 정상 실행 파일의 존재를 구별해 기록한다. 실패한 산출물은 실행하지 않는다.

## 완료 기준

직접 작성한 소스, 실행한 명령, 출력, 종료 상태를 보존하고 `-o hello`와 `./hello`의 차이를 자신의 말로 설명한다. 셸·파일 형식·종료 상태의 구체적인 관찰은 **[GCC/Linux 구현]**으로 표시한다. 커밋은 이 실습의 필수 조건이 아니다.
