# 2-9. 구현별 자료형 크기 직접 확인

이론: [2-9. 구현별 자료형 크기 직접 확인](../../../notes/02-variables-and-types/2-9-implementation-type-sizes.md).

## 준비

- C17 호스트 환경과 C 컴파일러를 사용한다. 아래 명령은 **[GCC/Linux 구현]** 예다.
- `C/` 기준으로 아래 디렉터리에 이동한다. `type_report.c`는 학습자가 직접 작성하며 이 README는 완성 답안 소스를 제공하지 않는다.
- 한 환경의 보고서가 필수다. 다른 OS·컴파일러·32-bit 개발 환경 설치는 요구하지 않는다.
- 소스의 출력 항목 이름에는 ASCII 문구를 사용하면 인코딩 차이를 줄일 수 있다. 보고서의 해석은 한국어로 작성한다.

```sh
cd exercises/02-variables-and-types/2-9
gcc --version
gcc -dumpmachine
uname -a
```

`uname`은 호스트 정보이고 `gcc -dumpmachine`은 컴파일러의 설정 대상 정보다. 둘이 모든 대상 옵션과 ABI를 설명하지는 않는다. 전체 빌드 명령과 확인한 ABI 문서도 기록하며, 확인하지 못한 정보는 추측하지 말고 '미확인'으로 둔다.

## 필수 과제

- **목적:** 크기·범위·정밀도를 실제 대상에서 확인하고 결과를 재현할 조건을 남긴다.
- **해야 할 일:** `type_report.c`에서 아래 필수 출력표의 모든 항목을 출력한다. `sizeof` 결과 하나 이상을 `size_t` 변수에 초기화하여 사용한다. `<stdio.h>`, `<stddef.h>`, `<limits.h>`, `<float.h>`를 목적에 맞게 포함하고 `int main(void)`와 `return 0;`을 사용한다. 환경 정보, 빌드와 실행 상태, 실제 출력, 표준 보장 두 개와 구현 관찰 두 개를 기록한다.
- **사용할 개념:** 기본 자료형, 선언·초기화, `sizeof`, `size_t`, `CHAR_BIT`, 정수·실수 한계 매크로, 출력 서식, 컴파일 대상과 ABI.
- **예상 관찰 결과:** 14개 자료형의 크기와 정수·실수 한계가 순서대로 출력된다. 세 char 계열의 크기는 1이다. `int`, `long`, `long double` 등의 구체적 크기와 한계는 대상에 따라 달라질 수 있다. 두 형이 같은 크기여도 오류가 아니다.
- **확인 포인트:** 수치를 문자열에 직접 적지 않았는가? 크기는 `%zu`로 출력했는가? 실수의 `MIN`을 최소 양의 정규화 값으로 해석했는가? 컴파일러·OS·CPU·ABI를 구별했는가? 관찰값을 C17의 고정 규칙이라고 쓰지 않았는가?

### 필수 출력 항목

| 분류 | 포함할 항목 | 서식 힌트 |
|---|---|---|
| 크기 14개 | `char`, `signed char`, `unsigned char`, `short`, `unsigned short`, `int`, `unsigned int`, `long`, `unsigned long`, `long long`, `unsigned long long`, `float`, `double`, `long double`의 `sizeof` | 모두 `%zu` |
| byte 기준 | `(int)CHAR_BIT` | `%d` |
| int 계열 범위 | `INT_MIN`, `INT_MAX`, `UINT_MAX` | `%d`, `%d`, `%u` |
| long 계열 범위 | `LONG_MIN`, `LONG_MAX`, `ULONG_MAX` | `%ld`, `%ld`, `%lu` |
| long long 계열 범위 | `LLONG_MIN`, `LLONG_MAX`, `ULLONG_MAX` | `%lld`, `%lld`, `%llu` |
| 실수 범위 | `FLT_MIN/MAX`, `DBL_MIN/MAX`, `LDBL_MIN/MAX` | 앞의 두 형은 `%e`, 마지막 형은 `%Le` |
| 실수 정밀도 | `FLT_DIG`, `DBL_DIG`, `LDBL_DIG` | `%d` |
| 1 근처 간격 | `FLT_EPSILON`, `DBL_EPSILON`, `LDBL_EPSILON` | `%e`, `%e`, `%Le` |

`INT_MIN/MAX`는 두 매크로 `INT_MIN`과 `INT_MAX`를 뜻하는 설명 표기다. 다른 `/` 표기도 각각의 실제 매크로 이름으로 나누어 쓴다. unsigned 정수형의 최소값은 0이며 별도의 `UINT_MIN` 매크로를 찾지 않는다.

### 작성 순서

1. 노트의 작은 예제를 이해한 뒤 별도 `type_report.c`를 직접 작성한다.
2. 크기 출력, 정수 범위 출력, 실수 특성 출력 순서로 `printf` 문장을 나열한다. 조건문·반복문·배열·포인터·동적 할당은 사용하지 않는다.
3. 형과 출력 서식을 대조하고 아래 명령으로 빌드한다.
4. 성공한 이번 실행 파일의 출력과 상태를 기록한다.
5. 환경 표와 해석 표를 채운다. 전체 저장 bit 수를 종이에 계산했다면 값 bit 수와 같다고 단정하지 않는다.

## 빌드와 실행

한 명령씩 실행하고 상태 출력 사이에 다른 명령을 끼우지 않는다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic type_report.c -o type_report
printf 'build status=%s\n' "$?"
```

빌드 상태가 0일 때만 다음 명령을 실행한다. 실패했다면 오래된 실행 파일을 실행하지 말고 진단을 읽어 수정한다. 경고도 무시하지 않는다.

```sh
./type_report
printf 'run status=%s\n' "$?"
```

성공 상태와 출력 항목의 정확성을 따로 검토한다. `$?`와 위 명령은 Linux 셸 사용법이지 C 문법이 아니다.

## 추가 과제

- ★ **기초:** 크기가 같은 자료형 두 개를 찾아도 서로 다른 형이라는 설명을 붙인다.
- ★★ **응용:** `FLT_RADIX`, 세 실수형의 `*_MANT_DIG`, `*_TRUE_MIN`을 추가해 저장 공간·기수·정밀도·최소 양수를 구별한다. 별표는 실제 매크로 이름으로 풀어 쓴다.
- ★★★ **선택 도전:** 이미 사용 가능한 다른 환경에서 같은 소스를 빌드·실행하여 보고서를 비교한다. 달라진 조건과 관찰만 적고 원인을 무조건 컴파일러 하나로 단정하지 않는다. 도구가 없다면 '미실행'이라고 적으며 필수 완료에는 영향이 없다.

## 완료 기준

- 학습자가 작성한 소스가 경고 없이 빌드되고 이번 실행 파일의 출력·상태를 기록했다.
- 14개 크기, `CHAR_BIT`, 지정한 정수 범위와 실수 특성이 빠짐없이 있다.
- 소스·명령·환경·실제 출력·해석을 함께 보존했다.
- CPU·OS·컴파일러·ABI와 표준 보장·구현 관찰을 구별했다.
- 완성 답안 복사나 후속 문법 없이 작성했다. 커밋과 두 번째 환경 실행은 필수가 아니다.
