# 2-3 실습: `long`, `long long`

이론: [2-3. `long`, `long long`](../../../notes/02-variables-and-types/2-3-long-long-long.md)

완성 답안 소스는 제공하지 않는다. 아래 파일은 학습자가 직접 작성한다. 기준은 C17이며 명령은 GCC가 설치된 Linux 셸용이다. 조건문, 반복문, 배열, 포인터, 동적 메모리, 입력 함수는 필요 없다.

## 준비와 작성 파일

저장소의 `C/`에서 시작한다.

```sh
cd exercises/02-variables-and-types/2-3
gcc --version
```

| 파일 | 구분 | 역할 |
|---|---|---|
| `wide_values.c` | 필수 | 최소 보장 범위 안의 큰 정수 출력 |
| `wide_limits.c` | 필수 | 현재 구현의 `long`, `long long` 한계값 출력 |
| `wide_negative.c` | 추가 ★ | 큰 음수 출력 |
| `wide_choices.c` | 추가 ★★ | 요구 범위에 맞는 자료형 선택 |

각 C 파일은 독립적인 `int main(void)`와 `return 0;`을 갖는다. 출력에는 `<stdio.h>`를 포함한다. 두 필수 파일을 한 실행 파일로 묶지 않는다.

## 필수 과제 A: 큰 정수 저장과 출력

- **목적:** 최소 보장 범위만으로 자료형을 선택하고 그 형에 맞게 출력한다.
- **파일:** `wide_values.c`.
- **해야 할 일:**
  1. `long` 변수 `distance`를 2000000000L로 초기화한다.
  2. `long long` 변수 `population`을 8000000000LL로 초기화한다.
  3. 각 변수를 이름과 함께 한 줄씩 출력한다. `long`은 `%ld`, `long long`은 `%lld`를 사용한다.
  4. `long`의 크기를 8바이트로 가정하지 않고 두 선택의 이유를 기록한다.
- **사용할 개념:** 변수 선언·초기화, `L`/`LL` 접미사, `%ld`/`%lld`, 줄바꿈.
- **예상 관찰 결과:** 정상적인 출력 환경에서 아래 두 줄이다. `long`이 흔한 4바이트인 환경에서도 같은 값이 보존된다.
- **확인 포인트:** 상수의 접미사와 변수 자료형, 서식 지정자를 각각 구별했는가? 80억을 `long`에 넣지 않았는가?

```text
distance=2000000000
population=8000000000
```

## 필수 과제 B: 현재 구현의 한계값

- **목적:** C17 최소 보장과 현재 환경의 실제 한계를 구별한다.
- **파일:** `wide_limits.c`.
- **해야 할 일:** `<limits.h>`를 추가하고 `LONG_MIN`, `LONG_MAX`, `LLONG_MIN`, `LLONG_MAX`를 각각 매크로 이름과 함께 네 줄로 출력한다. 앞의 둘은 `%ld`, 뒤의 둘은 `%lld`를 사용한다. 한계값 매크로를 함수처럼 호출하지 않는다.
- **사용할 개념:** 표준 헤더, 정수 한계 매크로, signed 정수형 범위.
- **예상 관찰 결과:** `long`의 구간은 적어도 -2147483647 ~ 2147483647, `long long`의 구간은 적어도 -9223372036854775807 ~ 9223372036854775807을 포함한다. 두 자료형의 실제 구간이 같아도 정상이다.
- **확인 포인트:** 현재 출력의 정확한 숫자를 표준의 고정값이라고 쓰지 않았는가? `LONG_MAX + 1L`이나 `LLONG_MAX + 1LL` 같은 signed overflow를 실행하지 않았는가?

## 컴파일과 실행

현재 디렉터리에서 각 파일을 별도로 빌드·실행한다. `&&`는 빌드가 성공한 경우에만 실행하는 셸 문법이다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic wide_values.c -o wide_values && ./wide_values
printf 'status=%s\n' "$?"
gcc -std=c17 -Wall -Wextra -Wpedantic wide_limits.c -o wide_limits && ./wide_limits
printf 'status=%s\n' "$?"
```

각 `status`는 직전 연결 명령의 상태다. 빌드에서 멈췄다면 빌드 실패 상태이고, 실행까지 했다면 프로그램 상태다. 경고나 오류가 있다면 원인을 고치고 다시 빌드한다. 실패 뒤 남아 있는 예전 실행 파일을 새 결과로 오해하지 않는다.

## 추가 실습

- ★ **`wide_negative.c`:** `long`과 `long long`에 각각 -2000000000L, -8000000000LL을 넣고 출력한다. 음수 부호까지 보존되는지 확인한다.
- ★★ **`wide_choices.c`:** 필요한 최댓값 30000, 2000000000, 8000000000에 대해 `int`, `long`, `long long` 중 표준 최소 보장 범위로 충분한 첫 자료형을 고른다. 각 변수를 초기화하고 그 형에 맞게 출력한다. 선택 근거를 따로 적는다.
- ★★★ **선택 도전, 관찰 보고서:** 과제 B의 결과를 노트의 LP64/LLP64 사례와 비교한다. 한계값만 보고 정확한 바이트 수나 전체 ABI를 확정하지 않는다. 다른 환경에서 직접 실행하지 않았다면 비교 표의 사례라고 명시한다.

추가 소스의 빌드·실행 명령은 다음과 같다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic wide_negative.c -o wide_negative && ./wide_negative
gcc -std=c17 -Wall -Wextra -Wpedantic wide_choices.c -o wide_choices && ./wide_choices
```
