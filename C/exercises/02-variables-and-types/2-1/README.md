# 2-1. 변수 선언·초기화와 이름 규칙

이론: [2-1. 변수 선언·초기화와 이름 규칙](../../../notes/02-variables-and-types/2-1-variable-declaration-initialization-identifiers.md)

완성 답안 소스는 제공하지 않는다. 요구 사항을 읽고 `inventory.c`를 직접 작성한다.

## 준비

- Linux 셸과 GCC를 사용한다. 아래 이동 명령은 저장소의 `C/`에서 실행한다.
- Part 1의 프로그램 골격, `printf`와 줄바꿈을 사용한다.
- 조건문, 반복문, 배열 선언, 포인터 조작, 동적 메모리 할당은 사용하지 않는다. 이미 배운 출력용 문자열 리터럴은 사용한다.

```sh
cd exercises/02-variables-and-types/2-1
gcc --version
```

## 필수 과제: 현재 재고와 복사한 값

- **목적:** 객체의 초기화와 나중의 대입을 구별하고 값 복사의 독립성을 관찰한다.
- **작성할 파일:** 이 디렉터리의 `inventory.c`.
- **사용할 개념:** `int`, 식별자, 선언·정의, 초기화, 값 복사, 대입, `%d`, `\n`, 빌드와 실행.

### 해야 할 일

1. `<stdio.h>`를 포함하고 `int main(void)`의 본문과 정상 종료를 작성한다.
2. 의미 있는 영문 이름으로 재고를 나타내는 `int` 객체를 선언하고 12로 초기화한다.
3. 두 번째 `int` 객체를 선언하고 첫 객체의 현재 값을 읽어 초기화한다. 숫자 12를 다시 직접 쓰는 대신 값 복사를 사용한다.
4. 첫 객체의 현재 값을 `stock=12` 형태로 한 줄 출력한다.
5. 첫 객체에 9를 대입한다. 같은 이름을 다시 선언하지 않는다.
6. 첫 객체와 두 번째 객체의 현재 값을 각각 `stock=9`, `saved=12` 형태로 출력한다.
7. 모든 줄 끝에 줄바꿈을 넣는다. 숫자는 문자열에 고정하지 않고 `%d`와 해당 객체의 값으로 출력한다.
8. 자신의 코드에서 선언·초기화가 있는 줄, 대입 문장, 값을 읽는 부분을 기록한다.

`%d` 하나에는 `int` 값 하나를 인수로 전달한다. 출력 문자열의 `stock`과 `saved`는 표시용 글자이므로 소스의 식별자와 같을 필요는 없다. 객체의 이름과 화면에 보이는 글자를 구별한다.

## 컴파일

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic inventory.c -o inventory
printf 'build status=%s\n' "$?"
```

상태 확인 전에 다른 명령을 넣지 않는다. 경고와 오류가 있다면 원인을 수정하고 다시 빌드한다. 빌드가 실패했다면 기존 실행 파일이 있어도 실행하지 않는다.

## 실행

빌드 상태가 0임을 확인한 다음 실행한다.

```sh
./inventory
printf 'run status=%s\n' "$?"
```

수정 후 한 번에 확인할 때는 성공한 빌드만 실행하도록 연결한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic inventory.c -o inventory && ./inventory
```

## 예상 관찰 결과

정상 표준 출력 환경에서 프로그램의 출력은 다음 세 줄이다.

```text
stock=12
stock=9
saved=12
```

Linux 셸의 정상 실행 상태는 0이다. 상태를 출력하는 셸의 줄은 위 프로그램 출력 세 줄에 포함하지 않는다. 두 번째 객체는 첫 객체의 별명이 아니라 초기화 당시의 값을 가진 별개 객체다.

## 확인 포인트

- 첫 객체와 두 번째 객체를 각각 한 번만 선언했는가?
- 모든 값을 읽기 전에 초기화 또는 대입으로 정했는가?
- 첫 객체를 바꾸는 문장은 초기화가 아니라 대입임을 설명했는가?
- 식별자가 숫자로 시작하지 않고 키워드나 예약 이름을 피했는가?
- `%d`의 수와 인수 수가 맞고 전달한 값이 `int`인가?
- 결과만 같게 하려고 숫자를 출력 문자열에 직접 적지 않았는가?
- 선언이 저장 공간과 관련된다고 해서 실제 스택 슬롯 하나를 반드시 만든다고 단정하지 않았는가?

## 기록할 내용

| 항목 | 직접 기록 |

| 선택한 두 식별자와 이름을 고른 이유 | |
| 선언·정의·초기화가 함께 있는 줄 | |
| 기존 객체에 대입하는 줄 | |
| 첫 출력 직전 두 객체의 값 | |

| 실행 출력과 종료 상태 | |
| 값 복사와 같은 객체의 별명이 다른 이유 | |

## 추가 과제

- ★ **이름 변경:** 두 식별자를 더 구체적으로 바꾸되 표시 문자열과 숫자는 유지한다. 재빌드 후 세 줄이 같아야 한다.
- ★★ **선언 후 대입:** `inventory-assignment.c`를 작성해 첫 객체의 선언과 첫 대입을 분리한다. 첫 대입 전에는 읽지 않는다. 출력은 같아야 하지만 첫 값 저장의 문법적 분류가 달라짐을 기록한다.
- ★★★ **독립적인 수정:** `inventory-independent.c`를 작성해 마지막에 복사한 객체에 5를 대입한 후 두 객체를 추가 출력한다. 추가 출력은 `stock=9`, `saved=5`여야 한다. 객체를 더 만든 것이 아니라 기존 두 객체의 값만 다룬 것임을 설명한다.

선택 파일도 각각 빌드하고 성공한 파일만 실행한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic inventory-assignment.c -o inventory-assignment && ./inventory-assignment
gcc -std=c17 -Wall -Wextra -Wpedantic inventory-independent.c -o inventory-independent && ./inventory-independent
```
