## 준비

- C17 호스트 환경에서 Part 2의 선언·초기화·자료형·크기·한계를 통합한다.
- `part2_review.c`는 학습자가 빈 파일부터 직접 작성한다. 이 README는 완성 답안 소스를 제공하지 않는다.
- 입력, 조건문, 반복문, 배열, 포인터, `malloc`은 사용하지 않는다. 값은 선언할 때 초기화하고 출력 문장을 순서대로 나열한다.
- 가능하면 [2-9 실습](../2-9/README.md)의 환경 기록을 준비한다. 다른 컴파일러나 OS를 설치할 필요는 없다.

**[GCC/Linux 구현]** 저장소의 `C/`에서 이동하여 환경 정보를 확인한다.

```sh
cd exercises/02-variables-and-types/2-10
gcc --version
gcc -dumpmachine
uname -a
```

출력 항목 이름에는 ASCII 문구를 사용하고 자료형 선택 이유와 해석은 한국어로 적어도 된다. 한글 출력 자체를 사용한다면 입력·실행 문자 집합과 터미널 인코딩의 영향을 별도로 기록한다.

## 필수 과제

- **목적:** 의미 있는 변수의 값 카드와 대상 구현의 특성 카드를 한 프로그램에서 작성한다.
- **해야 할 일:** 아래 14개 기본 자료형의 변수를 각각 선언·초기화하고 값과 `sizeof`를 출력한다. 별도로 `size_t` 변수에 크기 하나를 저장하여 출력한다. 필수 한계 항목도 모두 출력한다. 각 변수의 용도·단위·자료형 선택 이유, 환경 정보, 빌드·실행 상태, 표준 보장 두 개와 구현 관찰 두 개를 기록한다. `<stdio.h>`, `<stddef.h>`, `<limits.h>`, `<float.h>`의 역할을 구별하고 `int main(void)`와 `return 0;`을 사용한다.
- **사용할 개념:** 이름 규칙, 선언·초기화, 정수형, signed·unsigned, 실수형, 리터럴 접미사, `sizeof`, `size_t`, C byte, `CHAR_BIT`, 두 한계 헤더, 필요한 출력 서식.
- **예상 관찰 결과:** 초기값과 형별 크기·범위·정밀도 정보가 순서대로 표시된다. 세 char 계열은 모두 1 C byte다. 대응 signed·unsigned 형의 크기는 같지만 값 범위는 다르다. 실수 표시에는 서식에 따른 반올림이 있을 수 있다. 구체적 한계는 대상 구현의 결과다.
- **확인 포인트:** 모든 값 변수를 초기화했는가? 변수 이름이 유효하고 의미가 드러나는가? 리터럴과 서식이 형에 맞는가? 크기·bit 수·범위·유효 자릿수를 구별했는가? 초기화하지 않은 값 읽기와 범위 밖 계산 없이 확인했는가?

### 값 카드: 직접 선언할 자료형

| 자료형 | 값 출력 서식 | 선택할 값의 조건 |
|---|---|---|
| `char` | `%c`와 `(int)` 변환 | `'A'` 같은 기본 문자 한 개 |
| `signed char` | `%hhd` | 작은 음수 또는 양수 |
| `unsigned char` | `%hhu` | 작은 음이 아닌 정수 |
| `short` | `%hd` | 최소 보장 범위 안 정수 |
| `unsigned short` | `%hu` | 최소 보장 범위 안 음이 아닌 정수 |
| `int` | `%d` | 최소 보장 범위 안 정수 |
| `unsigned int` | `%u` | 범위 안 정수, `U` 접미사 확인 |
| `long` | `%ld` | 범위 안 정수, `L` 접미사 확인 |
| `unsigned long` | `%lu` | 범위 안 정수, `UL` 접미사 확인 |
| `long long` | `%lld` | 범위 안 정수, `LL` 접미사 확인 |
| `unsigned long long` | `%llu` | 범위 안 정수, `ULL` 접미사 확인 |
| `float` | `%f` 또는 `%e` | 작은 실수, `f` 접미사 확인 |
| `double` | `%f` 또는 `%e` | 작은 실수, 접미사 없는 소수 리터럴 |
| `long double` | `%Lf` 또는 `%Le` | 작은 실수, `L` 접미사 확인 |

크기 출력은 모두 `%zu`다. `size_t`를 특정 기본형이라고 가정하지 않는다. plain `char`는 문자로 출력하므로 문자 코드가 항상 ASCII라는 가정을 하지 않는다. plain `char`의 signedness는 구현 정의이고 범위 확인 매크로는 `CHAR_MIN`·`CHAR_MAX`라는 설명을 보고서에 적는다. 이 두 매크로의 직접 출력은 필수 과제가 아니다.

### 구현 카드: 필수 한계 항목

| 분류 | 항목 | 서식 |
|---|---|---|
| C byte | `(int)CHAR_BIT` | `%d` |
| 작은 정수 | `SCHAR_MIN`, `SCHAR_MAX`, `UCHAR_MAX` | `%hhd`, `%hhd`, `%hhu` |
| short 계열 | `SHRT_MIN`, `SHRT_MAX`, `USHRT_MAX` | `%hd`, `%hd`, `%hu` |
| int 계열 | `INT_MIN`, `INT_MAX`, `UINT_MAX` | `%d`, `%d`, `%u` |
| long 계열 | `LONG_MIN`, `LONG_MAX`, `ULONG_MAX` | `%ld`, `%ld`, `%lu` |
| long long 계열 | `LLONG_MIN`, `LLONG_MAX`, `ULLONG_MAX` | `%lld`, `%lld`, `%llu` |
| 실수 범위 | 세 실수형의 `*_MIN`, `*_MAX` | float·double 계열은 `%e`, long double 계열은 `%Le` |
| 실수 정밀도 | `FLT_DIG`, `DBL_DIG`, `LDBL_DIG` | `%d` |
| 1 근처 간격 | 세 실수형의 `*_EPSILON` | float·double 계열은 `%e`, long double 계열은 `%Le` |
| 공통 기수 | `FLT_RADIX` | `%d` |

별표는 설명용이다. `*_MIN`은 실제 코드에서 `FLT_MIN`, `DBL_MIN`, `LDBL_MIN`으로 나누어 쓴다. 다른 계열도 마찬가지다. 작은 정수는 출력 호출에서 승격되고 `float`는 `double`로 승격되므로 위 대응을 따른다. 이것은 `printf`용 표이며 입력 함수의 서식표가 아니다.

## 작성 순서

1. 변수별 의미·단위와 자료형 선택 이유를 먼저 표에 적는다. 키워드, 숫자로 시작하는 이름, 선행 밑줄 이름을 피한다.
2. 각 변수를 범위 안의 값으로 초기화하고 값 출력과 크기 출력을 구분한다.
3. 한계 매크로를 출력하는 문장을 추가한다. 값을 직접 계산해 경계를 넘기는 실험은 하지 않는다.
4. 빌드한 뒤 각 경고의 원인을 읽고 수정한다. 실패한 빌드 뒤 오래된 실행 파일을 실행하지 않는다.
5. 실제 출력과 완료표를 대조하고 구현 관찰의 조건을 적는다.

## 빌드와 실행

아래 명령은 한 줄씩 실행한다. 상태를 출력하기 전에 다른 명령을 실행하면 `$?`가 바뀐다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic part2_review.c -o part2_review
printf 'build status=%s\n' "$?"
```

빌드 상태가 0일 때만 다음을 실행한다.

```sh
./part2_review
printf 'run status=%s\n' "$?"
```

이 절차는 **[GCC/Linux 구현]** 예다. 다른 환경을 사용했다면 실제 명령을 기록한다. 상태 0만으로 항목 누락이나 잘못된 설명까지 자동 검증되지는 않는다.
