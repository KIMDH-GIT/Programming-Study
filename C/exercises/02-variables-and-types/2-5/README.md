# Step 2-5 실습: `float`, `double`, `long double`

이론: [2-5. `float`, `double`, `long double`](../../../notes/02-variables-and-types/2-5-floating-types.md)

완성 답안 소스는 제공하지 않는다. 아래 요구를 읽고 학습자가 직접 작성한다. 배열, 포인터, 조건문, 반복문, 입력, 동적 메모리는 사용하지 않아도 모든 과제를 해결할 수 있다.

## 준비

- C17 호스트 환경과 **[GCC/Linux 구현]** 셸을 사용한다.
- 저장소의 `C/` 디렉터리를 기준으로 아래 디렉터리로 이동한다.
- 각 소스에 `<stdio.h>`, `int main(void)`, `return 0;`을 작성한다.
- 모든 출력 줄 끝에 `\n`을 넣는다. 셸의 `&&`는 성공한 빌드만 실행한다.

```sh
cd exercises/02-variables-and-types/2-5
gcc --version
```

## 필수 실습 A — 기초: 세 형과 서식 맞추기

- **목적:** 실수형, 상수 접미사, `printf` 인수형을 연결한다.
- **해야 할 일:** `floating_types.c`에 `float`, `double`, `long double` 변수를 하나씩 선언한다. 각각 `12.5f`, `12.5`, `12.5L`로 초기화한다. 형 이름과 값을 한 줄씩 출력하되 소수점 아래 2자리를 표시한다. `float`와 `double`에는 `%.2f`, `long double`에는 `%.2Lf`를 사용한다.
- **사용할 개념:** 선언·초기화, 실수 상수의 형, `f`·접미사 없음·`L`, 가변 인수 승격, 출력 서식.
- **예상 관찰 결과:** 정상 환경에서 아래 세 줄이 출력되고 프로그램은 성공 종료한다. 같은 출력이 세 자료형의 표현 능력이 같음을 증명하지는 않는다.
- **확인 포인트:** 변수형뿐 아니라 오른쪽 상수의 형도 설명할 수 있는가? `float`는 `printf`에 전달될 때 `double`로 승격됨을 기록했는가? 대문자 `L`을 맞췄는가?

```text
float: 12.50
double: 12.50
long double: 12.50
```

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic floating_types.c -o floating_types && ./floating_types
printf 'status=%s\n' "$?"
```

마지막 명령은 직전 빌드·실행 목록의 상태를 기록한다. 빌드가 실패하면 실행은 하지 않으며, 그때 상태는 빌드 실패 상태다. 다른 명령을 사이에 넣지 않는다.

## 추가 실습 B — 응용: 표시 자릿수 비교

- **목적:** 저장 정밀도와 출력 소수 자릿수를 구별한다.
- **해야 할 일:** `decimal_view.c`에 세 형의 변수를 각각 `0.1f`, `0.1`, `0.1L`로 초기화한다. 각 값을 소수점 아래 2자리와 20자리로 출력하여 여섯 줄을 만든다. 각 줄에 형 이름과 표시 자릿수도 적어 구별한다.
- **사용할 개념:** `%.2f`, `%.20f`, `%.2Lf`, `%.20Lf`, 십진 상수와 부동소수점 근사.
- **예상 관찰 결과:** 흔한 IEEE 754 2진 구현에서는 긴 출력에 근사의 흔적이 보일 수 있다. 구체적인 마지막 숫자나 세 형의 출력 차이는 이식 가능한 정답으로 고정하지 않는다.
- **확인 포인트:** 더 많은 자리를 출력해도 변수의 저장 정밀도는 늘지 않음을 설명했는가? `0.1`이 정확하지 않다는 2진 구현의 관찰을 모든 기수의 C 구현에 일반화하지 않았는가?

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic decimal_view.c -o decimal_view && ./decimal_view
printf 'status=%s\n' "$?"
```

## 추가 실습 C — 선택 도전: 두 초기화 경로

- **목적:** 상수의 형과 목적 변수의 형이 서로 다른 개념임을 확인한다.
- **해야 할 일:** `literal_paths.c`에 `long double` 변수 두 개를 선언한다. 첫 변수는 `0.1`, 둘째는 `0.1L`로 초기화한다. 둘 다 `%.20Lf`로 출력하고 결과와 설명을 기록한다. 같거나 다르다는 판단은 출력물을 읽고 하며 조건문은 필요 없다.
- **사용할 개념:** 접미사에 따른 상수형, 초기화 변환, `long double` 출력.
- **예상 관찰 결과:** 대상 구현의 표현 능력과 변환 방식에 따라 출력이 같거나 다를 수 있다. 차이가 없어도 과제 실패가 아니다.
- **확인 포인트:** 첫 번째는 `double` 상수에서 출발함을 적었는가? 더 넓은 형에 저장해도 이미 잃은 정보가 복구되지 않음을 설명했는가? `long double`의 표현 능력이 반드시 더 크다고 주장하지 않았는가?

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic literal_paths.c -o literal_paths && ./literal_paths
printf 'status=%s\n' "$?"
```
