# 2-2. `char`, `short`, `int`

이론: [2-2. `char`, `short`, `int`](../../../notes/02-variables-and-types/2-2-char-short-int.md)

완성 답안 소스는 제공하지 않는다. 아래 요구를 만족하는 `type-record.c`를 직접 작성한다.

## 준비

- Linux 셸과 GCC를 사용한다. 이동 명령은 저장소의 `C/`에서 실행한다.
- 변수 선언·초기화·대입, 프로그램 골격과 `printf`를 사용한다.
- 조건문, 반복문, 배열 선언, 포인터 조작, 동적 메모리 할당은 사용하지 않는다. 출력용 문자열 리터럴은 사용한다.
- 이번 과제는 자료형을 사용해 보는 단계다. `sizeof`와 `<limits.h>`를 이용한 크기·범위 측정은 뒤의 Step에서 진행한다.

```sh
cd exercises/02-variables-and-types/2-2
gcc --version
```

## 필수 과제: 세 자료형으로 상태 출력

- **목적:** `char`, `short`, `int`의 선언과 출력, 값 변경을 연습하고 표준 최소 범위 안에서 값을 선택한다.
- **작성할 파일:** 이 디렉터리의 `type-record.c`.
- **사용할 개념:** 기본 정수형, 문자 상수, 식별자, 초기화, 대입, 최소 표현 범위, `%c`, `%d`, 정수 승격.

### 해야 할 일

1. `<stdio.h>`를 포함하고 `int main(void)`와 정상 종료를 작성한다.
2. 등급을 담는 plain `char` 객체를 `'B'`로 초기화한다. 작은따옴표를 사용한다.
3. 수량을 담는 `short` 객체를 200으로 초기화한다.
4. 누적값을 담는 `int` 객체를 30000으로 초기화한다.
5. 세 객체의 값을 각각 `grade=B`, `count=200`, `total=30000` 형태로 출력한다.
6. 수량 객체에 150을 대입하고 `count=150` 형태로 다시 출력한다. 자료형을 반복하여 재선언하지 않는다.
7. 각 출력 줄 끝에 `\n`을 넣는다. 숫자와 문자 값은 표시 문자열에 고정하지 말고 객체의 값을 전달한다.
8. 자신이 쓴 숫자가 C17의 최소 보장 범위에 들어가는 이유를 기록한다.

### 출력에 필요한 최소 규칙

- `%d`는 `int` 값의 부호 있는 10진수 출력이다. `short`는 이 호출의 인수로 전달될 때 `int`로 승격되므로 `%d`를 사용할 수 있다.
- `%c`는 전달받은 `int`를 문자로 출력한다. 등급 변수 앞에 `(int)`를 붙여 전달한다. 이는 값을 `int`로 변환하는 문법이며, 예제의 기본 문자 `'B'`는 안전하게 변환할 수 있다.
- plain `char`가 모든 구현에서 `int`로 승격한다고 가정하지 않는다. 위 명시적 변환은 여기서 사용하는 문자 값에 맞춘 것이다.
- 인수 값의 변환은 원래 객체의 자료형을 바꾸지 않는다.

```sh

printf 'build status=%s\n' "$?"
```

```sh

```

수정 후에는 다음 명령으로 성공한 빌드와 실행을 연결할 수 있다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic type-record.c -o type-record && ./type-record
```

## 예상 관찰 결과

정상 표준 출력 환경에서 프로그램의 출력은 다음과 같다.

```text
grade=B
count=200
total=30000
count=150
```

Linux 셸의 정상 실행 상태는 0이다. 셸에서 출력한 상태 줄은 프로그램의 네 줄과 구분한다.

수량의 값은 바뀌지만 객체는 계속 `short`다. 이 결과는 `char`가 signed인지, `short`가 몇 byte인지, `int`가 32비트인지 보여 주지 않는다. 문자 B가 출력되었다고 그 문자 코드가 반드시 ASCII의 66이라는 결론도 낼 수 없다.

## 확인 포인트

- 세 객체에 요청한 자료형을 각각 사용했는가?
- `'B'`와 `"B"`를 구별했는가?
- plain `char`의 부호에 의존하는 음수 저장을 하지 않았는가?
- 200, 150, 30000이 각각 자료형의 최소 보장 범위에 들어가는가?
- `%d`와 `%c`에 맞는 인수를 전달하고 경고를 확인했는가?
- `short`의 인수 승격이 원래 객체를 `int`로 바꾸는 것은 아님을 설명했는가?
- 모든 구현에서 `short`와 `int`의 크기가 달라야 한다고 주장하지 않았는가?

## 추가 과제

- ★ **표기 비교:** `type-record.c`의 `short`를 `short int`로 바꾸고 다시 빌드한다. 같은 자료형이므로 출력은 같아야 한다.
- ★★ **signed 값 사용:** `type-signed.c`를 작성해 수량 초기값만 -20, 누적값 초기값만 0으로 바꾼다. 등급과 이후 대입은 유지한다. 출력은 `grade=B`, `count=-20`, `total=0`, `count=150`이어야 한다. plain `char`에는 음수를 넣지 않는다.
- ★★★ **표준과 구현 문서 분리:** 노트의 공식 GCC 참고 자료에서 plain `char`의 부호와 대상 ABI의 관계를 읽는다. 표준이 정한 것과 구현이 선택하는 것을 각각 한 문장으로 기록한다. 현재 대상의 부호를 문서로 확인하지 못했다면 미확인이라고 적는다. 범위 밖 값을 저장하는 실험으로 대신하지 않는다.

선택 소스를 작성했다면 다음 명령을 사용한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic type-signed.c -o type-signed && ./type-signed
```
