## 필수 과제

- **목적:** 손으로 확인한 진법·범위 모델과 C17 프로그램이 보여 주는 정의된 값을 하나의 Part 3 증거 묶음으로 작성한다.
- **작성할 파일:** `part3_review.c`와 아래 기록표. 추가 답안 소스는 필수가 아니다.
- **해야 할 일:** `CHAR_BIT`와 `sizeof(unsigned int)`를 출력한다. 값 42를 나타내는 `unsigned int` 변수 세 개를 각각 `42U`, `052U`, `0x2AU`로 초기화해 같은 줄에 출력한다. `UINT_MAX` 변수, 그 값에 `1U`를 더한 변수, `0U`에서 `1U`를 뺀 변수를 만들고 각각 출력한다. 모든 변수는 선언할 때 초기화한다. 손계산표에서 2진↔10진, 16진↔2진, N-bit unsigned 범위, C17 signed 표현 세 가지를 검산한다. signed 범위를 넘는 식은 소스에 넣거나 실행하지 않는다.
- **사용할 개념:** bit, C byte, `CHAR_BIT`, 자릿값, 진법 변환, 10진·8진·16진 C 리터럴, unsigned 접미사, N개의 값 비트, signed 표현 모델, 같은 패턴의 해석 조건, unsigned 모듈러 산술, signed overflow UB.
- **예상 관찰 결과:** 세 리터럴 변수는 모두 42로 표시된다. `UINT_MAX` 다음 값은 0이고 `0U` 바로 아래 값은 `UINT_MAX`와 같다. `CHAR_BIT`, `sizeof(unsigned int)`, `UINT_MAX`의 구체적인 숫자는 대상 구현에 따라 달라질 수 있다. 이 출력은 리터럴의 값과 산술 관계를 확인하지만 실제 객체의 byte 순서나 특정 signed 표현을 증명하지 않는다.
- **확인 포인트:** C byte와 bit의 단위를 구별했는가? 8진의 앞자리 0과 `U` 접미사를 구별했는가? 출력 서식이 인수형과 맞는가? N을 저장 비트가 아닌 값 비트 수로 적었는가? 2의 보수를 유일한 C17 규칙으로 쓰지 않았는가? 정의된 unsigned 경계만 실행했는가? 제외 범위를 지켰는가?

## 손계산 카드

### A. 2진수와 10진수

각 행에 자릿값의 합 또는 2로 나눈 몫·나머지를 적는다. 계산기 결과만 복사하지 않는다.

| 출발 값 | 자릿값 또는 나눗셈 기록 | 변환 결과 | 역변환 확인 |
|---|---|---|---|
| `101101₂` | | | |
| `110101₂` | | | |
| 42 | | | |
| 61 | | | |

### B. 16진수와 2진수

16진수 한 자리를 2진수 네 자리로 맞춘다. 패턴 폭을 나타내는 앞쪽 0은 표에서 유지한다.

| 16진 또는 2진 표기 | 네 bit씩 묶기 | 변환 결과 | 10진 값 검산 |
|---|---|---|---:|
| `2D₁₆` | | | |
| `7B₁₆` | | | |
| `0011 1101₂` | | | |
| `0010 1010₂` | | | |

### C. C17 정수 리터럴

| 소스 표기 | 기수 | 예상 수학적 값 | 실행 출력 | 접미사가 정한 후보 계열 |
|---|---:|---:|---:|---|
| `42U` | | | | |
| `052U` | | | | |
| `0x2AU` | | | | |

`08`과 `0b101010`을 필수 소스에 넣지 않는다. 각각 왜 이 실습의 올바른 C17 정수 리터럴이 아닌지 기록에 한 문장씩 설명한다.

### D. N-bit unsigned 범위

N은 padding이나 부호 비트를 포함한 저장 비트 수가 아니라 **값 비트 수**다. 거듭제곱은 수학 표기로 계산하며 C 연산자 실습으로 바꾸지 않는다.

| 값 비트 N | 가능한 패턴 수 | 최솟값 | 최댓값 | 최댓값의 N자리 패턴 |
|---:|---:|---:|---:|:---:|
| 3 | | | | |
| 4 | | | | |
| 6 | | | | |
| 8 | | | | |

| 패턴 | unsigned 값 | 부호와 크기 | 1의 보수 | 2의 보수 | C17에서 하나로 확정 가능한가? |

## 프로그램 출력 요구표

완성 소스를 제공하지 않는다. 아래 순서와 자료형·서식을 보고 직접 문장을 작성한다.

| 순서 | 출력할 항목 | 값의 자료형 | 사용할 서식 | 필수 관계 |
|---:|---|---|---|---|
| 1 | `CHAR_BIT` | `(int)`로 맞춘 값 | `%d` | 8 이상 |
| 2 | `sizeof(unsigned int)` | `size_t` | `%zu` | C byte 단위 |
| 3 | 세 리터럴 변수 | `unsigned int` | `%u` 세 개 | 모두 42 |
| 4 | `UINT_MAX` 변수 | `unsigned int` | `%u` | 구현의 최댓값 |
| 5 | 최댓값 다음 변수 | `unsigned int` | `%u` | 0 |
| 6 | 0 바로 아래 변수 | `unsigned int` | `%u` | `UINT_MAX`와 같음 |

소스에는 `<limits.h>`, `<stdio.h>`, `int main(void)`, 초기화한 여섯 `unsigned int` 변수, 필요한 출력, `return 0;`이 있어야 한다. `CHAR_BIT`와 `sizeof` 결과는 별도 변수를 만들지 않고 출력해도 된다. 입력, 조건문, 반복문, 배열, 포인터는 필요하지 않다.

## 작성 순서

1. 손계산 카드 A~E를 먼저 채우고 세 리터럴의 예상값과 두 unsigned 경계 관계를 적는다.
2. 필요한 두 표준 헤더와 `int main(void)`를 작성한다.
3. 세 리터럴 변수와 세 경계 변수를 모두 선언하면서 초기화한다. signed 최대값을 넘기는 비교 코드는 만들지 않는다.
4. 프로그램 출력 요구표 순서대로 `printf` 문장을 작성하고 `%d`, `%zu`, `%u`의 인수형을 확인한다.
5. 빌드가 성공한 뒤에만 현재 실행 파일을 실행한다. 출력 원문과 상태를 기록한다.
6. 손계산·표준 보장·현재 구현 관찰을 서로 다른 표에 적고 완료 기준을 검토한다.

## 빌드와 실행

다음 명령을 한 줄씩 실행한다. 빌드 상태를 확인하기 전에 다른 명령을 실행하면 `$?`의 값이 바뀐다는 점에 주의한다.

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic part3_review.c -o part3_review
printf 'build status=%s\n' "$?"
```

빌드 상태가 0일 때만 실행한다.

```sh
./part3_review
printf 'run status=%s\n' "$?"
```

이 명령은 **[GCC/Linux 구현]** 예다. 다른 구현에서는 실제 명령과 경고 옵션을 기록한다. 경고 없음과 상태 0은 항목·관계·설명이 모두 맞다는 자동 증명이 아니다. 실패한 빌드 뒤에 남아 있던 실행 파일을 이번 결과로 사용하지 않는다.

## 추가 과제

- ★ **기초:** 값 61을 `61U`, `075U`, `0x3DU`로 각각 초기화해 값만 비교한다. 손계산 카드의 2진 결과와 연결하되 새 표기를 C17 2진 리터럴로 쓰지 않는다.
- ★★ **응용:** 값 비트 N이 5와 12인 unsigned 모델의 패턴 수와 범위를 추가 계산한다. N과 `sizeof(형) × CHAR_BIT`를 자동으로 같게 둘 수 없는 이유를 설명한다.
- ★★★ **선택 도전:** `11111111`을 개념적 세 signed 표현에서 다시 검산하고 음의 0 또는 trap 가능성을 조사한다. 객체의 byte를 읽는 코드, endianness 비교, 비트 연산과 shift는 추가하지 않는다.
